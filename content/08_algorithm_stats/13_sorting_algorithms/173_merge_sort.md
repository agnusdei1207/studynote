## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 합병 정렬 (Merge Sort)은 배열을 계속 반으로 나눈 뒤, 정렬된 작은 조각들을 다시 병합해 전체 순서를 만드는 <strong>분할 정복 (Divide and Conquer)</strong> 정렬이다.
> 2. **가치**: 입력 상태와 무관하게 항상 `O(n log n)`을 보장하고 안정 정렬 (Stable Sort) 이라서, 연결 리스트와 외부 정렬에서 특히 강하다.
> 3. **판단 포인트**: 배열에서는 보조 메모리 `O(n)`과 복사 비용이 필요하므로, 안정성과 예측 가능성이 메모리 절약보다 중요할 때 선택하는 것이 맞다.

---

## Ⅰ. 개요 및 필요성

합병 정렬은 큰 문제를 작은 문제로 쪼갠 뒤 다시 합치는 전형적인 분할 정복 알고리즘이다. 핵심은 "어떻게 한 번에 정렬할까"가 아니라, <strong>작게 쪼개면 정렬이 쉬워지고, 정렬된 두 조각은 선형 시간에 합칠 수 있다</strong>는 사실을 이용하는 데 있다.

이 알고리즘이 중요해진 이유는 단순 비교 정렬들이 데이터 크기가 커질수록 급격히 느려지기 때문이다. 버블 정렬이나 선택 정렬은 최악에 `O(n^)`가 걸리므로, 입력 크기가 커지면 처리 시간이 폭증한다. 반면 합병 정렬은 입력이 이미 정렬돼 있든 역순이든 관계없이 작업량이 거의 일정하다.

또한 합병 정렬은 안정 정렬이라는 점에서 실무 가치가 크다. 예를 들어 "점수순 정렬 후 같은 점수에서는 먼저 들어온 순서를 유지"해야 하는 데이터에서, 합병 정렬은 동일 키의 기존 순서를 보존한다. 그래서 단순히 빠른 정렬이 아니라 <strong>예측 가능하고 순서를 보존하는 정렬</strong>로 기억해야 한다.

합병 정렬이 특히 빛나는 곳은 메모리 안 배열만이 아니다. 연결 리스트처럼 순차 접근이 자연스러운 구조, 그리고 디스크에 있는 대용량 파일을 여러 조각으로 나눠 정렬한 뒤 다시 합치는 외부 정렬에서 매우 강력하다.

- **📢 섹션 요약 비유**: 큰 카드 더미를 한 번에 줄 세우기 어렵다면, 먼저 반씩 나눠 작은 더미로 만든 뒤 정리된 더미끼리 합치는 편이 훨씬 쉽다. 합병 정렬은 이 단순한 원리를 끝까지 밀어붙인 방식이다.

## Ⅱ. 아키텍처 및 핵심 원리

합병 정렬은 보통 **분할 (Divide) -> 정복 (Conquer) -> 병합 (Merge)** 의 세 단계로 이해하면 된다. 분할은 배열을 절반씩 쪼개는 단계이고, 정복은 길이 1이 될 때까지 재귀적으로 내려가는 단계이며, 병합은 이미 정렬된 두 배열을 선형 시간에 합치는 단계다.

| 단계 | 핵심 동작 | 시간 관점 | 구현 포인트 |
| :--- | :--- | :--- | :--- |
| 분할 | 배열을 절반으로 나눔 | 깊이 `log n` 형성 | 재귀 또는 반복 구현 |
| 정복 | 더 이상 나눌 수 없는 크기까지 진행 | 길이 1은 이미 정렬 상태 | 재귀 종료 조건 필요 |
| 병합 | 두 정렬 구간을 비교하며 합침 | 각 레벨마다 `O(n)` | 임시 버퍼, 두 포인터 사용 |

아래 그림은 분할과 병합이 어떻게 맞물리는지 보여 준다.

```text
+--------------------------------------------------------------------+
|                 Merge Sort: split first, merge later               |
+--------------------------------------------------------------------+
| [38 27 43 03 09 82 10 14]                                          |
|          +---------------+---------------+                         |
|      [38 27 43 03]   [09 82 10 14]                                |
|        +------+------+   +------+------+                          |
|      [38 27][43 03] [09 82][10 14]                                |
|                                                                    |
| merge upward:                                                      |
| [27 38] [03 43] [09 82] [10 14]                                   |
|      +------+------+   +------+------+                            |
|      [03 27 38 43]      [09 10 14 82]                             |
|               +--------------+--------------+                     |
|           [03 09 10 14 27 38 43 82]                               |
+--------------------------------------------------------------------+
```

병합 단계의 핵심은 두 포인터 비교다. 왼쪽 정렬 구간과 오른쪽 정렬 구간의 맨 앞 원소를 비교해 더 작은 값을 임시 배열에 넣고, 그쪽 포인터만 한 칸 전진한다. 이 작업을 반복하면 두 정렬 구간을 `O(n)`에 합칠 수 있다. 따라서 전체 시간 복잡도는 `T(n) = 2T(n/2) + O(n)` 이 되고, 마스터 정리 (Master Theorem) 에 의해 `O(n log n)`이 된다.

안정성이 유지되는 이유도 병합 단계에 있다. 두 값이 같을 때 오른쪽이 아니라 **왼쪽 구간 원소를 먼저 복사하면**, 원래 입력에서 앞에 있던 원소가 결과에서도 앞에 남는다. 즉 안정성은 공짜 옵션이 아니라 병합 규칙으로부터 나온다.

- **📢 섹션 요약 비유**: 두 줄로 이미 정렬된 학생들을 합칠 때 맨 앞 학생끼리만 비교해 작은 번호부터 세우면 된다. 줄을 나눌 때는 어렵지 않고, 합칠 때 규칙만 정확하면 전체가 자동으로 정렬된다.

## Ⅲ. 비교 및 연결

합병 정렬의 장점을 제대로 보려면 퀵 정렬 (Quick Sort), 힙 정렬 (Heap Sort) 과 비교해야 한다. 세 알고리즘은 모두 `O(n log n)` 영역에 속하지만, 강점의 방향이 다르다.

| 비교 축 | 합병 정렬 | 퀵 정렬 | 힙 정렬 |
| :--- | :--- | :--- | :--- |
| 평균 시간 복잡도 | `O(n log n)` | `O(n log n)` | `O(n log n)` |
| 최악 시간 복잡도 | `O(n log n)` | `O(n^)` | `O(n log n)` |
| 추가 메모리 | `O(n)` | 보통 `O(log n)` | `O(1)` |
| 안정성 | 안정 | 불안정 | 불안정 |
| 잘 맞는 환경 | 외부 정렬, 연결 리스트, 다중 키 정렬 | 일반 배열 정렬, 캐시 효율 | 메모리 제약, 최악 보장 |

퀵 정렬은 평균적으로 매우 빠르고 캐시 친화적이지만, 피벗 선택이 나쁘면 최악 성능이 급격히 나빠질 수 있다. 힙 정렬은 추가 메모리 없이 최악도 보장하지만, 데이터 접근이 분산되어 실제 체감 성능이 떨어질 수 있다. 합병 정렬은 이 둘 사이에서 <strong>안정성과 예측 가능성</strong>을 가장 강하게 제공한다.

또한 합병 정렬은 연결 리스트에서 더 매력적이다. 배열은 중간 분할 후 병합할 때 임시 버퍼가 필요하지만, 연결 리스트는 포인터 재연결만으로 정렬된 두 리스트를 합칠 수 있다. 그래서 같은 `O(n log n)`이라도 자료구조가 달라지면 알고리즘의 실제 매력이 달라진다.

실무적으로는 합병 정렬이 현대 라이브러리의 하이브리드 정렬로도 이어진다. 예를 들어 Timsort 는 합병 정렬의 병합 구조 위에 "이미 부분 정렬된 구간(run)"을 활용하는 아이디어를 얹어 실제 데이터에서 더 좋은 성능을 낸다.

- **📢 섹션 요약 비유**: 퀵 정렬은 재빠른 단거리 선수, 힙 정렬은 힘 좋은 등산가, 합병 정렬은 꾸준하고 질서 있는 마라토너에 가깝다. 어떤 레이스인지에 따라 가장 빛나는 선수가 달라진다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서 합병 정렬을 선택하는 대표 이유는 세 가지다. **안정성**, <strong>예측 가능한 최악 성능</strong>, <strong>순차 접근 친화성</strong>이다. 예를 들어 로그를 시간순으로 정렬하면서 같은 타임스탬프의 기존 입력 순서를 유지해야 한다면, 합병 정렬은 안전한 선택이 된다.

대용량 파일 정렬에서도 합병 정렬은 핵심 기반 기술이다. 메모리에 한 번에 다 올릴 수 없는 데이터를 여러 청크로 나눠 각각 정렬한 뒤, 다방향 병합 (Multi-way Merge) 으로 하나의 정렬 파일로 합친다. 즉 외부 정렬은 사실상 합병 정렬의 확장판이다.

### 실무자 판단 체크리스트

1. 최악 성능이 흔들리면 안 되는가?
2. 동일 키의 기존 순서를 보존해야 하는가?
3. 데이터가 디스크, 스트림, 연결 리스트처럼 순차 접근 중심인가?
4. 배열 정렬이라면 `O(n)` 보조 메모리를 감당할 수 있는가?
5. 이미 부분 정렬된 데이터가 많다면 Timsort 같은 변형이 더 적합한가?

### 자주 나오는 안티패턴

- 메모리가 매우 작은 환경에서 무심코 재귀형 합병 정렬을 쓰는 경우
- 병합용 임시 버퍼를 매 단계마다 비효율적으로 재할당하는 경우
- 안정성이 필요 없는데도 단순히 "최악 보장"만 보고 배열 정렬의 기본값으로 남용하는 경우

현실적인 판단은 이렇다. 배열에서 절대 메모리를 아껴야 하면 합병 정렬이 부담스럽다. 하지만 안정성이 중요하거나 외부 정렬·연결 리스트·병렬 병합처럼 순차적 합치기가 중심인 문제에서는 여전히 매우 강한 선택지다.

- **📢 섹션 요약 비유**: 이삿짐을 한 번에 정리하기 어렵다면 상자별로 먼저 정리한 뒤 큰 방에서 차례로 합치는 편이 안전하다. 다만 상자를 잠시 펼쳐 놓을 여유 공간은 필요하다.

## Ⅴ. 기대효과 및 결론

합병 정렬은 데이터 상태와 무관하게 일정한 성능을 내므로, 성능 예측이 쉬운 정렬이라는 장점을 가진다. 또한 안정 정렬이어서 다중 기준 정렬, 로그 정렬, 레코드 정렬처럼 순서 보존이 중요한 문제에 잘 맞는다.

더 중요한 점은 합병 정렬이 단독 알고리즘을 넘어 <strong>외부 정렬, 병렬 정렬, Timsort 같은 하이브리드 정렬의 기반</strong>이라는 사실이다. 즉 이 알고리즘은 교과서 예제가 아니라, 대규모 데이터 처리의 뼈대를 이루는 기본 메커니즘이다.

물론 배열에서는 `O(n)` 추가 공간이 늘 부담이다. 그래서 합병 정렬은 "무조건 가장 좋은 정렬"이 아니라, <strong>안정성과 예측 가능성을 위해 메모리를 기꺼이 쓰는 정렬</strong>로 기억하는 것이 정확하다.

- **📢 섹션 요약 비유**: 합병 정렬은 넓은 작업대 위에서 물건을 종류별로 나눠 놓고 차근차근 합치는 방식이다. 작업대 공간은 필요하지만, 정리가 정확하고 실수가 적다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| 분할 정복 (Divide and Conquer) | Merge Sort 의 가장 핵심적인 설계 원리 |
| 안정 정렬 (Stable Sort) | 동일 키의 상대적 순서를 보존하는 성질 |
| 외부 정렬 (External Sort) | 디스크 기반 대용량 정렬에서 Merge Sort 를 확장해 사용 |
| 연결 리스트 정렬 | 순차 접근 구조에서 Merge Sort 가 특히 강함 |
| 다방향 병합 (Multi-way Merge) | 여러 정렬 런(run)을 한 번에 합치는 확장 기법 |
| Timsort | Merge Sort 의 병합 구조를 활용한 실용 하이브리드 정렬 |

### 📈 관련 키워드 및 발전 흐름도

```text
Quadratic comparison sorts
         |
         v
Divide and Conquer idea
         |
         v
Merge Sort with stable O(n log n)
         |
         v
External multi-way merge for large files
         |
         v
Timsort and parallel merge based optimizations
```

이 흐름은 "단순 비교 정렬의 한계 -> 분할 정복 -> 안정적 병합 정렬 -> 대용량·하이브리드 정렬로의 확장"을 보여 준다.

### 👶 어린이를 위한 3줄 비유 설명

1. 카드가 너무 많으면 반으로 나눠서 작은 더미부터 먼저 줄을 세워요.
2. 정리된 두 더미는 맨 앞 카드끼리만 비교하면서 하나로 합쳐요.
3. 이렇게 계속 합치면 큰 카드 더미도 예쁘게 순서대로 정리돼요.
