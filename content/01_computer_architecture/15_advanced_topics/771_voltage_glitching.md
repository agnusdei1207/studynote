## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 볼티지 글리칭 (Voltage Glitching)은 칩의 VDD (공급 전압)를 ns~μs 단위로 순간적으로 떨어뜨려, 정상 동작하던 논리 경로의 타이밍 여유를 깨고 instruction skip이나 연산 오류를 유도하는 <strong>능동형 fault injection</strong>이다.
> 2. **가치**: 보안 부트, 비밀번호 비교, 암호 연산처럼 "딱 한 번만 틀리면" 큰 피해가 나는 구간을 직접 흔들 수 있어, 소프트웨어 보호를 물리 계층에서 우회하는 데 강력하다.
> 3. **판단 포인트**: 성공 여부는 offset, width, depth 같은 glitch 파라미터에 달려 있으므로, 방어도 BOD (Brown-Out Detector), on-die regulator, redundancy, tamper response를 함께 설계해야 한다.

---

## Ⅰ. 개요 및 필요성

볼티지 글리칭은 대상 칩의 전원선에 아주 짧은 전압 강하를 만들어, 회로가 "계산은 끝났다고 믿고 다음 단계로 넘어가지만 실제 값은 아직 안정되지 않은" 상태를 강제로 만드는 공격이다. 디지털 회로는 0과 1로 동작해 견고해 보이지만, 실제로는 충분한 전압과 시간 여유가 있을 때만 그 0과 1이 안정적으로 구분된다.

이 공격이 중요한 이유는 하드웨어가 신뢰의 바닥층이기 때문이다. 소프트웨어는 아무리 서명 검증을 잘 짜도, 그 비교 연산을 수행하는 CPU나 MCU (Microcontroller Unit)가 순간적으로 틀린 분기 결정을 내리면 보호가 무의미해진다. 그래서 secure boot, 스마트카드, 자동차 ECU (Electronic Control Unit), 보안 토큰처럼 물리 접근이 가능한 장치는 voltage glitching을 항상 위협 모델에 넣어야 한다.

또한 볼티지 글리칭은 단순 서비스 거부보다 더 위험한 경우가 많다. 공격자는 "기기를 꺼뜨리는 것"이 아니라 "보안 검사 한 줄만 틀리게 만드는 것"을 원하기 때문이다. 전압 강하가 너무 크면 리셋되어 실패하지만, 적절한 강도라면 인증 비교문이나 키 연산의 특정 단계만 조용히 흔들 수 있다.

- **📢 섹션 요약 비유**: 달리기 선수를 넘어뜨리는 것이 아니라, 결승선 바로 앞에서 바닥을 살짝 미끄럽게 만들어 발을 헛디디게 하는 공격이라고 생각하면 된다.

## Ⅱ. 아키텍처 및 핵심 원리

전압이 낮아지면 CMOS (Complementary Metal-Oxide-Semiconductor) 게이트의 스위칭 속도가 느려진다. 같은 클럭 주기 안에 계산을 끝내야 하는 경로가 있는데, 그 경로의 지연이 순간적으로 길어지면 플립플롭은 아직 덜 완성된 값을 잡아 버린다. 이때 나타나는 대표 결과가 instruction skip, 상태 머신 꼬임, 암호 중간값 fault다.

| 파라미터 | 의미 | 너무 약할 때 | 너무 강할 때 |
| :--- | :--- | :--- | :--- |
| offset | 목표 연산 기준 글리치 시작 시점 | 영향이 없는 위치에 빗맞음 | 다른 단계까지 흔들어 재현성 하락 |
| width | 전압 강하 지속 시간 | 타이밍 위반이 부족 | reset, brown-out, 시스템 다운 |
| depth | 얼마나 낮출지 | fault가 안 남음 | 전체 동작 정지 |
| trigger | 글리치 발사 조건 | 타이밍 동기화 실패 | 반복성 없는 실험이 됨 |

아래 그림은 voltage glitch가 "전원 부족 -> 게이트 지연 증가 -> 잘못된 래치"로 이어지는 과정을 요약한다.

```text
+--------------------------------------------------------------------+
| Voltage glitch timing                                              |
+--------------------------------------------------------------------+
| VDD : ------------------+    +----------------------------------   |
|                         +----+                                     |
| CLK : --+  +--+  +--+  +--+  +--+                                  |
|         +--+  +--+  +--+  +--+  +--                               |
|                 ^                                                  |
|         target instruction active during VDD dip                   |
|                 |                                                  |
|                 +- longer gate delay -> setup violation -> fault   |
+--------------------------------------------------------------------+
```

실전에서는 MOSFET (Metal-Oxide-Semiconductor Field-Effect Transistor) 기반 glitcher, FPGA (Field-Programmable Gate Array) 트리거, 로직 애널라이저를 함께 써서 수천~수만 번 파라미터를 스윕한다. 목표는 "장비가 멈추지 않으면서도 보안 로직만 어긋나는 창"을 찾는 것이다. 예를 들어 secure boot 서명 비교 시점에 맞춘 short dip은 검증 분기를 건너뛰게 할 수 있고, 암호 연산 라운드 중 fault는 DFA (Differential Fault Analysis)로 이어질 수 있다.

- **📢 섹션 요약 비유**: 수도관을 끊어 버리는 것이 아니라, 요리사가 소금을 넣는 순간에만 수압을 살짝 떨어뜨려 레시피 한 줄을 틀리게 만드는 방식이다.

## Ⅲ. 비교 및 연결

Voltage glitching은 다른 fault injection과 같은 계열이지만 접근성과 정밀도가 다르다. 전압선을 직접 건드리므로 구현은 비교적 단순하지만, 영향 범위가 칩 전체 전원 도메인으로 넓게 퍼질 수 있다. 반대로 clock glitching은 시간 정밀도가 더 높고, EMFI (Electromagnetic Fault Injection)는 공간 정밀도가 더 높다.

| 기법 | 주입 경로 | 강점 | 약점 | 대표 표적 |
| :--- | :--- | :--- | :--- | :--- |
| 볼티지 글리칭 | 전원선(VDD) | 구현 비교적 단순, 칩 전체 영향 가능 | blast radius가 넓어 재현성 조정 필요 | secure boot, 인증 비교, 암호 연산 |
| 클럭 글리칭 | 외부 클럭선 | 사이클 단위 정밀도 우수 | 내부 클럭 사용 시 어려움 | instruction skip, 루프 조작 |
| EMFI (Electromagnetic Fault Injection) | 비접촉 전자기 펄스 | 공간적으로 특정 블록 조준 가능 | 장비 고가, 실험 복잡 | 보안 칩, 국소 fault 유도 |
| 플런더버그 | 소프트웨어 전압 제어 | 물리 프로브 없이 fault 유도 | 영향 받는 아키텍처·권한 필요 | SGX 등 기밀 연산 |

이 비교에서 중요한 연결점은 "모두 같은 물리 현상을 다른 손잡이로 건드린다"는 점이다. 플런더버그는 전압 글리칭을 소프트웨어화한 형태로 볼 수 있고, EMFI는 전원 핀을 건드리지 않고도 내부 전위 분포를 교란하는 더 정교한 형태라고 볼 수 있다. 반면 클럭 글리칭은 전압이 아니라 시간 기준을 흔든다는 점에서 구분된다.

보안 응용 측면에서는 secure boot와 DFA가 자주 함께 등장한다. 부트 단계에서는 서명 확인 한 번만 빗나가도 임의 펌웨어 실행으로 이어지고, 암호 연산 단계에서는 잘못된 한 라운드가 비밀 키의 수학적 단서가 된다. 그래서 voltage glitching은 "명령을 건너뛰는 공격"과 "키를 역산하는 공격" 둘 다와 연결된다.

- **📢 섹션 요약 비유**: 전압 글리칭이 밥을 순간적으로 굶겨 실수하게 만드는 방식이라면, 클럭 글리칭은 박자를 헷갈리게 하고, EMFI는 몸의 특정 근육만 찌르는 방식에 가깝다.

## Ⅳ. 실무 적용 및 실무자 판단

실무 방어는 "전압이 흔들려도 버티게 만들기"와 "흔들리는 순간 바로 감지하고 멈추기"의 두 축으로 간다. 하드웨어 쪽에서는 BOD나 LVD (Low Voltage Detection)로 brown-out을 감지하고, on-die LDO (Low Dropout Regulator)와 충분한 decoupling capacitor로 외부 dip이 코어까지 전달되지 않게 막는다. 보안 칩에서는 voltage glitch detector가 급격한 dV/dt를 감지하면 즉시 reset이나 key zeroization을 수행하기도 한다.

### 실무 체크리스트

1. 전압 강하 감지 회로(BOD/LVD)가 보안 루틴보다 늦지 않게 반응하도록 설정되어 있는가?
2. 중요한 비교문과 인증 결과가 단일 분기 한 번에만 의존하지 않도록 중복 검증을 넣었는가?
3. PCB와 패키지 수준에서 전원선 접근, 프로빙, decoupling 우회를 어렵게 만들었는가?
4. secure boot, key ladder, firmware update 루틴에 실제 glitch campaign을 수행해 봤는가?

소프트웨어 측면에서도 대응이 필요하다. 결과를 두 번 계산해 비교하거나, `0x00/0x01` 대신 Hamming distance가 큰 encoded state를 쓰고, 중요한 분기를 단일 조건문 하나로 끝내지 않도록 설계하면 single-fault 공격 난도가 올라간다. 다만 random delay만 넣고 끝내는 것은 안티패턴이다. 숙련된 공격자는 결국 트리거를 다시 맞추므로, 지연은 보조책일 뿐 감지·중복·하드웨어 보호를 대체하지 못한다.

- **📢 섹션 요약 비유**: 흔들림에 강한 건물을 짓는 데는 두꺼운 기둥만으로 부족하다. 흔들림 센서, 비상 정지 장치, 같은 계산을 다시 확인하는 감리 절차까지 함께 있어야 한다.

## Ⅴ. 기대효과 및 결론

Voltage glitching을 위협 모델에 넣고 대응하면, 물리 접근이 가능한 장치의 보안 설계가 훨씬 현실적이 된다. secure boot 우회, 키 추출, 디버그 모드 강제 진입 같은 대표 시나리오를 사전에 검증할 수 있어, 출시 후 "논리적으로는 맞았는데 현장에서는 뚫렸다"는 실패를 줄일 수 있다. 특히 보안 토큰, 자동차 제어기, 산업 제어 장비처럼 한 번 탈취되면 실험실 공격을 받을 가능성이 높은 제품군에서 효과가 크다.

한계도 있다. decoupling을 늘리면 면적과 비용이 들고, 과도한 감지 회로는 정상 전원 변동에도 오탐을 낼 수 있다. 또 voltage glitching을 막아도 EMFI나 레이저 fault injection 같은 더 정교한 물리 공격은 남는다. 따라서 최종 목표는 단일 방패가 아니라, fault injection 전반을 줄이고 감지하고 복구하는 다층 구조다.

결론적으로 볼티지 글리칭은 "소프트웨어 보안도 결국 전압이 지탱한다"는 사실을 가장 노골적으로 보여 주는 주제다. 이 문서는 단순 전원 교란 기법으로 외우기보다, timing margin과 신뢰 경계가 만나는 지점으로 기억해야 실제 시험과 실무 판단에 강하다.

- **📢 섹션 요약 비유**: 성문을 부수는 대신 성문 아래 지반을 순간적으로 꺼지게 만들어 저절로 문이 비틀리게 하는 공격이므로, 문짝뿐 아니라 기초 공사와 진동 센서까지 함께 챙겨야 한다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| Fault Injection | 볼티지 글리칭이 속하는 상위 공격 분류다. |
| BOD (Brown-Out Detector) | 전압 강하를 감지해 reset이나 보호 동작을 유발하는 방어 회로다. |
| LDO (Low Dropout Regulator) | 외부 전원 변동이 코어 전압에 그대로 전달되지 않도록 완충한다. |
| DFA (Differential Fault Analysis) | glitch로 만든 잘못된 암호 결과에서 키를 복원한다. |
| Secure Boot | voltage glitching의 대표적인 우회 목표다. |
| EMFI (Electromagnetic Fault Injection) | 전압선 대신 전자기 펄스로 유사 fault를 만드는 관련 기법이다. |

### 📈 관련 키워드 및 발전 흐름도

```text
외부 전원 접근 + trigger 수집
              |
              v
볼티지 글리칭 파라미터 탐색
: offset / width / depth
              |
              v
fault 발생
: instruction skip / faulty crypto / state desync
              |
              +---> secure boot bypass
              +---> DFA 기반 키 복원
              |
              v
BOD + regulator + redundancy + tamper response
```

이 흐름은 "전원 교란"이 어떻게 "보안 우회"로 이어지고, 다시 "감지·완충·중복 검증"으로 대응되는지 보여 준다.

### 👶 어린이를 위한 3줄 비유 설명

1. 컴퓨터는 밥처럼 전기를 먹고 일을 하는데, 나쁜 사람이 그 밥을 아주 잠깐만 줄여 버려요.
2. 그러면 컴퓨터가 문제를 다 풀기 전에 서둘러 답을 적어서 한 줄을 틀리거나 건너뛸 수 있어요.
3. 그래서 중요한 컴퓨터는 밥이 조금만 줄어도 바로 알아채고, 다시 확인하거나 멈추는 장치를 꼭 달아 둬야 해요.
