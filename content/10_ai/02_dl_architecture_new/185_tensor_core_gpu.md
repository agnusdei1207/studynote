## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 텐서 코어 (Tensor Core)는 NVIDIA의 GPU (Graphics Processing Unit) SM (Streaming Multiprocessor) 안에 들어 있는 행렬 곱-누산 전용 하드웨어로, 딥러닝의 핵심 연산인 MMA (Matrix Multiply-Accumulate)를 워프 (Warp) 단위로 매우 높은 처리량으로 수행한다.
> 2. **가치**: 일반 CUDA (Compute Unified Device Architecture) 코어보다 훨씬 높은 연산 밀도와 전력 효율을 제공해, 학습과 추론에서 거대한 GEMM (General Matrix Multiply)·합성곱·어텐션 연산을 현실적인 시간 안에 돌리게 해 준다.
> 3. **판단 포인트**: 텐서 코어는 적절한 저정밀 데이터 형식과 라이브러리 경로, 행렬 크기 정렬이 맞아야 제대로 활성화되므로, 하드웨어만 좋은 것보다 소프트웨어가 그 경로를 타게 설계했는지가 성능을 좌우한다.

## Ⅰ. 개요 및 필요성

딥러닝 계산의 대부분은 결국 큰 행렬을 곱하고 더하는 일로 환원된다. 완전연결층, 합성곱, 어텐션, 임베딩 투영은 형태만 다를 뿐 대부분 대규모 선형대수 연산이며, 이 연산은 데이터 재사용과 병렬 처리에 유리하다. 그래서 GPU는 CPU (Central Processing Unit)보다 훨씬 많은 스레드를 동시에 굴리며 딥러닝 가속기의 중심이 되었다.

하지만 초기 GPU 가속은 어디까지나 "범용 병렬 코어를 많이 동원하는 방식"이었다. CUDA 코어는 다양한 부동소수점 연산을 처리할 수 있지만, 딥러닝이 반복적으로 수행하는 행렬 타일 연산만 놓고 보면 회로를 더 공격적으로 특화할 여지가 있었다. 모델 크기가 수억 개 파라미터를 넘어 수백억 개 이상으로 커지자, 범용성보다 행렬 처리량과 전력 효율이 더 절박한 문제가 되었다.

이 지점에서 등장한 것이 텐서 코어다. 텐서 코어는 GPU를 "픽셀용 병렬 프로세서"에서 "행렬용 병렬 프로세서"로 한 단계 더 밀어 올린 장치다. 즉 딥러닝 시대의 GPU는 CUDA 코어만 많은 장치가 아니라, 텐서 코어를 얼마나 잘 활용하는지가 실제 AI 처리량을 결정하는 구조로 진화했다.

- **📢 섹션 요약 비유**: CUDA 코어가 다재다능한 작업자라면, 텐서 코어는 같은 벽돌 쌓기 일을 위해 특별히 만든 자동 벽돌 적층기와 같다.

## Ⅱ. 아키텍처 및 핵심 원리

텐서 코어는 GPU 바깥에 따로 붙은 장치가 아니라, SM 내부에서 워프 스케줄러와 함께 동작하는 연산 경로다. 워프는 보통 32개 스레드가 한 묶음으로 움직이며, MMA 명령을 통해 행렬 조각(Fragment)을 텐서 코어에 공급한다. 입력 타일은 글로벌 메모리에서 L2 캐시(Level 2 Cache)와 공유 메모리(Shared Memory)를 거쳐 레지스터로 올라오고, 텐서 코어는 이를 곱한 뒤 더 높은 정밀도의 누산기로 모아 결과 타일을 만든다.

```text
+----------------------------------------------------------------------+
| Tensor Core path inside one SM                                      |
+----------------------------------------------------------------------+
| Global Memory -> L2 Cache -> Shared Memory                          |
|                                   |                                 |
|                                   v                                 |
|                           Warp fragment load                        |
|                                   | mma.sync                        |
|                                   v                                 |
|                    Tensor Core MMA : A × B + C                      |
|                                   |                                 |
|                                   v                                 |
|                 FP32 / higher-precision accumulate                  |
|                                   |                                 |
|                                   v                                 |
|                      Registers -> output tile store                 |
+----------------------------------------------------------------------+
```

이 경로가 중요한 이유는 텐서 코어가 단순히 "빠른 곱셈기"가 아니라, 메모리 계층과 워프 실행 모델을 전제로 최적화된 행렬 엔진이기 때문이다. 따라서 연산량이 충분히 크고 데이터가 타일 형태로 잘 공급될 때 진가를 발휘한다. 반대로 메모리 접근이 불규칙하거나, 행렬 크기가 너무 작거나, 조건 분기가 많은 코드는 텐서 코어의 장점을 거의 살리지 못한다.

| 구성 요소 | 역할 | 실무적으로 중요한 이유 |
| :--- | :--- | :--- |
| SM (Streaming Multiprocessor) | CUDA 코어, 텐서 코어, 스케줄러, 메모리를 묶는 실행 단위 | 텐서 코어 성능은 SM 내부 자원 배치와 점유율에 좌우된다 |
| Warp | 32개 스레드의 협업 실행 단위 | MMA 명령은 보통 워프가 협력해 한 타일을 계산한다 |
| Tensor Core | 행렬 곱-누산 전용 연산 유닛 | 같은 전력에서 훨씬 높은 FLOPS (Floating Point Operations Per Second)를 낸다 |
| Shared Memory / Registers | 타일 데이터를 재사용하게 해 주는 근거리 저장소 | 글로벌 메모리 병목을 줄여 연산 유닛을 굶기지 않는다 |
| Mixed Precision Accumulator | 낮은 정밀도 입력과 상대적으로 높은 정밀도 누산을 결합 | 속도와 정확도 사이의 균형을 맞춘다 |

또 하나의 핵심은 혼합 정밀도 (Mixed Precision)다. 텐서 코어는 세대에 따라 FP16 (16-bit Floating Point), BF16 (Bfloat16), TF32 (Tensor Float 32), INT8 (8-bit Integer), FP8 (8-bit Floating Point) 같은 형식을 지원하며, 종종 누산은 FP32 (32-bit Floating Point)처럼 더 높은 정밀도로 수행한다. 이 구조 덕분에 학습 속도를 크게 올리면서도 정확도 손실을 통제할 수 있다. 다만 입력 형식과 커널 선택이 맞지 않으면 프레임워크가 일반 CUDA 코어 경로로 돌아가 버릴 수 있다.

- **📢 섹션 요약 비유**: 텐서 코어는 작은 블록을 규격에 맞게 넣어 주면 순식간에 벽면 한 칸을 통째로 쌓아 올리는 프레스 설비와 같다.

## Ⅲ. 비교 및 연결

텐서 코어를 이해하려면 CUDA 코어와의 경계를 분명히 봐야 한다. CUDA 코어는 범용 SIMT (Single Instruction, Multiple Threads) 연산에 강하고, 텐서 코어는 밀집 행렬 연산에 특화된다. 그래서 텐서 코어가 있다고 해서 GPU의 모든 코드가 빨라지는 것은 아니다. 실제 딥러닝 모델도 텐서 코어가 잘 먹히는 GEMM·합성곱 구간과, 메모리 이동·인덱싱·정규화처럼 상대적으로 일반 코어 의존도가 큰 구간이 섞여 있다.

| 비교 축 | CUDA 코어 | 텐서 코어 | 왜 차이가 중요한가 |
| :--- | :--- | :--- | :--- |
| 주 연산 단위 | 스칼라/벡터 중심 범용 연산 | 행렬 조각 단위 MMA | 딥러닝 핵심 구간에서 처리량 차이가 크게 난다 |
| 지원 범위 | 조건 분기, 주소 계산, 일반 커널 | GEMM, 합성곱, 어텐션 등 밀집 연산 | 모델 내부에서도 가속 구간과 비가속 구간이 갈린다 |
| 정밀도 전략 | FP32, INT 등 범용 처리 | FP16, BF16, TF32, FP8 등 혼합 정밀도 친화적 | 속도와 정확도의 균형점이 달라진다 |
| 성능 한계 | 범용성은 높지만 연산 밀도는 낮음 | 높은 FLOPS, 그러나 메모리 병목에 민감 | 코어 수보다 데이터 공급 설계가 중요해진다 |

세대별 연결도 중요하다. Volta는 FP16 중심의 1세대 텐서 코어를 대중화했고, Ampere는 TF32와 BF16 지원으로 기존 FP32 코드의 진입 장벽을 낮췄으며, Hopper는 FP8과 Transformer 엔진을 통해 초거대 모델 학습·추론 최적화에 더 특화되었다. 즉 텐서 코어의 진화는 단순한 속도 증가가 아니라, <strong>개발자가 텐서 코어 경로에 쉽게 올라탈 수 있도록 소프트웨어와 정밀도 체계를 함께 바꾼 역사</strong>다.

이 때문에 프레임워크 계층도 함께 봐야 한다. PyTorch, TensorFlow, cuBLAS, cuDNN, CUTLASS는 모두 "연산을 텐서 코어 친화적인 타일과 커널로 바꾸는 번역기" 역할을 한다. 하드웨어와 소프트웨어가 따로가 아니라, 라이브러리 스택이 텐서 코어를 실질적으로 열어 준다는 점이 중요하다.

- **📢 섹션 요약 비유**: CUDA 코어가 만능 공구라면, 텐서 코어는 규격이 맞는 자재를 받았을 때 압도적 속도로 일하는 전용 금형 기계와 같다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서 가장 흔한 오해는 "비싼 GPU를 샀으니 자동으로 텐서 코어가 잘 돌 것"이라는 생각이다. 실제 성능은 모델 구조, 프레임워크 설정, 커널 선택, 데이터 형식, 배치 크기, 통신 오버헤드가 함께 결정한다. 예를 들어 LLM (Large Language Model) 학습에서 텐서 코어 자체는 매우 빠르더라도, 시퀀스 길이와 배치 크기가 작거나 NCCL (NVIDIA Collective Communications Library) 통신이 병목이면 기대만큼 스케일되지 않는다.

따라서 실무적 판단은 "텐서 코어를 쓸 수 있는가"가 아니라 "내 워크로드가 텐서 코어를 계속 배불리 먹일 수 있는가"에 가깝다. 연산이 충분히 크고, 형식이 맞고, 라이브러리 최적화 경로를 타며, 메모리와 통신이 받쳐 줄 때 비로소 성능이 나온다.

### 실무 체크리스트

1. 프레임워크에서 AMP (Automatic Mixed Precision) 또는 BF16 경로를 활성화했는가?
2. GEMM·합성곱·어텐션의 주요 차원이 8, 16, 32 등 타일 친화적 배수로 정렬되어 있는가?
3. cuBLAS, cuDNN, FlashAttention, CUTLASS 같은 텐서 코어 최적화 커널을 실제로 사용하고 있는가?
4. 병목이 계산인지, 메모리 대역폭인지, 다중 GPU 통신인지 프로파일링으로 확인했는가?
5. 정확도 민감한 구간은 FP32 유지, 나머지는 혼합 정밀도로 분리하는 기준이 있는가?

### 자주 발생하는 안티패턴

- 텐서 코어 지원 GPU를 쓰면서도 모든 연산을 무조건 FP32로 고정하는 경우
- 작은 배치와 불규칙한 텐서 크기 때문에 텐서 코어가 거의 활성화되지 않는 경우
- 분기 많은 전처리 로직까지 GPU에 몰아 넣고 "GPU 활용률이 낮다"고 오해하는 경우
- `GPU Utilization`만 보고 `Tensor Utilization`을 확인하지 않는 경우
- 모델 계산보다 데이터 로딩이나 GPU 간 통신이 더 느린데도 코어 교체만으로 해결하려는 경우

실무적으로는 밀집 Transformer, 대규모 CNN (Convolutional Neural Network), 벡터 검색 재랭킹 같은 워크로드에서 텐서 코어의 효과가 특히 크다. 반면 작은 배치의 지연시간 민감 추론, 불규칙 그래프 연산, FP64 (Double Precision) 중심 과학 계산은 다른 설계 선택이 더 중요할 수 있다.

- **📢 섹션 요약 비유**: 텐서 코어는 대형 인쇄기라서 종이 규격과 잉크 공급이 맞아야 폭발적인 생산성이 나오고, 준비가 엉망이면 오히려 기계가 놀게 된다.

## Ⅴ. 기대효과 및 결론

텐서 코어가 가져온 가장 큰 변화는 AI 모델 규모와 실험 속도의 상한을 바꿨다는 점이다. 같은 전력과 같은 랙 공간에서 더 많은 학습 스텝을 수행할 수 있게 되었고, 추론에서도 더 높은 처리량을 확보할 수 있게 되었다. 이 덕분에 초거대 모델 학습, 실시간 생성형 AI 서비스, 혼합 정밀도 기반 대규모 배포가 현실이 되었다.

하지만 텐서 코어는 만능 해결책이 아니다. 메모리 대역폭, 캐시 적중률, GPU 간 통신, 커널 런치 오버헤드, 소프트웨어 스택 품질이 따라주지 않으면 이론 FLOPS는 현실 성능으로 이어지지 않는다. 즉 텐서 코어 시대의 성능 최적화는 코어 하나의 속도보다, <strong>연산-메모리-통신-정밀도 전략을 함께 설계하는 시스템 문제</strong>가 되었다.

결론적으로 이 주제는 "GPU가 빠르다"로 기억하면 부족하다. <strong>텐서 코어는 GPU 안의 행렬 처리 전용 엔진이며, 현대 AI 성능의 핵심은 이 엔진이 지속적으로 일할 수 있게 소프트웨어와 데이터 배치를 맞추는 데 있다.</strong> 하드웨어 진화와 프레임워크 최적화가 함께 굴러갈 때 비로소 AI 처리량이 폭발한다.

- **📢 섹션 요약 비유**: 텐서 코어는 거대한 제분기와 같아서, 곡물을 맞는 크기로 꾸준히 공급해 줄 때만 공장 전체 생산량을 바꿔 놓는다.
