## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 딥 큐 네트워크 (DQN, Deep Q-Network)는 큐-러닝 (Q-Learning)의 Q-테이블을 심층 신경망으로 대체해, 픽셀·센서처럼 큰 상태 공간에서도 행동 가치를 근사하는 값 기반 강화 학습 모델이다.
> 2. **가치**: 경험 재생 (Experience Replay)과 타겟 네트워크 (Target Network)를 통해 "연속된 경험의 상관관계"와 "계속 움직이는 학습 목표"를 완화하면서, 아타리 (Atari) 게임처럼 고차원 관측에서도 안정적으로 학습할 수 있게 했다.
> 3. **판단 포인트**: DQN은 **관측은 크지만 행동은 이산적 (Discrete)** 인 문제에 강하다. 반대로 연속 제어, 극단적 희소 보상, 매우 큰 행동 공간에서는 더블 DQN (Double DQN), 레인보우 DQN (Rainbow DQN), 액터-크리틱 (Actor-Critic) 계열로 확장 또는 전환해야 한다.

---

## Ⅰ. 개요 및 필요성

딥 큐 네트워크 (DQN)는 상태 `s`에서 행동 `a`를 했을 때의 미래 누적 보상 `Q(s,a)`를 신경망으로 추정하는 강화 학습 기법이다. 전통적인 큐-러닝은 상태와 행동 조합을 표로 저장하므로, 작은 격자 미로나 단순 게임에서는 잘 동작한다. 하지만 화면 픽셀, 카메라 프레임, 복잡한 센서 벡터처럼 상태 차원이 커지면 Q-테이블 자체를 만들 수 없고, 비슷한 상태끼리 일반화도 어렵다.

DQN이 등장한 이유는 바로 이 "표 기반 강화 학습의 확장 한계" 때문이다. 동일한 게임이라도 화면의 작은 변화가 새로운 상태로 취급되면, 에이전트는 사실상 매번 처음 보는 상황을 만난다. 딥마인드 (DeepMind)는 이 문제를 신경망으로 해결해, 상태를 일일이 외우는 대신 "비슷한 화면이면 비슷한 가치가 있겠다"고 추론하게 만들었다.

아래 그림은 왜 Q-테이블 대신 함수 근사가 필요했는지를 보여준다.

```text
+--------------------------------------------------------------+
|        Q-테이블 기반 강화 학습이 부딪히는 확장 한계          |
+--------------------------------------------------------------+
| 작은 미로                                                     |
|   상태 수 적음 ---> 표(Q-Table)에 값 저장 가능                 |
|                                                              |
| 아타리 화면 84×84×4 프레임                                    |
|   상태 수 폭증 ---> 표 저장 불가 ---> 일반화 불가               |
|                                                              |
| 해결: Q(s,a)를 표가 아니라 신경망 Q(s,a; θ)로 근사            |
+--------------------------------------------------------------+
```

즉 DQN은 "강화 학습을 딥러닝 시대의 입력 규모에 맞게 확장한 첫 실용 해법"으로 이해하면 된다. 이 덕분에 강화 학습은 작은 표 문제를 넘어, 이미지 기반 게임·비전 제어·추천 의사결정으로 적용 범위를 넓힐 수 있었다.

- **📢 섹션 요약 비유**: 큐-러닝이 작은 동네의 모든 길을 종이에 적어 두는 방식이라면, DQN은 지도를 외우는 대신 하늘에서 내려다보며 "이 모양이면 이쪽 길이 유리하다"고 판단하는 내비게이션과 같다.

## Ⅱ. 아키텍처 및 핵심 원리

DQN의 기본 구성은 온라인 Q-네트워크 (Online Q-Network), 타겟 네트워크, 리플레이 버퍼 (Replay Buffer), 그리고 입실론-탐욕 정책 (ε-Greedy Policy)으로 나뉜다. 온라인 네트워크는 현재 행동 가치를 계산하고, 타겟 네트워크는 비교적 천천히 갱신되는 학습 기준점을 제공한다. 리플레이 버퍼는 경험 `(s, a, r, s')`를 저장했다가 무작위 미니배치로 꺼내 학습함으로써, 시간적으로 붙어 있는 샘플의 상관관계를 줄인다.

핵심 업데이트는 큐-러닝과 같지만, 값을 테이블이 아닌 신경망이 근사한다는 점이 다르다. 비종료 상태라면 목표값은 대체로 `y = r + γ max_a' Q_target(s', a')`이고, 현재 추정 `Q_online(s, a)`가 이 목표에 가까워지도록 손실을 줄인다. 여기서 타겟 네트워크를 주기적으로만 동기화하는 이유는, 학습하는 손과 채점하는 손을 분리해 발산을 줄이기 위해서다.

아래 그림은 DQN의 학습 루프를 요약한 것이다.

```text
+--------------------------------------------------------------+
|                    DQN 학습 루프                             |
+--------------------------------------------------------------+
| 현재 상태 s                                                   |
|      |                                                       |
|      v                                                       |
| Online Q-Network ---> Q값들 ---> ε-Greedy로 행동 a 선택         |
|      |                                                       |
|      v                                                       |
| 환경(Environment) ---> 보상 r, 다음 상태 s' 반환              |
|      |                                                       |
|      v                                                       |
| Replay Buffer에 (s,a,r,s') 저장                              |
|      |                                                       |
|      v                                                       |
| 미니배치 샘플링 ---> Target Network로 목표값 y 계산           |
|      |                                                       |
|      v                                                       |
| 손실 최소화로 Online 갱신 ---> 주기적으로 Target 동기화        |
+--------------------------------------------------------------+
```

| 구성 요소 | 역할 | 설계 포인트 |
| :--- | :--- | :--- |
| 온라인 Q-네트워크 | 현재 `Q(s,a)` 추정 | 과적합·발산 방지용 학습률 조정 |
| 타겟 네트워크 | 목표값 계산용 기준 | 너무 자주 복사하면 안정성 저하 |
| 경험 재생 | 샘플 상관관계 완화, 데이터 재사용 | 버퍼 크기와 샘플 최신성 균형 |
| ε-탐욕 정책 | 탐험과 활용 균형 | 학습 초반 ε 크게, 후반 점진 감소 |
| 보상 클리핑 | 학습 폭주 완화 | Atari류에서 `[-1, 1]` 클리핑 자주 사용 |

특히 경험 재생과 타겟 네트워크는 DQN 성공의 핵심 안전장치다. 경험 재생이 없으면 연속된 화면이 너무 비슷해 편향된 업데이트가 반복되고, 타겟 네트워크가 없으면 신경망이 스스로 만든 흔들리는 목표를 쫓다가 쉽게 발산한다. DQN은 단순히 "Q-러닝 + 신경망"이 아니라, <strong>학습을 안정화하는 운영 장치까지 포함한 설계</strong>라고 봐야 한다.

- **📢 섹션 요약 비유**: 경험 재생은 시험공부할 때 같은 단원만 연속으로 보지 않고 문제집을 섞어 푸는 것이고, 타겟 네트워크는 채점 기준을 시험 도중 바꾸지 않게 정답지를 잠시 고정해 두는 것과 같다.

## Ⅲ. 비교 및 연결

DQN의 경계는 큐-러닝과 액터-크리틱을 함께 비교할 때 가장 분명하다. 큐-러닝은 해석이 쉽고 안정적이지만 Q-테이블에 갇혀 있고, DQN은 큰 상태 공간을 처리할 수 있지만 여전히 행동 공간이 이산적이어야 한다. 액터-크리틱은 연속 제어까지 확장되지만, 정책 네트워크와 가치 네트워크를 함께 다뤄야 하므로 구현·튜닝 복잡도가 더 높아진다.

| 항목 | 큐-러닝 (Q-Learning) | DQN | 액터-크리틱 (Actor-Critic) |
| :--- | :--- | :--- | :--- |
| 상태 표현 | 표 기반 이산 상태 | 신경망 기반 고차원 상태 | 신경망 기반 고차원 상태 |
| 행동 공간 | 이산 | 이산 | 이산·연속 모두 가능 |
| 장점 | 단순, 해석 용이 | 이미지·센서 입력 일반화 | 연속 제어와 큰 정책 공간 대응 |
| 약점 | 차원의 저주 | 학습 불안정, 과대평가 가능성 | 튜닝 복잡도와 분산 증가 |
| 대표 확장 | SARSA | Double/Dueling/Rainbow DQN | DDPG, A3C, PPO |

DQN 내부에서도 추가 확장이 이어졌다. 더블 DQN은 `max` 연산이 만든 과대평가 편향을 줄이고, 듀얼링 DQN (Dueling DQN)은 상태 가치와 행동 이점을 분리해 학습 효율을 높인다. 우선순위 경험 재생 (Prioritized Experience Replay)은 학습 가치가 큰 샘플을 더 자주 복습하게 해, 같은 DQN 계열 안에서도 성능 차이를 만든다.

따라서 DQN은 강화 학습의 종착점이 아니라, 표 기반 가치 학습을 심층 신경망으로 확장한 <strong>중간 교량</strong>에 가깝다. MDP (Markov Decision Process), 벨만 최적 방정식, 탐험-활용 균형 같은 고전 개념이 DQN 안에서 계속 살아 있으며, 이후 많은 딥 강화 학습 기법이 이 구조를 개조해 발전했다.

- **📢 섹션 요약 비유**: 큐-러닝이 손으로 그린 동네 지도라면, DQN은 위성사진을 보는 내비게이션이고, 액터-크리틱은 자동차 핸들까지 실시간으로 조정하는 자율주행 시스템에 더 가깝다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서 DQN이 잘 맞는 대표 상황은 관측은 복잡하지만 행동은 몇 가지 버튼 수준으로 제한된 문제다. 예를 들어 창고 로봇이 카메라 영상을 보고 `좌회전·직진·우회전·정지` 네 가지 행동만 고르면 된다면, DQN은 충분히 실용적이다. 반대로 조향각, 가속도, 관절 토크처럼 연속값을 직접 출력해야 한다면 DQN보다 DDPG (Deep Deterministic Policy Gradient), SAC (Soft Actor-Critic), PPO (Proximal Policy Optimization)를 먼저 검토하는 편이 맞다.

운영 관점에서는 학습 안정성과 재현성이 중요하다. 보통 리플레이 버퍼를 수십만~수백만 건으로 두고, 타겟 네트워크는 수천~수만 스텝마다 동기화하며, 평가 시에는 `ε`를 매우 낮게 둬 실제 정책 품질을 확인한다. 예를 들어 Atari류 실험에서는 프레임 스택 4장, 리플레이 버퍼 100만, 타겟 갱신 10,000 스텝 같은 구성이 자주 쓰인다.

### 적용 체크리스트

1. 행동 공간이 이산적 (Discrete) 인가?
2. 상태 입력이 크더라도 충분한 시뮬레이터·로그 데이터가 있는가?
3. 리플레이 버퍼 메모리 비용과 학습 시간이 예산 안에 들어오는가?
4. 희소 보상 문제를 중간 보상 설계나 커리큘럼 학습으로 완화할 수 있는가?

### 대표 안티패턴

- 연속 제어 문제에 DQN을 억지로 적용하는 설계
- 경험 재생 없이 최근 경험만으로 학습해 발산을 부르는 설계
- 리워드 해킹 (Reward Hacking)을 막지 못해, 점수는 높지만 목표는 틀린 정책을 만드는 설계

학습 정리에서는 "DQN은 고차원 상태 + 이산 행동에서 강력하지만, 안정화 장치와 문제 적합성 판단이 선행돼야 한다"고 정리하면 균형이 좋다. 즉 성능보다 먼저 <strong>문제 구조가 DQN 친화적인지</strong>를 판단하는 것이 설계자의 역할이다.

- **📢 섹션 요약 비유**: DQN은 버튼 몇 개로 움직이는 게임기에는 강하지만, 핸들을 연속으로 돌려야 하는 실제 자동차에는 맞지 않는다. 리모컨 문제와 운전 문제를 같은 도구로 풀 수는 없다.

## Ⅴ. 기대효과 및 결론

DQN의 가장 큰 공헌은 강화 학습을 작은 표 문제에서 실제 고차원 입력 문제로 끌어올렸다는 점이다. 덕분에 에이전트는 사람이 직접 특징을 설계하지 않아도, 화면과 보상만으로 행동 가치를 학습할 수 있게 되었다. 이는 이후 게임 AI, 추천, 로봇 제어, 시뮬레이션 최적화 연구의 출발점이 되었다.

다만 한계도 분명하다. 학습이 데이터 비효율적일 수 있고, 보상 설계가 나쁘면 엉뚱한 전략을 과하게 학습하며, 행동이 연속적이거나 환경이 매우 비정상적이면 성능이 급격히 떨어진다. 그래서 현대 실무에서는 더블 DQN, 레인보우 DQN, 분포형 강화 학습, 액터-크리틱 등으로 보완하는 경우가 많다.

결론적으로 DQN은 "Q-러닝의 일반화 능력을 딥러닝으로 확장한 첫 실전형 전환점"으로 기억하면 된다. 강화 학습을 공부할 때도, 설계할 때도, DQN은 언제 가치 기반 접근이 유효하고 언제 다른 계열로 넘어가야 하는지 판단하는 중요한 기준점이 된다.

- **📢 섹션 요약 비유**: DQN은 종이 지도만 보던 탐험가에게 드론 카메라를 달아 준 것과 같다. 훨씬 넓게 볼 수 있게 되었지만, 산악 구조처럼 더 복잡한 임무에서는 여전히 더 전문적인 장비가 필요하다.

```text
Rainbow DQN · 심층 강화 학습 (Deep Reinforcement Learning)
```

이 흐름도는 가치 기반 강화 학습이 표 기반에서 함수 근사 기반으로 확장되고, 이후 안정화 기법을 더하며 발전한 경로를 보여준다.

### 👶 어린이를 위한 3줄 비유 설명

1. 옛날 로봇은 길마다 점수표를 다 적어 두어야 했지만, 너무 큰 세상에서는 그 표를 만들 수 없었어요.
2. DQN은 로봇에게 사진을 보고 "이 장면이면 이 버튼이 좋겠네"라고 생각하는 똑똑한 눈과 뇌를 준 거예요.
3. 대신 너무 흥분하지 않게, 지난 경험을 섞어 복습하고 정답지도 천천히 바꾸며 공부하게 만들어요.
