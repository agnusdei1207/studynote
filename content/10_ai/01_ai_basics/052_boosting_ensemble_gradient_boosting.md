## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 부스팅 (Boosting)은 앞 모델의 오차를 다음 모델이 순차적으로 보완하는 앙상블 학습 방식이다.
> 2. **가치**: 약한 학습기 여러 개를 직렬로 연결해 강한 예측기를 만들며, 특히 정형 데이터에서 매우 강하다.
> 3. **판단 포인트**: 학습률, 트리 깊이, 반복 수, 조기 종료 (Early Stopping)를 잘못 잡으면 과적합이 쉽게 발생한다.

---

## Ⅰ. 개요 및 필요성

부스팅은 "틀린 부분만 집요하게 고쳐 나가는" 학습법이다. 배깅이 병렬로 여러 모델을 만들고 평균내는 방식이라면, 부스팅은 한 모델이 틀린 곳을 다음 모델이 이어서 고친다. 그래서 편향을 줄이는 데 강하다.

이 방식이 필요한 이유는 복잡한 패턴을 다루는 정형 데이터에서 단순 모델의 성능 한계가 뚜렷하기 때문이다. 부스팅은 작은 나무를 여러 번 쌓아 올려 예측 성능을 끝까지 끌어올린다.

- **📢 섹션 요약 비유**: 부스팅은 오답 노트를 다음 날 또 풀고, 그다음 날 또 푸는 끝장 복습과 같다.

---

## Ⅱ. 아키텍처 및 핵심 원리

부스팅은 약한 학습기를 직렬로 연결한다. AdaBoost는 오답 샘플에 가중치를 올리고, Gradient Boosting은 잔차 (Residual)를 다음 모델의 타깃으로 삼는다. 이 반복 덕분에 최종 예측이 정답에 수렴한다.

```text
+--------------------------------------------------------------+
|                 부스팅의 순차적 오차 보정                   |
+--------------------------------------------------------------+
| 입력 데이터 -> Tree 1 -> 잔차 계산 -> Tree 2 -> 잔차 계산       |
|                     -> Tree 3 -> ... -> 최종 앙상블           |
+--------------------------------------------------------------+
```

| 항목 | 의미 | 영향 |
| :--- | :--- | :--- |
| 약한 학습기 | 얕은 결정 트리 | 직렬 보완에 적합 |
| 학습률 | 각 모델의 기여 정도 | 낮을수록 안정적 |
| 반복 수 | 몇 번 보정할지 | 많을수록 성능^, 과적합^ |
| 잔차 | 남은 오차 | 다음 모델의 학습 대상 |

| 알고리즘 | 특징 |
| :--- | :--- |
| AdaBoost | 오답 샘플 가중치를 높인다 |
| GBM | 잔차를 다음 모델의 타깃으로 삼는다 |
| XGBoost | 정규화와 시스템 최적화가 강하다 |
| LightGBM | 빠르고 대용량에 강하다 |
| CatBoost | 범주형 처리에 강하다 |

부스팅의 핵심은 "한 번에 다 맞히려 하지 말고, 조금씩 오차를 없애라"다. 이 때문에 훈련 성능은 매우 강하지만, 데이터가 적고 노이즈가 많으면 과적합이 생기기 쉽다.

- **📢 섹션 요약 비유**: 부스팅은 선생님이 틀린 문제만 콕 집어 다시 내 주는 집중 보충 수업과 같다.

---

## Ⅲ. 비교 및 연결

부스팅은 배깅과 자주 비교된다. 배깅은 병렬로 안정성을 높이고, 부스팅은 순차적으로 정확도를 높인다. 스태킹은 여러 모델을 메타 모델로 결합한다는 점에서 또 다르다.

| 항목 | 배깅 (Bagging) | 부스팅 (Boosting) | 스태킹 (Stacking) |
| :--- | :--- | :--- | :--- |
| 방식 | 병렬 | 순차 | 계층적 |
| 주 목표 | 분산 감소 | 편향 감소 | 메타 결합 |
| 장점 | 안정적 | 고정밀 | 유연함 |
| 단점 | 한계 성능 | 과적합 위험 | 구현 복잡 |

부스팅은 특히 XGBoost, LightGBM 같은 트리 기반 모델로 널리 쓰인다. 이유는 정형 데이터에서 트리 분할이 해석과 성능 모두 좋기 때문이다. 다만 이미지/텍스트 같은 비정형 데이터에서는 딥러닝이 더 적합한 경우가 많다.

- **📢 섹션 요약 비유**: 배깅은 여러 사람이 각자 풀고 투표하는 것, 부스팅은 한 사람이 틀린 부분을 다음 사람에게 넘겨가며 고치는 것, 스태킹은 마지막 심사위원이 최종 판단하는 것과 같다.

---

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 학습률, 트리 깊이, 서브샘플링, early stopping이 중요하다. 특히 데이터가 적거나 노이즈가 많으면 깊은 트리를 많이 쌓는 방식은 위험하다. 검증셋 성능이 떨어지기 시작하면 멈춰야 한다.

### 체크리스트

1. 정형 데이터 문제인가?
2. 학습률과 트리 깊이를 낮게 시작했는가?
3. 검증셋과 조기 종료를 사용했는가?
4. 범주형 변수 처리와 결측치 전략이 있는가?

### 안티패턴

- 작은 데이터에 큰 부스팅 모델을 과하게 쌓는 경우
- 학습 데이터만 보고 튜닝하는 경우
- 과적합 신호를 무시하고 반복 수만 늘리는 경우

실무 관점에서는 부스팅을 "정확도 극대화 도구"로만 말하지 말고, 왜 과적합이 생기고 어떻게 제어하는지까지 설명해야 한다. 그래야 실무 적용성이 생긴다.

- **📢 섹션 요약 비유**: 부스팅은 악기 연습에서 틀린 음만 계속 고치는 것과 같다. 잘 고치면 훌륭하지만, 너무 집착하면 오히려 다른 음까지 망칠 수 있다.

---

## Ⅴ. 기대효과 및 결론

부스팅은 정형 데이터에서 높은 예측 성능을 내는 대표적인 앙상블 방법이다. 작은 약점들을 차례로 메워 가는 구조 덕분에, 많은 산업 문제에서 강력한 실전 성능을 보인다.

하지만 순차 학습 특성상 느리고, 과적합에 민감하다. 따라서 부스팅은 "아무 때나 쓰는 만능"이 아니라, 데이터 구조와 튜닝 역량이 맞을 때 가장 빛나는 기술로 기억해야 한다.

- **📢 섹션 요약 비유**: 부스팅은 틀린 곳을 끝까지 고쳐서 만점을 노리는 공부법이다. 잘하면 최고지만, 무리하면 과도한 암기가 된다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| 잔차 (Residual) | 다음 모델이 학습하는 오차 |
| 학습률 (Learning Rate) | 각 트리의 기여 크기 |
| 조기 종료 (Early Stopping) | 과적합 방지 장치 |
| XGBoost | 정규화와 시스템 최적화 강화 |
| LightGBM | 대용량과 빠른 학습에 강함 |

### 📈 관련 키워드 및 발전 흐름도

```text
약한 학습기
    |
    v
AdaBoost
    |
    v
Gradient Boosting
    |
    v
XGBoost / LightGBM / CatBoost
    |
    v
정형 데이터 고정밀 앙상블
```

이 흐름은 오답 보정형 직렬 앙상블이 고성능 산업 표준으로 진화한 과정을 보여준다.

2. 첫 번째가 틀린 곳을 두 번째가 고치고, 두 번째가 틀린 곳을 세 번째가 또 고쳐요.
3. 그래서 마지막에는 아주 정확한 답을 만들 수 있어요.
