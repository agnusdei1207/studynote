## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 의도 기반 네트워킹(IBN)은 운영자가 원하는 비즈니스 의도를 정책으로 선언하면 시스템이 네트워크 설정, 검증, 모니터링, 보정을 자동 수행하는 폐루프 네트워크 운영 모델이다.
> 2. **가치**: 장비별 CLI 수작업을 줄이고, 정책 일관성, 변경 검증, 장애 복구 속도를 높여 대규모 멀티벤더 네트워크의 운영 리스크를 낮춘다.
> 3. **판단 포인트**: 자동화 범위가 넓을수록 검증과 롤백이 중요하다. 의도 모델, 소스 오브 트루스, 텔레메트리 품질이 낮으면 오히려 장애가 자동 확산될 수 있다.

---

## I. 개요 및 필요성

전통 네트워크 운영은 장비별 CLI, 수동 변경 승인, 사후 장애 대응에 의존했다. 데이터센터, 클라우드, SD-WAN, 캠퍼스, 엣지망이 커지면 사람이 모든 ACL, 라우팅, QoS, 세그먼트 정책을 일관되게 관리하기 어렵다.

IBN은 `무엇을 원하는가`와 `어떻게 설정할 것인가`를 분리한다. 예를 들어 운영자는 "결제 시스템은 DB와만 통신하고 외부 인터넷은 차단"이라는 의도를 선언하고, 시스템은 VLAN, VRF, ACL, 보안그룹, 라우팅 정책으로 변환해 배포한다.

```text
[Intent Based Networking Loop]

Intent
  |
  v
Translate -> Validate -> Deploy -> Observe
    ^                              |
    |                              v
    +--------- Assurance <---------+
```

## II. 아키텍처 및 핵심 원리

| 구성 요소 | 역할 | 대표 기술 |
| :--- | :--- | :--- |
| Intent Model | 정책을 추상화된 언어로 표현 | YAML, YANG, policy DSL |
| Source of Truth | 자산, IP, 회선, 토폴로지 기준정보 | NetBox, CMDB, IPAM |
| Controller | 의도를 장비 설정으로 변환 | SDN controller, Ansible, Terraform |
| Validation | 배포 전/후 정책 검증 | Batfish, pyATS, digital twin |
| Telemetry | 상태 수집과 이상 탐지 | streaming telemetry, SNMP, gNMI |
| Assurance | 의도와 실제 상태의 차이 보정 | closed-loop remediation |

핵심은 폐루프다. 단순 자동화는 설정을 밀어 넣는 데서 끝나지만, IBN은 실제 네트워크 상태가 의도와 일치하는지 지속 확인하고 차이가 나면 경고하거나 자동 보정한다.

## III. 비교 및 연결

| 구분 | 스크립트 자동화 | SDN | IBN |
| :--- | :--- | :--- | :--- |
| 목적 | 반복 작업 감소 | 제어/데이터 평면 분리 | 의도-상태 일치 보장 |
| 입력 | 명령 절차 | 중앙 제어 정책 | 비즈니스 의도 |
| 검증 | 제한적 | 컨트롤러 중심 | 사전/사후 검증 포함 |
| 피드백 | 수동 확인 | 일부 제공 | 폐루프 보정 |
| 위험 | 스크립트 오류 | 컨트롤러 의존 | 잘못된 의도 자동 확산 |

NetDevOps와도 연결된다. 네트워크 변경을 코드로 관리하고 Git 리뷰, 테스트, CI/CD, 승인, 롤백을 적용하면 IBN의 신뢰성이 높아진다.

## IV. 실무 적용 및 실무자 판단

### 적용 절차

1. 네트워크 기준정보와 토폴로지 데이터를 정비한다.
2. 반복 변경 업무를 선정해 의도 모델로 추상화한다.
3. 디지털 트윈 또는 검증 도구로 배포 전 영향도를 분석한다.
4. 낮은 위험 영역부터 자동 배포와 사후 검증을 적용한다.
5. 자동 보정은 알림 모드에서 시작해 검증 후 차단/수정 모드로 전환한다.

### 피해야 할 안티패턴

- CMDB/IPAM이 부정확한 상태에서 자동화를 시작하는 경우
- 장비별 예외 설정을 숨긴 채 표준 정책만 밀어 넣는 경우
- 검증 없이 자동 롤백/자동 보정을 켜는 경우
- 네트워크팀의 운영 절차와 승인 체계를 무시하는 경우

## V. 기대효과 및 결론

IBN은 네트워크 자동화의 최종 형태라기보다, 의도 선언과 상태 검증을 결합한 운영 모델이다. 학습 정리에서는 SDN, NetDevOps, 디지털 트윈, 텔레메트리, 폐루프 보정을 연결해 설명하는 것이 적절하다.

### 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| SDN | 중앙 제어 기반 정책 배포 |
| NetDevOps | GitOps와 테스트 기반 변경 관리 |
| Source of Truth | 자동화의 기준 데이터 |
| Streaming Telemetry | 실시간 상태 수집 |
| Digital Twin | 변경 전 영향 검증 |
