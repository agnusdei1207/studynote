## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPU 클라우드 AI 인프라 최적화는 제한된 GPU 자원을 학습, 튜닝, 추론 워크로드에 맞게 배치하여 처리량, 지연시간, 비용, 가용성을 동시에 맞추는 용량 공학이다.
> 2. **가치**: GPU는 CPU보다 단가와 조달 리스크가 크므로, 사용률을 10%p만 올려도 대규모 AI 서비스의 월 비용과 대기 시간을 크게 줄일 수 있다.
> 3. **판단 포인트**: 모델 크기, 배치 크기, 메모리 대역폭, 네트워크 토폴로지, 예약/스팟 조합을 함께 봐야 하며 단순히 최신 GPU를 쓰는 것이 최적해는 아니다.

---

## I. 개요 및 필요성

AI 인프라에서 GPU는 가장 비싸고 병목이 되기 쉬운 자원이다. 학습은 장시간 대규모 병렬 처리와 고속 인터커넥트가 중요하고, 추론은 낮은 지연시간과 안정적인 처리량이 중요하다. RAG, 멀티모달, 에이전트 워크플로가 늘면 동일 모델이라도 프롬프트 길이와 동시 요청 수에 따라 GPU 메모리와 KV cache 사용량이 크게 달라진다.

최적화의 목적은 단순 비용 절감이 아니다. SLA를 지키면서 `GPU utilization`, `tokens/sec`, `time to first token`, `cost per 1M tokens`, `job queue time`을 함께 관리하는 것이다.

## II. 아키텍처 및 핵심 원리

| 영역 | 핵심 판단 | 기술 요소 |
| :--- | :--- | :--- |
| GPU 선택 | 메모리 용량, 대역폭, FP8/INT8 지원, 단가 | H100, A100, L40S, L4, T4 |
| 스케줄링 | 대기열, 우선순위, 선점, gang scheduling | Kubernetes, Kueue, Slurm, Ray |
| 분산 학습 | 통신 병목과 체크포인트 | NCCL, RDMA, EFA, NVLink, FSDP |
| 추론 최적화 | 지연시간과 처리량 균형 | vLLM, TensorRT-LLM, Triton, TGI |
| 비용 제어 | 예약/스팟/온디맨드 조합 | capacity block, savings plan, spot fallback |
| 관측성 | GPU와 모델 지표 통합 | DCGM, Prometheus, OpenTelemetry |

학습에서는 GPU 간 통신이 병목이 되기 쉽다. 모델 병렬, 데이터 병렬, 파이프라인 병렬의 조합을 워크로드에 맞춰 선택해야 한다. 추론에서는 배치 크기를 키우면 처리량은 좋아지지만 지연시간이 늘 수 있고, KV cache가 커지면 GPU 메모리 부족으로 OOM이 발생한다.

## III. 비교 및 연결

| 구분 | 학습 클러스터 | 실시간 추론 | 배치 추론 |
| :--- | :--- | :--- | :--- |
| 목표 | 학습 시간 단축 | p95/p99 지연시간 | 총 처리 비용 |
| 병목 | GPU 통신, 체크포인트 | KV cache, TTFT, 동시성 | 큐 처리량, 저장소 IO |
| 스케일링 | gang scheduling 필요 | HPA/KEDA 기반 | 작업 큐 기반 |
| 장애 처리 | 체크포인트 재시작 | 즉시 우회/롤백 | 재시도 허용 |

FinOps와 MLOps가 결합되어야 한다. 모델 성능이 좋아도 비용이 감당되지 않으면 서비스화가 어렵고, 비용만 낮춰 품질이 떨어지면 사용자 경험이 악화된다.

## IV. 실무 적용 및 실무자 판단

### 적용 절차

1. 워크로드를 학습, 튜닝, 실시간 추론, 배치 추론으로 분류한다.
2. 모델별 메모리, 토큰 길이, 동시성, SLA를 측정한다.
3. GPU 타입별 벤치마크를 동일 데이터와 동일 프롬프트 분포로 수행한다.
4. 예약 용량은 기준 부하에, 스팟은 중단 허용 작업에 배치한다.
5. 사용률, 큐 대기, 실패율, 비용 지표를 대시보드로 운영한다.

### 피해야 할 안티패턴

- 최신 고가 GPU를 모든 워크로드에 동일하게 배정하는 경우
- 평균 지연시간만 보고 p95/p99와 TTFT를 보지 않는 경우
- GPU 사용률만 높이고 사용자 지연시간을 악화시키는 경우
- 체크포인트와 재시작 전략 없이 스팟 GPU를 학습에 쓰는 경우

## V. 기대효과 및 결론

GPU 클라우드 최적화의 성패는 자원 구매가 아니라 워크로드 분류와 운영 지표에 달려 있다. 실무자는 GPU 종류보다 병목 위치, 장애 허용도, 비용 모델, 관측 가능성을 함께 설명할 수 있어야 한다.
