## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 사이버 주권(Cyber Sovereignty)은 자국 영토 내 데이터·네트워크·소프트웨어에 대한 관할권과 통제권을 확보하는 국가 전략이며, 디지털 자주권은 OS(운영체제), CPU(중앙처리장치), DBMS(데이터베이스관리시스템), 암호모듈, 클라우드, 네트워크 장비 등 핵심 ICT(정보통신기술) 스택에서 해외 기술 의존도를 탈피해 독자 개발·검증·운영 체계를 구축하는 기술 독립 정책이다.
> 2. **가치**: KCMVP(한국암호모듈검증체계) 인증 모듈 100% 국산 전환 시 연 1.2조원 외화 유출 방지, RISC-V(오픈 명령어집합구조) 기반 국산 CPU 도입으로 라이선스 비용 95% 절감, 공공부문 데이터 주권 회복률 78%->96%(2028 목표), 공급망 SBOM(소프트웨어구성원목록) 100% 가시화 시 취약점 탐지 MTTR(평균복구시간) 240시간->18시간 단축 효과.
> 3. **판단 포인트**: 기술 독립과 국제 호환성 간 트레이드오프(예: 국산 OS vs Windows API 호환성), 풀스택 교체 비용(전환율 1%당 약 3,800억원 소요) vs 단계적 다층화 전략(Strategic Modularity), 오픈소스(OSS, Open Source Software) 활용 시 라이선스 컴플라이언스(GPL/AGPL/LGPL) 및 포크(fork) 거버넌스 위험, 국가 주권형 클라우드와 하이퍼스케일러 간 데이터 트래픽 라우팅 정책 결정.

## Ⅰ. 개요 및 필요성

미국의 `Executive Order 14028`(2021, 사이버보안 행정명령)과 EU의 `Data Act`(2024), `Cyber Resilience Act`(2024) 등으로 글로벌 사이버 주권 경쟁이 본격화되었다. 한국은 2014년 `KCMVP` 도입, 2021년 `데이터 산업법`(데이터 산업진흥 및 이용촉진에 관한 기본법), 2022년 `클라우드컴퓨팅법`(클라우드컴퓨팅 발전 및 이용자 보호에 관한 법률) 개정, 2023년 국가안보실 `사이버안보전략` 개정, 2024년 과학기술정보통신부 `디지털 자주권 확보 전략` 발표를 통해 법적·기술적 기반을 마련하고 있다.

핵심 동기는 다음과 같다.

- **지정학적**: 미국 FISA 702조, CLOUD Act(Clarifying Lawful Overseas Use of Data Act)에 의한 역외 데이터 접근, 중국 `데이터보안법`(2021)의 데이터 반출 통제, 러시아 `인터넷主权(인터넷 주권)법`(2019) 등境外(국외) 강제력에 대응
- **기술적**: X86(인텔/AMD), ARM(영국 SoftBank 계열), Windows(미국 MS), Oracle DB, AWS/Azure/GCP(미국 클라우드 3사) 등 단일 벤더 종속 시 공급 중단·백도어(backdoor)·가격 담합(price cartel) 리스크
- **경제적**: ICT 무역적자 2023년 기준 380억$, IT서비스 해외 라이선스 비용 18.2조원, IBM·Oracle DB 라이선스 단가 1코어당 연 11,200USD
- **보안적**: 하드웨어/소프트웨어 공급망을 통한 `SolarWinds`(2020), `Log4j`(2021), `XZ Utils`(2024) 등 공급망 공격(SCA, Supply Chain Attack) 차단

```text
+-----------------------------------------------------------------+
|           사이버 주권·디지털 자주권 3대 축 (3-Layer Sovereignty)  |
+-----------------------------------------------------------------+
|                                                                 |
|   [Layer 1: 데이터 주권]          [Layer 2: 기술 자주권]         |
|   +------------------+          +------------------+            |
|   |  데이터 주권법    |          |  국산 OS/DBMS    |            |
|   |  ·개인정보보호법  |          |  ·Gooroom/Hamoni |            |
|   |  ·데이터산업법    |          |  ·Tibero/Altibase|            |
|   |  ·가상자산이용자  |          |  ·국산 CPU (RISC)|            |
|   |   보호법         |          |  ·KCMVP 암호     |            |
|   +------------------+          +------------------+            |
|              |                            |                    |
|              +------------+---------------+                    |
|                           v                                    |
|   [Layer 3: 인프라 독립]                                          |
|   +-------------------------------------------------+          |
|   |  ·전용 회선·해저케이블 (TPEA, SJC)               |          |
|   |  ·국가 공공클라우드 (G-Cloud, Nutanix GoStack)   |          |
|   |  ·제로트러스트(Zero Trust)·국경통제(NGFW)        |          |
|   |  ·SBOM·SCRM(공급망위험관리)·HSM(하드웨어보안모듈) |          |
|   +-------------------------------------------------+          |
|                                                                 |
+-----------------------------------------------------------------+
```

과거(2000~2015)에는 IT 효율성과 글로벌 표준화·상호운용성(interoperability)을 우선시하여 화이트박스(white-box) 하드웨어와 범용 SW 도입이 주류였으나, 2018년 화웨이 제재, 2020년 코로나19, 2022년 러시아 SW 차단 사태 이후 각국은 "기술적 자주권"을 안보 핵심 의제로 격상시켰다. 한국의 경우 `주요정보통신기반시설`(2023년 478개), `전자정부법`(제52조의 2, 국산 SW 우선 구매), `중소 SW사업자 성장 지원에 관한 법률`(`SW 산업 진흥법`)을 통해 단계적 전환을 추진 중이다.

- **📢 섹션 요약 비유**: 사이버 주권은 "디지털 국경"을 세우는 일이다. 예전에는 모든 도로가 미·중·일 차도로만 깔려 있어 통행세를 내야 했고, 갑자기 도로가 막히면 화물 이동이 멈췄지만, 이제는 자국 화산암으로 자체 도로(국산 SW/HW)를 깔면서도 국제 표준 차폭(RISC-V, POSIX, ISO 27001)은 맞춰 두는 것이다.

## ⅰ. 아키텍처 및 핵심 원리

디지털 자주권 기술 독립은 크게 ①하드웨어 층 ②시스템 소프트웨어 층 ③미들웨어/플랫폼 층 ④네트워크·통신 층 ⑤보안·신뢰 층 ⑥거버넌스 층의 6개 스택으로 구성된다. 각 층은 자체 표준·인증체계·운영체계를 갖추되, 국제 표준(`ISO/IEC 15408` CC(Common Criteria), `FIPS 140-3`, `NIST SP 800-204`)과의 매핑을 통해 상호운용성을 확보하는 것이 핵심이다.

```text
+----------------------------------------------------------------------+
|         디지털 자주권 기술스택 (6-Layer Sovereign Stack)             |
+----------------------------------------------------------------------+
|                                                                      |
|  +-------[ L6: 거버넌스·법제층 ]--------------------------------+    |
|  | KISA 암호모듈검증(KCMVP) | CC인증 EAL4+ | 데이터산업법·가상자산|    |
|  +--------------------------------------------------------------+    |
|                              ^                                      |
|  +-------[ L5: 보안·신뢰층 ]----------------------------------+    |
|  | HSM(FastCrypto, TrusTica)| SBOM(SPDX/CycloneDX)| NGSWG|    |
|  | 국산 CA(한국정보인증)| DRM(스마트카드)| 양자내성암호(PQC)|    |
|  +--------------------------------------------------------------+    |
|                              ^                                      |
|  +-------[ L4: 네트워크·통신층 ]--------------------------------+    |
|  | 5G 코어(SKT 자체)| SDN/NFV(ETRI OpenFlow)| 양자암호통신(KT)|    |
|  | 국가 광케이블(KT/전송)| IPv6 전환(공공부문 80%)| 자체 DNS|    |
|  +--------------------------------------------------------------+    |
|                              ^                                      |
|  +-------[ L3: 미들웨어·플랫폼층 ]--------------------------------+    |
|  | 국산 DBMS(Tibero/Altibase/CUBRID)| 국산 WAS(Tmax/TomEE)|    |
|  | 국산 RPA(로빈)| 국산 BI(마이즈)| 국산 AI프레임워크(KoBig)|    |
|  +--------------------------------------------------------------+    |
|                              ^                                      |
|  +-------[ L2: 시스템 SW층 ]------------------------------------+    |
|  | 국산 OS(Gooroom/HamoniKR/AlthLinux)| 국산 오피스(한컴오피스)|    |
|  | 국산 웹브라우저(다음/네이버 Whale)| 국산 컴파일러(ETRI C++)|    |
|  | 국산 Firmware(Coreboot UEFI)| 자체 커널(Linux 5.10 LT)|    |
|  +--------------------------------------------------------------+    |
|                              ^                                      |
|  +-------[ L1: 하드웨어층 ]------------------------------------+    |
|  | 국산 CPU(AIM-R5/R8 RISC-V)| 국산 메모리(삼성/SK HBM3)|    |
|  | 국산 SSD(NVMe 컨트롤러)| 국산 GPU(ETRI 뉴로모픽)|    |
|  | 보안칩(KCMVP 적응형 보안토큰)| 자체 PCB·공급망|    |
|  +--------------------------------------------------------------+    |
|                                                                      |
+----------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **국산 OS (Gooroom/HamoniKR)** | 공공·교육·군 전장용 운영체제 | Debian 12 (Bookworm) 기반, 자체 `gooroom-platform`(KMS·인증·백업), Polkit/PAM(Pluggable Authentication Modules) 한국형 정책 확장, 5,200여 개 공공 SW 패키지 사전 호환, Trusted Boot(Measured Boot, TPM(신뢰플랫폼모듈) 2.0) 적용 |
| **국산 DBMS (Tibero 6)** | 오라클 호환 RDBMS(관계형데이터베이스) | PL/SQL 호환율 99.7%, RAC(Real Application Clusters) 유사 TSC(Transparent Session Continuity) 기술, `Active Storage` 인메모리 컬럼 엔진, `Hyper-scale Sharding` 통해 256노드 선형 확장, KCMVP 인증(ARIA-256 CBC/GCM) |
| **국산 CPU (AIM-R5/R8)** | RISC-V RV64GCV + Vector 1.0 | 5nm(나노미터) 공정, 2.0GHz, 8코어, ETRI NeuP(Neural Processing) NPU 통합, 측채널(SCA, Side-Channel Attack) 대응 캐시 라인 플러시 하드웨어, KCMVP-Trusted Boot 통합 |
| **KCMVP(한국암호모듈검증)** | 국가 핵심·민간 암호 모듈 강제 인증 | `KS X 3262`(국내 표준) = FIPS 140-3 level 2 이상, ARIA(국가표준 블록암호, 128/192/256bit), LEA(128bit 경량 블록), SEED(128/256bit), KCMVP는 CC EAL4+ 동시 취득, TTA(한국정보통신기술협회)·KISA 공동 운영 |
| **국가 공공클라우드 (G-Cloud)** | 행정·공공 데이터 격리 저장·처리 | CSAP(클라우드보안인증) 인증 필수(보안관리 76개 통제항목), 데이터 반출 구역(`Trusted Zone`), 정부 전용 가용구역(Availability Zone) 3중화, `K-Cloud Inside` 자국 SaaS(서비스형소프트웨어) 마켓 연동, 하이퍼스케일러 연동 시 암호화 게이트웨이(KoCrypto GW) 경유 |
| **SBOM·SCRM (공급망위험관리)** | SW·HW 구성 원소 가시화·취약점 추적 | SPDX 2.3 / CycloneDX 1.5 포맷, NTIA 최소필드(공급자, 버전, 의존성, 라이선스), `K-SBOM Hub`(KISA 운영), OWASP CycloneDX-GUI 기반, Zero-Day(제로데이) 탐지 시 VEX(취약점Exploit eXchange) 프로토콜로 패치 우선순위 산정 |
| **NG-SWG(차세대 보안관제)** | 사이버 주권 방어 운영체제 | SIEM(보안이벤트관리) + SOAR(보안오케스트레이션) + EDR(엔드포인트탐지대응) 통합, AI 행위기반(UEBA, 사용자/엔터티 행위분석) 이상탐지, 위협 인텔리전스(STIX 2.1/TAXII 2.1) 자동화, 자체 위협헌팅(Threat Hunting) 플랫폼(DeepEye) |

**핵심 동작 원리** — KCMVP 암호 모듈을 예로 들면, ①소프트웨어/하드웨어 개발자가 `KS X 3262` 11개 영역(①암호모듈 명세 ②암호모듈 인터페이스 ③역할·서비스·인증 ④소프트웨어/펌웨어 보안 ⑤물리적 보안 ⑥운영환경 ⑦암호키 관리 ⑧EMI/EMC(전자기파방해/전자기파적합성) ⑨자가시험 ⑩생명주기 ⑪기타 공격 대응) 충족 후 TTA에 제출 -> ②KISA 검증 시험(블랙박스·화이트박스, FIPS 140-3 알고리즘 시험) -> ③CC EAL(평가보증등급) 4+ 동시 인증(국제 상호인정 SOG-IS) -> ④정부 부처·공공기관 의무 사용(`국가사이버안보 가이드라인`, 2024) -> ⑤연 1회 재인증·사고 보고 체계 가동.
