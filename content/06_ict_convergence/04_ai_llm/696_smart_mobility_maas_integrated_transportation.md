# 📚 실무자 학습 노트: 696. 스마트 모빌리티 MaaS 통합 교통

---

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MaaS(Mobility as a Service)는 분산된 다중 교통수단(대중교통·공유모빌리티·라이드헤일링·UAM)을 GTFS/NeTEx/GBFS/TOMP/MDS 기반의 개방형 데이터 표준과 OJP·OAS(Open API Specification) 인터페이스로 통합하여, 단일 앱에서 **검색-예약-결제-이용-정산**의 End-to-End 이동 서비스를 제공하는 Subscription형 모빌리티 플랫폼 패러다임이다.
> 2. **가치**: 핀란드 Whim 사례 기준 사용자 통행시간 평균 23% 단축, 환승 대기시간 35% 감소, 차량 보유 의향 30% 하락(헬싱키시 2019 보고), 한국 의정부 U-Smart MaaS 시범서비스에서 월 평균 모빌리티 이용 횟수 4.2회->6.8회(62% 증가), 1인당 CO₂ 배출량 약 18% 저감 효과를 입증했다.
> 3. **판단 포인트**: 아키텍처는 **중앙집중형 Aggregator vs 분산형 Broker(Hybrid)**, 데이터는 **Push형(Streaming) vs Pull형(Polling)**, 수익모델은 **B2C 구독 vs B2G 공공조달 vs B2B 법인계약**의 3대 트레이드오프가 있으며, 실무적 판단 기준은 **①표준화 ②확장성 ③결제 무결성 ④데이터 주권 ⑤거버넌스**로 귀결된다.

## Ⅰ. 개요 및 필요성

### 1.1 배경과 패러다임 전환

기존 교통체계는 **수단별(Silo) 운영**이었다. 버스는 버스 회사 앱, 지하철은 별도 노선도, 택시와 공유모빌리티는 각기 다른 결제수단과 회원체계를 사용해 사용자는 "**마지막 마일(Last Mile) 단절**"과 "**결제 Fragmentation**"이라는 두 가지 고질적 문제를 겪었다. 한국은 1996년 서울버스 후불교통카드 도입, 2014년 티머니·캐시비 호환, 2016년 카카오버스(모바일 정보 통합)를 거치며 점진적으로 진화해 왔으나, 본질적으로 **"정보 통합"**에 머물러 있었다.

2020년 「지능형 교통체계 기본법」 개정과 「모빌리티 혁신법」('20.4. 시행)은 MaaS를 **공공-민간 데이터 결합의 핵심 인프라**로 격상시켰으며, 유럽은 EU MaaS Action Plan(2018)·Sustainable and Smart Mobility Strategy(2020)을 통해 Maas를 탄소중립의 핵심 수단으로 채택했다. 이러한 정책적 흐름은 단순한 어플리케이션이 아닌 **도시 운영체제(City OS) 수준의 인프라**로 자리매김하고 있음을 시사한다.

### 1.2 MaaS 진화 단계 (5단계 Maturity Model)

```text
[Level 0] 단절 (Fragmented) ----------------------------------
  버스/지하철/택시/공유모빌리티 각자 운영, 결제·정보 호환 X
                |
                v  <- 1996: 후불교통카드, 2014: 티머니/캐시비 호환
[Level 1] 결제 통합 (Payment Integration) --------------------
  하나의 카드로 다수단 결제 가능, 그러나 정보·예약은 별개
                |
                v  <- 2010: 스마트카드 표준화, 모바일 NFC
[Level 2] 정보 통합 (Information Integration) ----------------
  네이버/카카오/티맵에서 다수단 경로 통합 검색, 실시간 혼잡도
                |
                v  <- 2018: 의정부 U-Smart, 헬싱키 Whim
[Level 3] 예약-결제 통합 (Booking & Payment Integration) -----
  MaaS 앱 1개로 검색·예약·결제·이용까지 원스톱, 정기권(MTT) 제공
                |
                v  <- 2022: UAM 연계, 자율주행 Robotaxi 통합
[Level 4] 자율 통합 (Autonomous Integration) -----------------
  AI 기반 수요반응(DRT), 자율주행 셔틀, UAM, Hyperloop 통합
                |
                v  <- 2030: AAM(Advanced Air Mobility) 상용화
[Level 5] Seamless & Predictive (예측 기반) ------------------
  사용자 의도 사전 예측, 자동 경로·결제·환승, 완전 무마찰 이동
```

### 1.3 왜 MaaS가 필수인가 (구 vs 신 패러다임)

| 차원 | 기존 ITS 패러다임 | MaaS 패러다임 |
| :--- | :--- | :--- |
| 서비스 대상 | 차량·인프라 중심 | 사용자(여행자) 중심 |
| 데이터 흐름 | 단방향(Broadcast) | 양방향(Broker형 양방향 API) |
| 최적화 목표 | 통행속도·정체 최소 | 총 Door-to-Door 시간·비용·CO₂ |
| 수익 모델 | 공공재·세금 | B2C 구독 + B2B/B2G 하이브리드 |
| 기술 스택 | DSRC, CCTV, VMS | 5G, V2X, AI, Blockchain, Digital Twin |
| 통합 범위 | 단일 수단(예: 버스) | 다수단 + UAM + 자율주행 |

- **📢 섹션 요약 비유**: 기존 교통은 "**각 가게에서 따로따로 계산하는 시장**"이었다면, MaaS는 "**모든 상품을 한 바구니에 담고 카드 한 번에 결제하는 대형 마트**"이다. 계산대에서 마트 전체 합계 영수증을 받는 것이 곧 정기권(MTT: Multimodal Travel Ticket)이다.
