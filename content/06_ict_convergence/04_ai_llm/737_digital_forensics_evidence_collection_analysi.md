## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 디지털 포렌식의 핵심은 **무결성(Integrity)·연계성(Chain of Custody)·재현성(Repeatability)**의 3대 원칙 하에, ISO/IEC 27037(수집·보존)·27041(보증)·27042(분석)·27043(해석) 표준과 NIST SP 800-86 절차에 따라 **휘발성 증거(Volatility 순서: Registers -> Cache -> RAM -> Disk -> Remote)**를 식별·획득·복제·해시(SHA-256, 512)·분석하여 법정에서 **도입 가능성(Daubert/Frye 기준)**과 **증거능(Relevance, Hearsay Exception, Best Evidence Rule)**을 확보하는 전자증거과학(Electronic Evidence Science)이다.
> 2. **가치**: 2024년 기준 한국 경찰청 사이버수사 통계상 전체 사건의 **87% 이상**이 디지털 증거에 의존하며, ransomware·BEC·딥페이크 등 AI 기반 범죄의 증가로 메모리·클라우드·IoT 포렌식의 비중이 확대되고 있다. 정확한 수집·분석은 **재판 결과 전환율 30~40% 이상** 차이를 만들며, 부실한 포렌식은 "**과실에 의한 증거인멸(파괴금지 위반, 형사소송법 제126조)**" 및 "**위법수집증거 배제(위수법 제308조)**"로 증거 자체가 무력화된다.
> 3. **판단 포인트**: **Live Acquisition vs Dead Acquisition**, **Logical vs Physical vs File System Acquisition**, **On-Premise vs Cloud Forensics**, **도구 신뢰성 검증(EnCase/FTK/X-Ways 검증성 보고서)**, **휘발성 데이터 우선순위(1·2·3 Order of Volatility)**, **항변 대응(안티포렌식·타임라인 위조)**, **개인정보보호법 제3조(민감정보), 통신비밀보호법 제3조(통신사실 확인자료 제공)** 등 법적·기술적 트레이드오프를 종합적으로 판단해야 한다.

## Ⅰ. 개요 및 필요성

디지털 포렌식(Digital Forensics)은 **"사건 해결을 위해 디지털 매체에서 잠재적 법적 증거를 과학적으로 식별·보존·수집·검증·분석·해석·기록하는 과정"**으로 정의된다. 2001년 DFRWS(Digital Forensic Research Workshop)에서 6단계 모델(Identification -> Preservation -> Collection -> Examination -> Analysis -> Presentation)로 처음 학술적 정의를 확립한 이후, 클라우드·IoT·AI·암호화폐 등 새로운 디지털 환경으로 영역이 확장되고 있다.

```text
[디지털 포렌식의 진화: 매체별 영역 확장]

  2000s 초반              2010년대                    2020s                     2025+
  +----------+          +----------+             +----------+             +----------+
  |  Disk    |          |  Disk    |             |  Disk    |             |  Disk    |
  |  Forensics|  --►    |  + Memory|  --►        |  + Memory|  --►        |  + Memory|
  |  (HDD)   |          |  + Mobile|             |  + Mobile|             |  + Mobile|
  +----------+          |  + Net   |             |  + Cloud |             |  + Cloud |
                        +----------+             |  + IoT   |             |  + IoT   |
                                                +----------+             |  + AI/ML |
                                                                       |  + Crypto|
                                                                       |  + Vehicle|
                                                                       |  + Drone |
                                                                       +----------+
        단일 매체           멀티 매체               분산 환경                AI·자율환경
     (DD/EWF 이미지)     (RAM+Disk+네트워크)     (AWS/Azure 로그)         (디지털 트윈 증거)
```

**필요성의 기술적 배경**:
- **디지털 의존도 폭증**: 현대 범죄(내·외부 유출, 사이버불링, 해킹, 영업비밀 침해)의 **95% 이상**이 디지털 흔적을 남기며, 한국 정보보호산업의 2023년 사이버침해사고 대응 건수는 약 **38만 건**으로 집계된다.
- **휘발성 데이터의 위협**: RAM(평균 수명 μs~ms), 네트워크 패킷(수 ms), ARP 캐시(수 분), 라우팅 테이블(수 시간), 디스크(수년) 등 **휘발성 순서(Order of Volatility)**에 따른 우선 수집 전략이 필수다.
- **법정 채택 기준 강화**: 2023년 대법원, "디지털 증거의 경우 위·변조 가능성이 항상 존재하므로 **수집·보존 과정의 엄격성**, **전문가의 검증**, **도구의 신뢰성**이 입증되어야 한다"는 판례를 확립(대법원 2023도12345 등).
- **규제 환경**: 개인정보보호법 제29조(안전조치), 정보통신망법 제28조(개인정보 영향평가), 통신비밀보호법(통신사실 확인자료의 제공요청), 전자문서법, 형사소송법 제306조(서증)·제308조(위법수집증거배제)가 포렌식 절차와 직결된다.

**기존 vs 새로운 패러다임 비교**:
| 패러다임 | 전통적 (2000s) | 현대적 (2020s~) |
|---|---|---|
| 증거 매체 | HDD, USB, CD | SSD, NVMe, 클라우드, 컨테이너, Kubernetes, 차량 ECU |
| 수집 방식 | Dead Acquisition, HPA/DCO 우회 | Live Acquisition, Memory Snapshot, Cloud API Snapshot |
| 분석 도구 | 단일 도구(EnCase) | 멀티도구(Autopsy + Volatility + Plaso + Velociraptor) |
| 법적 기준 | Best Evidence Rule 위주 | GDPR·PIPC·전자증거 국제공조(IIP) 포함 |
| 위협 | 단순 삭제, 포맷 | Anti-Forensics(Secure Erase, TRIM, Shim Cache, timestomping), AI 생성 증거 |

- **📢 섹션 요약 비유**: 디지털 포렌식은 **"현장 보존이 생명인 디지털 CSI"**다. 흙바닥의 발자국도 시간이 지나면 비가 쓸어버리듯, RAM의 흔적은 재부팅 1초 후, SSD의 TRIM은 수 초 후, 클라우드 로그는 정책에 따라 며칠 후 사라진다. 그래서 **휘발성 순서표(Volatility Order)**라는 "디지털 119구급 순서표"에 따라 가장 먼저 사라질 증거부터 확보해야 한다.

## Ⅱ. 아키텍처 및 핵심 원리

디지털 포렌식의 전체 아키텍처는 **DFRWS 6단계** 또는 **ISO/IEC 27037-27043** 프레임워크에 기반하며, **연계 보관성(Chain of Custody)**이 모든 단계를 관통하는 핵심 메타-프로세스다.

```text
[디지털 포렌식 통합 아키텍처: ISO/IEC 27037~27043 + NIST 800-86]

  +-----------------------------------------------------------------------------+
  |  Phase 1: Identification (식별) - ISO/IEC 27037                              |
  |  +-----------------+  +-----------------+  +-----------------+              |
  |  | 잠재 증거 매체   |  | 휘발성 데이터    |  | 원격 증거(클라우드|              |
  |  | - HDD/SSD/NVMe  |  | - RAM/Registers |  |  - AWS CloudTrail|             |
  |  | - USB/외장      |  | - Cache/Buffers |  |  - Azure Logs   |              |
  |  | - Mobile/iOS    |  | - Net Sessions  |  |  - GCP Audit    |              |
  |  +--------+--------+  +--------+--------+  +--------+--------+              |
  +-----------+---------------------+---------------------+--------------------+
              |                     |                     |
              v                     v                     v
  +-----------------------------------------------------------------------------+
  |  Phase 2: Collection (수집) - 현장 도구                                      |
  |  +-----------------+  +-----------------+  +-----------------+              |
  |  | Write Blocker   |  | 메모리 덤프      |  | 네트워크 패킷    |              |
  |  | (Tableau/T5)    |  | (WinPmem/LiME)  |  | (tcpdump/CACE)  |              |
  |  | H/W 차단 -> Read |  | .raw/.lime/.dmp |  | .pcap/.pcapng   |              |
  |  +--------+--------+  +--------+--------+  +--------+--------+              |
  +-----------+---------------------+---------------------+--------------------+
              |                     |                     |
              v                     v                     v
  +-----------------------------------------------------------------------------+
  |  Phase 3: Preservation (보존) - 무결성 보장                                 |
  |   +--------------------------------------------------------------+          |
  |   |  원본 --[Forensic Image]--► E01/DD/AFF4 + Hash(MD5/SHA1/SHA256)         |
  |   |         EWF(E01/E02) : 메타데이터, 압축, 분할 저장, CRC 내장             |
  |   |         AFF4 : Advanced Forensic Format 4 (대용량, 병렬)                 |
  |   |         DD   : Raw bit-stream (법정 호환성 최우수)                       |
  |   +--------------------------------------------------------------+          |
  +-----------------------------------------------------------------------------+
              |
              v
  +-----------------------------------------------------------------------------+
  |  Phase 4: Examination (검사) - 데이터 추출                                    |
  |  +--------------+ +--------------+ +--------------+ +--------------+      |
  |  | File Carving | | Registry     | | Log Parsing  | | SQLite/MFT   |      |
  |  | (PhotoRec/   | | (RegRipper/  | | (Log2t/Plaso)| | (MFTECmd/    |      |
  |  |  Scalpel)    | |  RegistryNavi| |              | |  Plaso)      |      |
  |  +--------------+ +--------------+ +--------------+ +--------------+      |
  +-----------------------------------------------------------------------------+
              |
              v
  +-----------------------------------------------------------------------------+
  |  Phase 5: Analysis (분석) - 상관관계·타임라인                                |
  |  +--------------------------------------------------------------+          |
  |   | Timeline Correlation:  $MFT + Prefetch + EVTX + LNK + JumpList        |
  |   |  -> Super-Timeline(μs 단위 통합 타임라인)                               |
  |   |  -> Volatility: 프로세스, DLL, 네트워크, 레지스트리, 코드 인젝션         |
  |   |  -> Plaso/log2timeline: 다중 로그 통합 파싱                             |
  |   |  -> AI/ML: 이상탐지, 패턴 매칭 (Ex: 문자열 인코딩, 암호화폐 주소)        |
  +--------------------------------------------------------------+          |
  +-----------------------------------------------------------------------------+
              |
              v
  +-----------------------------------------------------------------------------+
  |  Phase 6: Presentation (제출) - 법정 보고                                    |
  |   +--------------------------------------------------------------+          |
  |   |  Forensic Report: 사실관계, 도구/버전, 해시, 재현 절차, 판단 근거        |
  |   |  Expert Testimony: Daubert (방법론 검증, 동료 심사, 오류율, 표준 채택)   |
  |   |  Chain of Custody: 시점·인수자·목적·상태의 연속적 기록                  |
  |   +--------------------------------------------------------------+          |
  +-----------------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
|:---|:---|:---|
| **Write Blocker (쓰기 차단기)** | 원본 매체에 **읽기 전용** 접근을 강제하여 의도치 않은 변형 방지 | **H/W형**(Tableau T8u, WiebeTech, ICS): IDE/SATA/NVMe/USB 브리지 컨트롤러(FPGA)로 ATA/SCSI 명령어 중 `WRITE(0x2A/0xAA)` 차단, **S/W형**(Windows: `UBpc`, Linux: `blockdev --setro`): OS 레벨 I/O 필터 |
| **Forensic Imaging (이미징)** | 원본과 **비트 단위 동일**한 사본 생성, `E01`(EWF)·`DD`(Raw)·`AFF4` 형식 | `dd`, `dcfldd`(병렬 해시), `FTK Imager`, `EnCase`, `Guymager`: 압축·분할·CRC-32/SHA1·SHA256 동시 산출, **Sparse Aware**(할당되지 않은 섹터 0) 처리 |
| **Hashing (해시)** | 디지털 지문, **무결성 증명**의 핵심 | MD5(128bit, 충돌 발견됨/단독사용 금지), **SHA-1**(160bit, SHAttered 공격으로 deprecated), **SHA-256**(256bit, NIST FIPS 180-4, 현재 표준), **SHA-512**(512bit, 고속 디스크용), **Merkle-Damgård** 구조 기반 |
| **Memory Forensics (메모리 분석)** | RAM의 휘발성 잔재로부터 프로세스/네트워크/키로깅/루트킷 추출 | **Volatility 2/3**(Python, Win/Linux/Mac), **Rekall**, **MemProcFS**: 프로세스 트리, 핸들, DLL, 네트워크 연결, 코드 인젝션, EPROCESS, KDBG 구조체 분석 |
| **Mobile Forensics (모바일 분석)** | iOS/Android의 앱 데이터, 채팅, GPS, 사진 메타데이터 | **Cellebrite UFED 4PC**, **MSAB XRY**, **Magnet AXIOM**, **iMazing**: Logical(앱 DB 추출) / File System(파일시스템) / Physical(전체 플래시) / Chip-off(BGA 리볼) |
| **Network Forensics (네트워크 분석)** | 패킷 캡처, 흐름 분석, 침해 추적 | **Wireshark**(GUI),
