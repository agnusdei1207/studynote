## 핵심 인사이트 (3줄 요약)

> 1. **본질**: P2P 마켓플레이스 신뢰는 Akerlof의 "Lemons Problem"이 양면 시장 구조에서 발현하는 정보 비대칭을 해결하기 위한 **평판 시스템(Reputation System) + 신원 검증(Identity Proofing) + 에스크로(Escrow) + 분쟁 해결(Dispute Resolution)** 4축 통합 아키텍처이며, EigenTrust·HodgeRank·Bayesian Reputation 등 알고리즘으로 정량화된다.
> 2. **가치**: Airbnb의 양방향 리뷰 시스템 도입 후 예약 전환율이 **+12.4%p** 상승했고, Uber의 1,000+ Driver Rating 기반 매칭으로 사고율을 0.0003% 수준으로 유지, B2C 대비 P2P 거래의 마찰 비용을 **30~70% 절감**하여 양면 네트워크 효과의 cold start를 가속화한다.
> 3. **판단 포인트**: **중앙화 평판 DB vs DID/VC 기반 자기주권 신원**, **거래액 구간별 적정 검증 강도(KYC Tier)**, **신선도 민감도 vs 조작 저항성 trade-off**, 그리고 **양방향 리뷰의 후행 평가 편향(Posterior Bias)**을 어떻게 보정할지가 아키텍처 결정의 핵심이다.

## Ⅰ. 개요 및 필요성

P2P(Peer-to-Peer) 마켓플레이스는 호텔·택시·금융 등 전통 B2C 산업을 **다대다(many-to-many)** 거래 구조로 해체한 공유경제의 핵심 인프라다. Uber, Airbnb, Turo, Upwork, Kakao T 바이크, Toss P2P 송금, 당근마켓, Karrot(당근) 등이 그 예시이며, 2024년 글로벌 공유경제 시장 규모는 약 **$573B**, 2027년 $1.5T(CAGR 23.4%)로 전망된다.

그러나 P2P 구조는 본질적으로 **신뢰의 부재**라는 구조적 결함을 가진다. 숙소가 사진과 다른 경우(2023년 Airbnb 사기 건수 5,400건), 차량 렌탈 훼손 분쟁, 프리랜서 결과물 미달, P2P 송금 사기(2022년 한국 1,540억원) 등은 모두 "상대가 도주/파산/사기 행위"를 수행할 수 있다는 신뢰 부재에서 기인한다. 전통 B2C에서는 호텔 체인·렌터카 법인·은행이 신뢰의 보증인이지만, P2P에서는 **플랫폼이 신뢰의 중개자**가 되어야 한다.

이 신뢰 메커니즘의 설계 실패는 **양면 네트워크 효과의 붕괴**를 야기한다. 공급자(호스트/드라이버/렌터)는 손상 위험을 회피해 이탈하고, 수요자(게스트/승객)는 품질 불안을 이유로 이탈하는 **"죽음의 나선(Death Spiral)"**이 발생한다. eBay 초기에는 월 1,000만 건의 거래 중 약 **3%**가 분쟁으로 접수되었고, 적시에 해결하지 못해 listing이 25% 감소한 사례가 대표적이다.

```text
   +-------------------------------------------------------------+
   |         P2P 마켓플레이스 신뢰 부재의 3대 Pain Point          |
   +-------------------------------------------------------------+

   [1] 정보 비대칭 (Information Asymmetry)  [2] 도덕적 해이 (Moral Hazard)
   +-------------------+                +-------------------+
   |  게스트: 사진과 다름|                |  입금 후 연락두절  |
   |  호스트: 파손 발생  |                |  차량 인계 후 도주  |
   |  작업자: 결과물 미달 |                |  송금 사기(fraud)  |
   +---------+---------+                +---------+---------+
             |                                    |
             v                                    v
        [3] 콜드 스타트 (Cold Start)         [4] 평판 조작 가능성
   +-------------------+                +-------------------+
   | 신규 유저 평가 0건  |                | 셀러 협업 평판 (Rep)|
   | -> 매칭 거부율 ^   |                | 페이크 리뷰 봇     |
   | -> 신규 이탈 ^     |                | Sybil Attack      |
   +-------------------+                +-------------------+
```

**기존 B2C 신뢰 모델과의 비교**

| 구분 | 전통 B2C (호텔 체인) | 초기 P2P (2008~) | 현대 P2P (2020~) |
| :--- | :--- | :--- | :--- |
| 신뢰 보증 주체 | 법인(브랜드) | 단순 리뷰 텍스트 | 평판 알고리즘 + 신원 + 에스크로 + 보험 |
| 분쟁 해결 | 본사 CS, 매장 책임 | 당사자 자율 해결 | 플랫폼 개입형 3자 중재 |
| 정보 검증 | 자체 audit | 사용자 신고 | ML 기반 위변조 탐지 |
| 신뢰 비용 | 임대료/인건비에 포함 | 매칭 실패 비용 | 거래액의 5~12% 수수료로 흡수 |

- **📢 섹션 요약 비유**: P2P 마켓플레이스의 신뢰 시스템은 **"동네 사람이 아닌 낯선 이에게 차를 맡기는"** 것과 같다. 차 키를 건네기 전에 상대방의 운전 경력, 신분증, 이전 차주 후기를 확인하고, 미리 보험과 보증금을 설정해둬야 안심하고 거래할 수 있다.

## Ⅱ. 아키텍처 및 핵심 원리

P2P 마켓플레이스 신뢰 시스템은 **수집 계층 -> 정제/검증 계층 -> 평판 산출 계층 -> 매칭/결제/분쟁 계층**의 4-tier 아키텍처로 구성된다.

```text
   +--------------------------------------------------------------+
   |                  P2P Trust Platform Architecture              |
   +--------------------------------------------------------------+

   [Tier 1: 데이터 수집]      [Tier 2: 검증/정제]      [Tier 3: 평판 산출]
   +-------------+           +-------------+         +-------------+
   |  OAuth 2.0  |--인증----->|   KYC/AML   |         |  Bayesian   |
   |  OpenID C.  |           |   (Onfido,  |         |  Reputation |
   |  DID/VC(W3C)|           |    Persona) |         |  (Beta Dist)|
   +------+------+           +------+------+         +------+------+
          |                          |                       |
   +------v------+           +------v------+         +------v------+
   |  행동 로그   |           |   이상치    |         |  EigenTrust |
   |  (Kafka)    |----------->|   탐지 ML   |--------->|  /TrustRank |
   |  결제 로그   |           |   (XGBoost) |         |  (Graph)    |
   +------+------+           +------+------+         +------+------+
          |                          |                       |
   +------v------+           +------v------+         +------v------+
   |  양방향 리뷰 |           |   SBERT     |         |  HodgeRank  |
   |  (Post-txn) |----------->|   (위변조)  |--------->|  (협업 리뷰)|
   +-------------+           +-------------+         +------+------+
                                                             |
   [Tier 4: 매칭/거래/분쟁]                                  |
   +-------------+         +-------------+         +-------v-----+
   |  Stripe Conn.|<---------| Smart Escrow|<---------|  Trust Score|
   |  /Adyen     |         | (Eth/Polygon)|         |  (0~1000)   |
   +------+------+         +------+------+         +-------------+
          |                         |
   +------v------+         +------v------+
   |  보험/보증  |         | 분쟁 해결  |
   |  (AirCover) |         | (ODR/Trib.|
   +-------------+         |  Arbitration)|
                            +-------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **Identity Provider (IdP)** | OAuth 2.0 / OIDC / DID-Comm으로 신원 발급·검증 | W3C DID 표준(`did:ethr:0x...`), Verifiable Credentials(JWT+SD-JWT), 신원 증명 가중치 부여 (신용카드>이메일>전화번호 순) |
| **KYC/AML 엔진** | 실명·주소·생체 검증으로 사기꾼 가입 차단 | Onfido, Persona, Kakao Cert, NICE신용평가 API; document liveness(ML), face match(ArcFace), sanctions screening(OFAC) |
| **Reputation Engine** | 거래 후 평판 점수 산출 및 노출 | Bayesian Average(평균+사전 분포 가중치), Time-Decay(반감기 90일), Volume Confidence(거래수 50건 미만 페널티) |
| **Graph Trust (Trust Propagation)** | 평판 점수가 없는 신규 유저를 그래프 탐색으로 평가 | EigenTrust(PageRank 변형), HITS Hubs/Authorities, SybilRank(친구 그래프 클러스터링) |
| **ML Fraud Detection** | 비정상 거래 패턴·리뷰 텍스트 위변조 탐지 | XGBoost/LightGBM(피처 200+), SBERT 코사인 유사도(스팸 리뷰), HodgeRank(협력 셀링 그래프 랭크 추정) |
| **Smart Escrow & Payment** | 거래 대금의 조건부 보관·정산 | Stripe Connect(Direct Charge), Adyen MarketPay, Polygon zkEVM 기반 멀티시그 에스크로, ERC-20/ERC-721 송금 |
| **Dispute Resolution (ODR)** | 분쟁 발생 시 3자 중재·배상 | Modria/DisputeSuite(규칙기반), SmartContract 자동 환불, 당사자 협의->중재->AI 판정 단계별 에스컬레이션 |

### 핵심 알고리즘 심화 분석

**1) Bayesian Reputation System**
eBay·Airbnb가 채택한 핵심 알고리즘이다. 단순 평균의 문제를 해결한다.

```
R(u) = (n / (n + α)) × avg(u) + (α / (n + α)) × R_prior

where:
  n   = 사용자 u의 평가 횟수
  α   = prior weight (보통 10~50, 트래픽이 적을수록 크게)
  R_prior = 글로벌 평균 평판 (예: 4.5/5)
```

신규 유저(n이 작음)일수록 글로벌 평균 쪽으로 수렴해 콜드 스타트 문제를 완화한다.

**2) EigenTrust (P2P 신뢰 전파)**
분산 환경에서 악의적 노드의 평판 조작을 방지하기 위해 설계된 알고리즘으로, Kamvar et al.(2003)이 제안했다.

```
t_{i+1} = (1 - d) × C^T × t_i + d × p

where:
  C[i][j] = 노드 i가 노드 j에 부여한 신뢰의 정규화된 값
  d       = damping factor (보통 0.15, PageRank와 동일)
  p       = pre-trusted 노드 분포
```

`pre-trusted` 노드 집합을 시드로 두면 Sybil 노드(여러 가짜 ID를 만들어 신뢰를 부풀리는 공격)는 그래프 cut에서 자연스럽게 분리되어 낮은 점수를 받는다.

**3) HodgeRank & SybilRank**
Hodge Decomposition(그래프 라플라시안의 3분해: gradient + curl + harmonic)을 평점 그래프에 적용해 **협력적 평판 조작(Collusion)**을 탐지한다. 정상 평점 분포는 gradient 성분(일관성)에 강하고, 셀러 합동 평판 부풀리기는 curl 성분(순환)에 강하게 나타나므로 score가 음수가 되면 자동 플래그한다.

- **📢 섹션 요약 비유**: 신뢰 시스템은 **"학교 성적표"** 와 같다. 단순히 시험 점수만 적는 게 아니라, 출석률(거래 횟수), 선생님 평가(리뷰), 친구들의 평판(이웃 그래프), 그리고 부정행위 감시(ML 탐지)를 종합해 A~F 등급을 매기는 시스템이라 할 수 있다.

## Ⅲ. 비교 및 연결

### 1. 평판 시스템 패러다임 비교

| 구분 | 중앙 집중 평판 (Airbnb) | 자기주권 신원 (DID/VC) | 블록체인 평판 (Ethereum Attestation) |
| :--- | :--- | :--- | :--- |
| **데이터 저장** | 플랫폼 DB (MySQL/Cassandra) | 사용자 지갑 (IPFS Ceramic) | 온체인 Attestation Contract |
| **이식성** | 플랫폼 종속 | 다른 플랫폼으로 이전 가능 | 체인 어디서나 검증 가능 |
| **검증 강도** | KYC + 사진+위치 | VC 서명 검증(ZKP-Selective Disclosure) | 스마트 컨트랙트 트리거 |
| **조작 저항** | ML 기반 탐지 (HodgeRank) | 발급자 서명 검증 | 불변 이력, 단 컨센서스 취약 |
| **응답 속도** | 50~200ms (Redis 캐시) | 1~3초 (DID Resolution) | 5~15초 (블록 확정) |
| **규제 준수** | GDPR/개인정보보호법 직접 적용 | 본인이 데이터 통제 (GDPR 친화) | 미정, EU MiCA 검토 중 |
| **신규 유저 진입장벽** | 낮음 (이메일 가입) | 중간 (지갑/시드 구문) | 높음 (가스비·지갑 관리) |
| **적합 워크로드** | 거래액 < $1K 일반 B2C | 대출·고액 거래·의료 | DAO 평판·디지털 자산·탈중앙 신원 |
| **예시 플랫폼** | Airbnb, Uber, 당근마켓 | Microsoft Entra Verified ID, Spruce ID | Lens Protocol, Farcaster, EthSign |
| **결제** | Stripe Connect, Adyen | x402 Payment Required, L402 (Lightning) | USDC, DAI, ETH |

### 2. 기존 시스템과의 통합

P2P 신뢰 시스템은 독립 컴포
