## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 비정형 텍스트(HTML, SNS, PDF, 로그, 한글 코퍼스)는 구조화된 형태소·토큰 단위로 정규화되어야만 TF-IDF, Word2Vec, BERT 임베딩 등 후속 마이닝 모델(토픽 모델링·감성분석·NER·문서분류)이 통계적·의미적 신호를 추출할 수 있으며, 한글의 교착어적 특성(조사·어미 변형, 띄어쓰기 비일관성) 때문에 영어권 Stemmer/Lemmatizer와 다른 형태소 분석기(KoNLPy, Mecab, Khaiii, OKT) 기반의 어절 분리·품사 태깅이 필수적이다.
> 2. **가치**: 체계적 전처리를 수행할 경우 노이즈 토큰 비율이 평균 35~60% 감소하고, KoBERT/SBERT 임베딩 기반 분류기의 F1-score가 비전처리 대비 8~15%p 향상되며, 토픽 모델링(LDA)에서는 Perplexity 기준 20~40% 개선되어 동일 GPU/메모리 예산에서 분석 정확도와 처리량(throughput) 모두를 동시 확보할 수 있다.
> 3. **판단 포인트**: 형태소 분석기 선정 시 속도(Mecab > OKT > Hannanum > Komoran > Khaiii)와 정확도(Khaiii > Komoran > OKT > Mecab)의 Trade-off, 형태소 vs Subword(BPE, WordPiece) 선택이 OOV(Out-Of-Vocabulary) 대응력과 도메인 일반화에 미치는 영향, 그리고 도메인 사전(金融·医療·法律)·불용어 리스트의 도메인 특화 여부가 최종 분석 품질의 70% 이상을 결정한다.

## Ⅰ. 개요 및 필요성

디지털 데이터의 약 80~90%는 비정형 텍스트 형태로 존재하며, IDC 보고서에 따르면 2025년 전 세계 데이터 총량은 175 ZB에 이를 것으로 전망되며 이 중 비정형 데이터가 약 80%를 점유한다. 한국어 텍스트는 교착어(Agglutinative Language)로서 "나는 학교에 갔다"가 "내가/학교에서/갔다/었어"처럼 조사·어미가 자유롭게 결합되어 동일한 어휘(학교)가 문맥에 따라 형태가 변형되며, 띄어쓰기 오류, 신조어, 한자어, 외래어, 이모티콘이 혼재되어 있어 영어 중심의 NLTK·spaCy 파이프라인을 그대로 적용할 수 없다. 또한 의료(EMR), 법률(판례), 금융(공시·공시 첨부파일) 도메인에서는 전문용어의 비중이 30~50%에 달해 일반 어휘 사전만으로는 정확한 토큰화가 불가능하다.

텍스트 마이닝 전처리는 원시 코퍼스(Raw Corpus)를 정제·정규화·벡터화하여 머신러닝/딥러닝 모델이 직접 소비 가능한 Feature Space로 변환하는 전(全) 파이프라인을 의미하며, **"Garbage In, Garbage Out"** 원칙이 가장 극명하게 적용되는 단계이다. 동일 알고리즘(LSTM, BERT)·동일 하이퍼파라미터 조건에서도 전처리 품질에 따라 모델 성능 차이가 30% 이상 발생할 수 있으며, 전세계 AI 경진대회(Kaggle, AI Hub) 우승 솔루션 분석 결과 **상위 10% 솔루션의 차별점 중 약 65%가 전처리·피처 엔지니어링에 집중**되어 있다.

기존 통계 기반 NLP 시대(2000년대 초반)에는 BoW(Bag-of-Words) + TF-IDF + LDA(Latent Dirichlet Allocation)가 표준이었으나, 어순 무시, 희소성(Sparsity), 다의어 미해결 문제가 한계였다. 현재(2020년대~)는 Subword Tokenization(BPE, WordPiece, SentencePiece) + Contextual Embedding(KoBERT, KR-ELECTRA, Llama-3-Ko, Solar-Ko) 기반으로 패러다임이 전환되었으며, 특히 한국어의 경우 KoNLPy 형태소 분석기를 거친 텍스트를 다시 SentencePiece로 Subword 분할하는 **2단계 토크나이저(Hybrid Tokenizer)** 가 표준으로 자리 잡았다.

- **📢 섹션 요약 비유**: 텍스트 전처리는 마치 **요리사의 '미싱(食材 손질)' 과정**과 같다. 시장(raw corpus)에서 사 온 채소(HTML, 자모 분리, 오탈자)를 씻고(cleaning), 잎과 줄기를 갈라내고(tokenization), 먹을 수 없는 부분(불용어)을 제거한 후에야 비로소 볶음·끓이기(모델링) 단계로 넘어갈 수 있다. 5성급 호텔 셰프의 코스는 신선한 손질에서 시작되며, 1차 손질 미숙은 어떤 화려한 조리법으로도补救할 수 없다.

## Ⅱ. 아키텍처 및 핵심 원리

비정형 텍스트 전처리 시스템은 **수집->정제->형태소 분석->필터링->벡터화->저장**의 6단계 파이프라인으로 구성되며, 각 단계는 독립적인 마이크로서비스로 분리되어야 처리량 확장(Spark, Ray, Dask) 및 장애 격리가 가능하다. 실무에서는 Apache Airflow / Argo Workflows로 단계별 Task를 Orchestration하며, **Idempotency(멱등성)** 보장을 위해 단계별 Output을 Delta Lake / Parquet 형식으로 체크포인트한다.

```text
[실무 분산 전처리 아키텍처 - MSA + Spark 기반]

  +---------------------------------------------------------------------+
  |                       Orchestration Layer                           |
  |              Apache Airflow / Argo Workflows / Prefect              |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 1.  Ingestion (Kafka Topic: raw.text.{source})                |
  |   - Batch: Scrapy, BeautifulSoup, Tika(PyPDF2), Docling            |
  |   - Stream: Kafka Connect, Debezium CDC, Fluentd                    |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 2.  Cleaning (Dask / PySpark UDF)                            |
  |   +------------------------------------------------------+         |
  |   | Regex Pattern Bank:                                   |         |
  |   |   r'http\S+'        -> URL 제거                        |         |
  |   |   r'@\w+'           -> 멘션 제거                       |         |
  |   |   r'#\w+'           -> 해시태그 분리/제거               |         |
  |   |   r'[^\w\s가-힣]'   -> 특수문자 제거(보존 옵션 가능)    |         |
  |   |   unicodedata.normalize('NFKC', x) -> 유니코드 정규화  |         |
  |   +------------------------------------------------------+         |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 3.  Korean Morphological Analysis (GPU/CPU Pool)              |
  |   +------------------------------------------------------+         |
  |   |  Worker Pool:  Mecab(rc=4) / KoNLPy(OKT,Kkma)        |         |
  |   |  출력: [('나','NP'),('는','JX'),('학교','NNG'),...]   |         |
  |   |  품사 필터: NNG(일반명사) NNP(고유명사) VV(동사) VA   |         |
  |   |          SL(외래어) SH(한자)                          |         |
  |   +------------------------------------------------------+         |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 4.  Stopword & N-gram                                        |
  |   Stopword List (Union: general ∪ domain-specific)                 |
  |   Bigram/Trigram: mutual_info > threshold                          |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 5.  Vectorization                                             |
  |   +--------------+  +--------------+  +--------------+             |
  |   | Sparse:      |  | Static Emb:  |  | Context Emb: |             |
  |   | TF-IDF       |  | Word2Vec     |  | KoBERT       |             |
  |   | (sklearn)    |  | FastText     |  | (Last 4 layer|             |
  |   | dim=V        |  | dim=100~300  |  |  mean pool)  |             |
  |   |              |  |              |  | dim=768      |             |
  |   +--------------+  +--------------+  +--------------+             |
  +----------------------------+----------------------------------------+
                               v
  +---------------------------------------------------------------------+
  |  Stage 6.  Feature Store + Vector DB                                |
  |   Lakehouse (Iceberg/Delta) + FAISS / Milvus / Pinecone / Weaviate |
  +---------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **Ingestion Layer** | 다양한 비정형 소스(웹, SNS, PDF, 로그, RSS) 통합 수집 | Scrapy(웹크롤러, robots.txt 준수), Tesseract/Docling(OCR+PDF), Kafka(Fluentd Logstash, Exactly-Once Semantics), `Tika`(포맷 자동 감지) |
| **Cleaning Engine** | 노이즈 제거·유니코드 정규화·인코딩 통일 | `unicodedata.normalize('NFKC')`로 전각/반각 통일, `BeautifulSoup`로 HTML 태그 제거, 정규식 기반 URL·이메일·이모티콘 처리, **2-byte/3-byte 한글 보존** 위해 `[^가-힣ㄱ-ㅎㅏ-ㅣa-zA-Z0-9\s]` 활용 |
