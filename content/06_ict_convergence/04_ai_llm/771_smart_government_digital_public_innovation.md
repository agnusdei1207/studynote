## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 종이·대면·부서별 칸막이 행정에서 클라우드·데이터·AI·블록체인 기반 **공공데이터 개방형 플랫폼(Open Data Platform) + 정부서비스버스(GSB, Government Service Bus) + AI 시민비서**로 전환하는 **정부 아키텍처(E-Government Reference Architecture) 패러다임 전환**
> 2. **가치**: 연간 행정비용 약 **4.3조 원 절감**(2023년 행정안전부), 민원 처리 시간 평균 **70% 단축(9.4일->2.8일)**, 24/7 비대면 서비스 가용성 99.9% SLA, 정부24 누적 이용자 **2.6억 명**(2024년 기준)
> 3. **판단 포인트**: 레거시(AS/400, Oracle EBS, 전산센터) -> 클라우드 네이티브(Kubernetes, MSA) 전환 전략, **전자정부 표준프레임워크 vs 클라우드-네이티브 듀얼 트랙**, 데이터 주권(데이터 3법)과 AI 윤리, 시민 UX 단순성 vs 백엔드 통합 복잡도 간 트레이드오프

## Ⅰ. 개요 및 필요성

정부는 2000년대 **전자정부법(2001)** 이후 정부24(구 민원24), 정부통합전산센터, 행정망/인터넷망 분리, 전자조달, 전자세금 등 점진적 디지털화를 추진해 왔으나, 4차 산업혁명·초저연장·팬데믹·저출생·인구구조 변화라는 **VUCA 환경**에서 '**더 적은 자원으로 더 많은 시민 가치를 창출**'해야 하는 구조적 한계에 직면했다. 또한 단위 부서 단위 시스템(200여 종) 간 데이터 사일로(Silo), 칸막이 행정, 인증·결제·문서 교환의 비표준화, 주 5일 9~18시 업무시간 종속의 **non-24/7 서비스** 문제가 지속되어, OECD **정부 디지털 성숙도(Digital Government Index, DGI)** 평가에서 우리나라는 2019년 2위권이었으나 2023년 하락세로 전환점을 맞았다.

이에 **「디지털 정부 혁신 추진계획」(2022, 관계부처 합동)**, **「공공데이터 개방 및 활용에 관한 법률」**, **「지능형 정부 기본법(2024.1 시행)」** 등 법적·정책적 기반 위에서 '데이터·AI·클라우드' 3대 축을 중심으로 정부 전체를 하나의 **플랫폼(One-Platform Government)**으로 재설계하는 작업이 진행 중이다.

```text
[ 종이 정부 / 전자정부 / 스마트 정부 / 디지털 정부 진화 계보 ]

 (1960~1999)         (2000~2014)         (2015~2020)          (2021~ )
  종이·대면             e-Government         Smart Gov.            Digital Gov. (Gov.AI)
 +----------+        +----------+         +----------+         +----------+
 | 서류·현장  |   ->    | 웹·DB·PKI |    ->    | 모바일·빅데이터| -> | AI·클라우드 |
 | 관청 방문  |        | EDI·EKP  |         | IoT·공공데이터|    | 메타버스·LLM|
 +----------+        +----------+         +----------+         +----------+
  - 오프라인           - 전자결재            - 정부24 v2.0         - Gov.AI (1.0)
  - 주5일/9~18시       - 인터넷 민원          - 모바일 신분증        - 메타버스 정부
                       - 행정망/인터넷망       - 공공데이터 포털      - AI 윤리·신뢰
                         분리(2007)            (data.go.kr)          - 제로터치 행정
```

기존의 전자정부는 '**업무시스템의 단순 전자화**'(E-Automation)에 머물렀다면, 스마트/디지털 정부는 '**시민 여정(Citizen Journey) 중심의 재설계**', '**예측·선제적 정부(Anticipatory Gov.)**', '**데이터·AI 자동 의사결정**'으로 본질이 전환된다. 핵심 동인은 ① 저출생·인구감소로 인한 **행정 효율성 극대화**, ② 시민의 **디지털 경험 기대치(DX Maturity) 상승**, ③ **데이터 3법(개인정보보호법, 정보통신망법, 신용정보법)** 개정으로 인한 **마이데이터(MyData)·가명정보 활용**의 법적 토대 형성, ④ **OECD 디지털정부 성숙도 모델**의 6대 차원(Design, Data, Gov., Platform, Capability, Citizen-centric) 기준 평가 대응이다.

- **📢 섹션 요약 비유**: 종이 정부는 "은행 창구 9~4시", 전자정부는 "24시간 ATM", 스마트 정부는 "**앱 하나로 1,000가지 금융·생활서비스가 추천·자동 완료**"되는 토스/카카오뱅크 같은 수퍼앱형 정부이다.

## Ⅱ. 아키텍처 및 핵심 원리

스마트 정부 디지털 공공 서비스 혁신은 **3-거버넌스 + 5-플랫폼 + N-서비스** 구조로 요약된다. 3-거버넌스는 ① 디지털 정책 거버넌스(국가디지털혁신성장위원회), ② 데이터 거버넌스(데이터진흥원, NDS), ③ 정보보안·개인정보 거버넌스(개인정보보호위원회, KISA)이고, 5-플랫폼은 ① 정부서비스버스(GSB), ② 행정클라우드(공공클라우드), ③ 공공데이터 플랫폼, ④ 마이데이터 허브, ⑤ AI·지능형 플랫폼이다.

```text
[ 디지털 정부 참조 아키텍처(DGRA: Digital Government Reference Architecture) ]

                          |  시민(Citizen) / 기업(Business) / 공무원 |
                          +----------------+------------------------+
                                           | Omni-Channel
              +----------------------------+----------------------------+

              +----------------------------v----------------------------+
              |   ⑤ 데이터·AI·클라우드 기반 계층                         |

              |  |공공데이터|  |마이데이터|  |AI/Gov. |  |행정   |         |
              |  |플랫폼   |  |허브     |  |AI 플랫폼|  |클라우드|         |
              |  |data.go |  |         |  |(LLM,   |  |(공공  |         |
              |  |.kr     |  |         |  | RAG)   |  |클라우드|         |
              |  +--------+  +--------+  +--------+  +--------+         |
              +----------------------------+----------------------------+
                                           |
              +----------------------------v----------------------------+
              |   ⑥ 인프라 - 행정전산망(지자체망), 인터넷망, 클라우드,    |
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **정부서비스버스(GSB)** | 부처·지자체·공공기관 간 **API 통합·중재·라우팅** | Apache Camel / WSO2 ESB 기반 ESB, OAuth2/JWT 인증, API 게이트웨이(API-C, Common API), 표준 메시지 포맷(전자문서 KS X 6101, 전자서명), 메타버스·지자체 간 **데이터 연계 라우터** 역할. **"정부의 API 허리"** |
| **전자정부 표준프레임워크(eGovFrame)** | 공통 개발 런타임·표준 라이브러리·보안 | Spring 기반 경량 프레임워크, **모바일 공통컴포넌트, 웹 공통컴포넌트, UX 컴포넌트, ARS 컴포넌트, 전자결재(OpenEFrameWork)**, Git/SVN 기반 형상관리, Maven/Gradle 빌드 자동화, **Jenkins CI/CD 파이프라인**, 무중단 배포(Blue/Green) |
| **행정클라우드(공공클라우드)** | 200여 종 업무시스템의 **클라우드 전환 기반** | **공공클라우드(G-PaaS) + 기관별 SaaS**, 멀티/하이브리드 클라우드(Private On-Prem + Public CSP), 컨테이너 오케스트레이션(Kubernetes/OpenShift), VM(OpenStack) ↔ 컨테이너 듀얼 트랙, **클라우드-네이티브 듀얼 런타임(전자정부 표준프레임워크 호환)**, **클라우드 이용 가이드라인(2020, 행안부)** |
| **공공데이터 플랫폼(data.go.kr)** | 데이터 개방·제공·분석 | CKAN(Comprehensive Knowledge Archive Network) 기반 데이터 카탈로그, **Open API(1,400여 종)**, LOD/RDF, 데이터 품질관리(메타데이터 표준, DCAT-AP), **Mydata-공공데이터 연계 분석 환경** |
| **마이데이터 허브** | 시민 동의 기반 **개인정보 통합·이전** | **MyData 3법** (개인정보보호법 §36-2, 정보통신망법 §32-3, 신용정보법 §26) 기반, 데이터 신뢰관리기관, 본인인증·동의 UI 표준, **가명정보 결합 플랫폼(가명정보 처리안전성 평가)**, 샌드박스 |
| **AI/Gov.AI 플랫폼** | 지능형 민원상담·문서요약·정책시뮬레이션 | LLM(거대언어모델, GPT·Hyperclova·Exaone 기반), **RAG(Retrieval-Augmented Generation)** for 정부 지식베이스, MLOps, 프롬프트 거버넌스, **AI 영향평가(2024.1 지능형정부기본법 §17)**, AI 윤리原则(공정성·투명성·설명가능성) |
| **공통기반 GIS·공간정보** | 위치 기반 통합서비스 | **V-World(브이월드)**: 국가 공간정보 오픈 플랫폼, 행정구역 코드, 공간분석 API, 디지털트윈(세종시, 전주시), 스마트시티 데이터 허브 |
| **보안·신원 인프라** | 인증·접근제어·암호화 | **공동인증서(구 공인인증서) + 간편인증(SMS/PASS/지문/FIDO)**, **행정안전부 클라우드 보안인증(CSAP)**, 망분리(인터넷망/내부망/업무망), 데이터 암호화(HTTPS/TLS1.3, AES-256), 양자내성암호(PQC) 도입 검토 |

핵심 동작 메커니즘은 **"공통서비스의 표준화 -> GSB 라우팅 -> 부처 시스템 호출 -> 데이터 통합·분석 -> 시민에게 맞춤 제공"**이다. 예를 들어 시민이 정부24에서 "출생신고"를 하면, ① 인증(간편인증) -> ② 정부24 ↔ 가족관계시스템(행안부) ↔ 주민등록시스템(행안부) ↔ 의료보험(건보공단) ↔ 아동수당(복지부) API 자동 호출 -> ③ 문서 자동 발급 -> ④ 후속 행정(아동수당 자동 신청 알림)까지 **원스톱(One-Stop)** 처리된다. 여기서 GSB는 **ESB(Enterprise Service Bus) + API Gateway + iPaaS(Integration PaaS)** 의 결합 형태로 작동하며, 표준화된 API 명세(OpenAPI 3.0), 트래픽 관리(Rate Limiting, Circuit Breaker - Hystrix/Resilience4j), 로깅(ELK Stack), APM(Application Performance Monitoring - Scouter/Elastic APM) 필수 요건
