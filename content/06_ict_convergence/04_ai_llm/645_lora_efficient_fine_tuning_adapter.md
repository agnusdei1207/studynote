## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LoRA(Low-Rank Adaptation)는 사전학습된 거대 언어 모델(LLM)의 가중치 동결(Frozen) 상태에서, 어텐션 모듈의 Query/Value Projection에 저랭크 분해 행렬 ΔW = B·A (단, rank r ≪ d)만 주입해 학습 파라미터를 수십만 분의 1로 축소하는 PEFT(Parameter-Efficient Fine-Tuning) 어댑터 기법이다.
> 2. **가치**: GPT-3 175B 기준 학습 가능 파라미터를 0.01% 수준(≈ 7.7M)으로 축소하여, 단일 A100 80GB GPU에서도 7B~65B 모델 파인튜닝이 가능하고, 어댑터 파일(수십~수백 MB) 단위의 경량 배포로 멀티테넌트 모델 서빙과 작업 전환 비용을 극적으로 낮춘다.
> 3. **판단 포인트**: 랭크 r(1~64), 스케일링 팩터 α/r, 타겟 모듈 선정(Q/V vs Q/K/V/O), 양자화 결합(QLoRA·4-bit) 여부, 베이스 모델 가중치와 어댑터의 병합(Merge) 정책이 품질·메모리·지연시간 트레이드오프의 핵심 결정 변수다.

## Ⅰ. 개요 및 필요성

LLM의 풀 파인튜닝(Full Fine-Tuning)은 모델 파라미터 수 N에 비례하는 GPU 메모리(≈ 16N bytes for FP32)와 Adam 옵티마이저 상태(2×N), 그래디언트 버퍼(2×N), 활성값까지 합쳐 약 16N bytes의 메모리를 요구한다. 70B 모델만 해도 1.12TB가 필요해 사실상 분산 학습 인프라가 강제된다. 또한 각 다운스트림 작업마다 전체 체크포인트(140GB)를 별도 저장·배포해야 멀티테넌트 환경이 구성 가능해, 스토리지와 서빙 비효율이 누적된다.

LoRA(Hu et al., 2021)는 "사전학습된 가중치는 저랭크 적응만으로 충분히 표현된다"는 가설에 기반한다. W₀ ∈ ℝ^{d×k}에 대해 ΔW = B·A (B∈ℝ^{d×r}, A∈ℝ^{r×k}, rank r ≪ min(d,k))로 분해하고, A는 랜덤 가우시안, B는 0으로 초기화하여 학습 초기에 ΔW=0이 되도록 한다. 순전파는 h = W₀x + (α/r)·B·A·x로 계산되어 원본 출력을 처음에는 보존한다.

```text
[기존 풀 파인튜닝 vs LoRA 파인튜닝의 메모리·저장 비교]

  풀 파인튜닝 (기존)                      LoRA 파인튜닝 (신규)
  +------------------+                  +------------------+
  |  W₀ (Frozen)     |                  |  W₀ (Frozen)     |
  |  d × k = 4096²   |                  |  d × k = 4096²   |
  |  = 16M params    |                  |  = 16M params    |
  |  (Gradient Yes)  |                  |  (Gradient No)   |
  |  (Adam State Yes)|                  |  (Adam State No) |
  +------------------+                  +------------------+
           |                                      |
           v                                      v
  학습 파라미터: 100%                  학습 파라미터: 0.1~1%
  메모리: ~16N bytes                  메모리: ~2~4N bytes
  저장: 140GB/태스크                  저장: ~30MB/태스크

  -------- 병목 현상 --------         -------- 해결책 --------
  ✗ GPU 메모리 폭증                   ✓ 단일 GPU 학습 가능
  ✗ 체크포인트 거대화                  ✓ 어댑터 단위 경량 배포
  ✗ 작업 전환 비용 높음                ✓ Hot-swap 어댑터 서빙
  ✗ Catastrophic forgetting           ✓ 원본 지식 보존
```

특히 MLOps 관점에서 LoRA는 (1) 실험 이터레이션 속도, (2) GPU CapEx 효율, (3) 멀티태스크 라우팅, (4)灾难적 망각(Catastrophic Forgetting) 완화라는 네 가지 운영 페인포인트(Pain Point)를 동시에 해결한다.

- **📢 섹션 요약 비유**: 풀 파인튜닝은 백화점 전체 매장을 고객 취향에 맞춰 다시 짓는 공사이고, LoRA는 기존 매장 안에 작은 "이벤트 부스"만 따로 꾸며서 손님 취향을 반영하는 것과 같다. 매장(원본 모델)은 그대로, 부스(어댑터)만 갈아끼우면 된다.

## Ⅱ. 아키텍처 및 핵심 원리

### 1. 수학적 기반: 저랭크 분해

사전학습된 가중치 W₀ ∈ ℝ^{d×k}에 대해 적응 행렬 ΔW를 다음과 같이 강제한다:

```
ΔW = B · A,  단,  rank(ΔW) ≤ r ≪ min(d, k)
B ∈ ℝ^{d × r},  A ∈ ℝ^{r × k}
```

순전파:
```
h = W₀ x + ΔW x = W₀ x + (α/r) · B · A · x
```

스케일링 팩터 α/r의 역할은 학습 중 r을 변경하더라도 출력 스케일을 일정하게 유지하기 위함이다(∝r scaling). 이를 통해 하이퍼파라미터 튜닝 시 rank r만 조정해도 학습 동역학이 안정된다.

### 3. 핵심 구성 요소

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **Frozen Base W₀** | 사전학습된 거대 가중치 | 모든 gradient 계산·Adam 상태 저장에서 제외, fp16/bf16/fp32 그대로 동결. 디스크 I/O 부하 0에 수렴 |
| **LoRA-A (Up-projection)** | 입력 차원 축소 | ℝ^{r×k}, Kaiming uniform 초기화. 첫 forward pass에서 0이 아닌 활성화 생성 |
| **LoRA-B (Down-projection)** | 출력 차원 복원 | ℝ^{d×r}, **제로 초기화**로 시작 -> ΔW=BA=0 보장(학습 초기 안정성) |
| **Scaling Factor α/r** | rank 변경 시 출력 보정 | α는 학습률과 유사한 역할. 통상 α=2r 또는 α=r로 설정. **rsLoRA**는 α/√r 스케일링으로 더 큰 rank 사용 시 안정성 개선 |
| **Dropout (p=0.0~0.1)** | 어댑터 정규화 | ΔW에 적용. 풀 파인튜닝의 weight decay와 다른 효과. 과소적합 시 0, 과대적합 시 0.05~0.1 권장 |
| **Target Modules** | LoRA 주입 위치 | 통상 `["q_proj","v_proj"]` (8B 이하), `["q_proj","k_proj","v_proj","o_proj"]` (13B+), **FFN**(`gate_proj,up_proj,down_proj`)까지 확장 시 **DoRA·QLoRA + all-linear** 패턴 |
| **Merge/Unmerge** | 추론 시 경량화 | `model.merge_and_unload()`로 W' = W₀ + (α/r)·B·A를 단일 행렬로 합쳐 zero-overhead 추론, 어댑터 교체 시 다시 unmerge |

```text
  +---------------------------------------------------------+

  | |  LoRA Parameters (A, B)                          |   |  <- bf16: 2·r·(d+k)

  | |  • Gradients:  2·r·(d+k) bytes                   |   |      -> 524KB/모듈)
  | |  • Adam(m,v):  8·r·(d+k) bytes (fp32)            |   |

  ※ Adam 옵티마이저 상태가 ΔW에만 적용되므로 메모리 O(r) 스케일로 절감
```

### 5. 하이퍼파라미터 설계 가이드

- **rank r**: 1~64 범위. 권장 시작점 r=8. 매우 단순한 톤 적응이면 r=4, 추론·수학 추론이면 r=32~64.
- **α**: 통상 α = 2r (LoRA 원논문) 또는 α = r (rsLoRA 변형). r=8, α=16이 가장 검증된 조합.
- **target_modules**: 모델 크기가 클수록(>13B), 태스크 복잡도가 높을수록 더 많은 모듈에 분산 적용.
- **학습률**: 풀 파인튜닝 대비 1/10~1/5 수준(3e-4 ~ 1e-4)이 안정적. 어댑터는 좁은 파라미터 공간이므로 큰 step이 필요.
- **epoch 수**: 풀 FT 대비 3~10배 더 길게(작은 학습률 보상). 보통 3~5 epoch 시작.
- **warmup ratio**: 0.03~0.1 권장, 7B+ 모델은 cosine schedule.

- **📢 섹션 요약 비유**: LoRA의 A/B 행렬은 "번역가의 어깨에 앉은 동시통역사"와 같다. 원어(원본 가중치)는 그대로 흘려보내면서, 동시에 필요한 표현(ΔW)만 살짝 보탬으로 덧붙여 청자(다운스트림 태스크)에게 전달한다.

### 2. LoRA 주요 변형 비교

| 변형 | 핵심 아이디어 | rank 전략 | 메모리 추가 절감 | 권장 사용처 |
| :--- | :--- | :--- | :--- | :--- |
| **LoRA (원본)** | ΔW = B·A 고정 rank | 단일 r | - | 일반 PEFT |
| **QLoRA** | 4-bit NF4 양자화 + Double Quant + paged optimizers | LoRA 동일 | 65B -> 48GB 단일 GPU | 70B급 단일 GPU 학습 |

| **LoRA+** | A/B에 **비대칭 학습률**(A: η, B: λ·η, λ=2^4=16) | 단일 r | - | 수렴 속도 ^ |
