## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT PPM (Information Technology Project Portfolio Management)은 개별 프로젝트 성공보다, <strong>제한된 예산과 인력을 어떤 조합에 배치해야 기업 가치가 가장 커지는지</strong>를 다루는 거버넌스다.
> 2. **가치**: 운영, 확장, 혁신 예산을 균형 있게 배분해 좀비 프로젝트를 줄이고 전략적으로 중요한 과제에 자원을 집중시킨다.
> 3. **판단 포인트**: 높은 수익 예상만으로는 부족하며, <strong>전략 적합성·리스크·병목 자원 용량·중단 기준</strong>까지 함께 봐야 진짜 포트폴리오 관리가 된다.

---

## Ⅰ. 개요 및 필요성

기업 정보화 투자 포트폴리오 관리, 즉 IT PPM은 조직 내 IT 과제들을 하나의 투자 묶음으로 보고 우선순위와 자원 배분을 조정하는 관리 체계다. 프로젝트가 개별적으로 잘 수행되는지보다, 그 프로젝트들의 조합이 회사 전략과 얼마나 맞는지를 묻는다는 점에서 프로젝트 관리와 다르다.

이 관리 체계가 필요한 이유는 기업의 예산과 핵심 인력이 항상 부족하기 때문이다. 현업 요구를 받는 대로 모두 시작하면 유지보수 과제와 혁신 과제가 섞여 병목 자원이 과부하되고, 어떤 프로젝트도 충분한 집중을 받지 못한다. 그 결과 중복 투자, 일정 지연, 매몰비용 오류, 좀비 프로젝트가 누적된다.

특히 디지털 전환 환경에서는 운영 안정화에만 돈을 쓰면 미래 성장 동력이 사라지고, 반대로 혁신 실험에만 몰아주면 현재 사업을 지탱하는 코어 시스템이 흔들린다. 따라서 PPM의 본질은 "많이 하는 것"이 아니라 <strong>무엇을 멈추고 무엇에 더 태울지 결정하는 것</strong>이다.

- **📢 섹션 요약 비유**: PPM은 농구 감독이 모든 선수를 동시에 코트에 넣는 것이 아니라, 경기 상황에 맞춰 수비형·공격형·신예 선수를 적절히 조합해 승률을 높이는 운영과 같다.

## Ⅱ. 아키텍처 및 핵심 원리

IT PPM은 보통 <strong>수요 수집 -> 평가 -> 예산 버킷 배분 -> 용량 검증 -> 정기 재조정</strong>의 루프로 움직인다. 여기서 중요한 것은 예산만 보는 것이 아니라, 병목 인력과 기술 제약까지 같이 보는 것이다.

| 예산 버킷 | 목적 | 대표 대상 | 핵심 KPI | 일반적 판단 |
| :-- | :-- | :-- | :-- | :-- |
| 운영 (Run) | 현재 사업 안정성 유지 | ERP, 보안 패치, 규제 대응 | 가동률, 장애 감소, 감사 통과 | 부족하면 현재 수익이 흔들림 |
| 확장 (Grow) | 기존 사업 성과 확대 | 채널 고도화, 데이터 분석, 고객 기능 개선 | 매출 증대, 전환율, 생산성 | 너무 적으면 경쟁력 둔화 |
| 혁신 (Transform) | 미래 사업 모델 탐색 | AI 신사업, 신규 플랫폼, 개념 검증 (PoC, Proof of Concept) | 학습 속도, 시장 검증, 옵션 가치 | 과도하면 실패 비용 증가 |

예산 버킷은 고정 비율 공식이 아니라 기업 전략과 시장 상황에 따라 달라진다. 다만 중요한 것은 세 버킷이 명시적으로 분리되어야 한다는 점이다. 그래야 운영 이슈가 혁신 예산을 잡아먹는 현상이나, 반대로 화려한 실험이 필수 운영투자를 잠식하는 현상을 막을 수 있다.

아래 그림은 수요를 어떻게 포트폴리오 의사결정으로 바꾸는지 보여준다.

```text
+----------------------------------------------------------------------+
| IT PPM decision cycle                                                |
+----------------------------------------------------------------------+
| Demand intake                                                        |
|   -> candidate projects / mandatory work / ideas                     |
|                                                                      |
| Scoring                                                              |
|   -> strategic fit / ROI / risk / compliance / dependency            |
|                                                                      |
| Bucket balance                                                       |
|   -> Run / Grow / Transform allocation                               |
|                                                                      |
| Capacity gate                                                        |
|   -> budget / architect / DBA / security reviewer availability       |
|                                                                      |
| Decision                                                             |
|   -> fund / defer / pilot / stop                                     |
|                                                                      |
| Quarterly review                                                     |
|   -> rebalance by market and delivery result                         |
+----------------------------------------------------------------------+
```

이 구조에서 가장 중요한 단계는 <strong>Capacity gate</strong>다. 예산이 있다고 해서 곧바로 착수할 수 있는 것이 아니다. 데이터베이스 관리자, 보안 검토자, 아키텍트처럼 희소한 자원이 부족하면 포트폴리오 전체 처리량이 떨어진다. 따라서 PPM은 프로젝트 승인 체계이면서 동시에 조직 처리량 조절 장치다.

- **📢 섹션 요약 비유**: PPM은 냉장고에 있는 재료만 세는 일이 아니라, 요리사 수와 가스레인지 개수까지 확인한 뒤 오늘 만들 수 있는 메뉴를 결정하는 주방 운영과 같다.

## Ⅲ. 비교 및 연결

IT PPM을 이해하려면 프로젝트 관리 (PM, Project Management)와 린 포트폴리오 관리 (Lean Portfolio Management)를 함께 비교해야 한다. PM이 선택된 과제를 잘 끝내는 실행 기술이라면, PPM은 어떤 과제를 선택할지부터 다루는 상위 레벨이다.

| 항목 | PM (Project Management) | 전통적 PPM | Lean PPM |
| :-- | :-- | :-- | :-- |
| 중심 질문 | 이 프로젝트를 잘 끝냈는가 | 어떤 프로젝트 조합이 전략에 맞는가 | 지금도 그 조합이 유효한가 |
| 예산 주기 | 프로젝트별 승인 후 집행 | 연간·반기 중심 | 분기·수시 재배분 |
| 자원 관점 | 개별 팀 일정 중심 | 전사 예산과 인력 포트폴리오 | 가치 흐름 단위의 지속 투자 |
| 장점 | 실행 통제에 강함 | 중복 제거와 정렬 강화 | 시장 변화 대응과 조기 중단 유리 |
| 위험 | 전략 부합도 미반영 | 승인 후 경직성 | 빈번한 우선순위 변경으로 혼선 가능 |

또한 PPM은 엔터프라이즈 아키텍처 (EA, Enterprise Architecture), Val IT, SAFe (Scaled Agile Framework)와도 연결된다. EA는 중복 기능과 구조 충돌을 발견하게 해 주고, Val IT는 투자 가치 관점을 제공하며, SAFe는 린 PPM을 대규모 조직에 적용하는 운영 패턴을 제공한다.

결국 PPM의 핵심은 숫자 경쟁이 아니라 균형이다. 운영과 혁신, 단기 현금 흐름과 장기 옵션, 위험 회피와 시장 탐색을 한 축에서만 최적화하면 전체 포트폴리오는 약해진다.

- **📢 섹션 요약 비유**: PM이 한 척의 배를 목적지까지 안전하게 모는 기술이라면, PPM은 여러 척의 배를 어떤 항로에 보내야 전체 함대가 이익을 내는지 정하는 항만 관제와 같다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서 PPM은 대개 두 가지 순간에 진가를 드러낸다. 첫째는 <strong>중복 투자 제거</strong>다. 비슷한 목표를 가진 프로젝트가 부서별로 따로 올라오면 중앙 시야 없이는 중복을 발견하기 어렵다. 둘째는 <strong>병목 자원 조절</strong>이다. 승인된 과제를 한꺼번에 시작하면 중요 인력이 분산되어 모두 늦어진다.

### 실무 판단 체크리스트

1. 이 과제는 전략 목표와 직접 연결되는가, 아니면 단순 희망사항인가?
2. 재무 지표 외에 규제 대응·보안 필수성·브랜드 영향 같은 비재무 가치가 있는가?
3. 핵심 병목 자원을 실제로 투입할 수 있는가?
4. 최소 기능 제품 (MVP, Minimum Viable Product) 수준으로 먼저 검증 가능한가?
5. 기대 가치가 사라졌을 때 중단할 명시적 기준이 존재하는가?

### 대표 안티패턴

- 이미 돈을 썼다는 이유만으로 가치가 사라진 과제를 중단하지 못하는 경우
- 혁신 예산을 운영 장애 처리에 계속 전용해 장기 성장 기회를 잃는 경우
- 점수 모델은 만들었지만 실제로는 임원 목소리 큰 과제가 모두 통과하는 경우
- 승인 프로젝트 수를 늘리는 것을 성과로 착각해 WIP (Work In Progress)를 통제하지 않는 경우

학습 정리에서는 "선정"과 "중단"을 함께 언급해야 한다. 좋은 포트폴리오는 많이 승인된 포트폴리오가 아니라, <strong>가치 없는 과제를 빨리 멈추고 중요한 과제에 집중한 포트폴리오</strong>다.

- **📢 섹션 요약 비유**: PPM은 고속도로 진입 램프에 신호등을 두어 차를 질서 있게 들여보내는 교통관제와 같아서, 차를 많이 넣는 것보다 막히지 않게 흘려보내는 것이 더 중요하다.

## Ⅴ. 기대효과 및 결론

IT PPM이 정착하면 중복 투자가 줄고, 우선순위 결정 근거가 투명해지며, 핵심 인력이 가장 가치 큰 과제에 먼저 배치된다. 결과적으로 전략 과제의 시장 출시 속도, 예산 사용 효율, 경영진과 IT 간 정렬 수준이 좋아진다. 운영·확장·혁신 예산을 분리해 보는 것만으로도 조직은 "왜 이 과제에 돈을 쓰는가"를 더 명확히 설명하게 된다.

그러나 PPM도 만능은 아니다. 지나치게 정교한 점수 모델은 관리비용만 키울 수 있고, 현장의 실험 자유를 지나치게 묶으면 관료화가 생긴다. 그래서 최근에는 분기 단위 재조정, 파일럿 투자, 가치 흐름 중심 펀딩처럼 더 가벼운 린 PPM이 확산되고 있다.

결론적으로 IT PPM은 프로젝트 목록 관리가 아니라, <strong>기업이 현재를 지키면서 미래를 살 수 있도록 예산과 인력을 배분하는 최고 수준의 투자 거버넌스</strong>로 기억해야 한다.

- **📢 섹션 요약 비유**: 좋은 PPM은 장난감을 많이 사 주는 부모가 아니라, 지금 필요한 학용품과 미래를 위한 악기 수업비를 함께 계산해 주는 살림 설계와 같다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
| :-- | :-- |
| PM (Project Management) | 개별 프로젝트 실행 관리 |
| EA (Enterprise Architecture) | 중복 투자와 구조 충돌 식별 |
| Val IT | IT 투자 가치 실현 관점 제공 |
| Lean Portfolio Management | 분기별 재배분과 실험 중심 운영 |
| Capacity Planning | 병목 자원 가용성 검증 |
| VSM (Value Stream Management) | 프로젝트보다 가치 흐름 중심으로 확장되는 방향 |

### 📈 관련 키워드 및 발전 흐름도

```text
Project-by-project approval
        |
        v
Portfolio visibility and scoring
        |
        v
Run / Grow / Transform budget split
        |
        v
Capacity-based prioritization and stop gate
        |
        v
Lean PPM and value-stream funding
```

이 흐름은 개별 프로젝트 중심 관리에서, 동적 자원 재배분과 가치 흐름 중심 거버넌스로 진화하는 과정을 보여준다.

### 👶 어린이를 위한 3줄 비유 설명

1. 용돈이 한정되어 있으면 장난감을 다 살 수 없어서 중요한 것부터 골라야 해요.
2. 지금 꼭 필요한 것, 더 잘하게 도와주는 것, 미래에 도전해 볼 것을 나눠 생각해야 해요.
3. PPM은 회사가 돈과 사람을 그렇게 똑똑하게 나눠 쓰게 도와주는 방법이에요.
