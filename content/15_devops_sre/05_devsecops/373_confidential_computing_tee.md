## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 컨피덴셜 컴퓨팅(Confidential Computing)은 데이터가 **사용 중(In-Use)**일 때도 하드웨어 기반 격리 실행 환경(TEE, Trusted Execution Environment)으로 보호하여, 저장(At-Rest)·전송(In-Transit) 보호만으로는 불가능한 **3중 완전 암호화**를 실현하는 기술이다.
> 2. **가치**: Intel SGX·AMD SEV·ARM TrustZone 등 CPU 수준 하드웨어 엔클레이브(Enclave)를 통해, 클라우드 운영자·호스트 OS·하이퍼바이저조차 접근 불가능한 데이터 처리 영역을 만들어 Zero Trust를 하드웨어 레벨까지 확장한다.
> 3. **판단 포인트**: 멀티 클라우드·멀티 테넌트 환경에서 데이터 주권(Data Sovereignty)과 규제 준수를 동시에 충족해야 할 때, TEE 기반 컨피덴셜 컴퓨팅은 가장 강력한 기술적 보증(Attestation)을 제공한다.

---

## Ⅰ. 개요 및 필요성

전통적 보안은 데이터를 저장 시(AES 암호화)와 전송 시(TLS)에만 보호한다. 그러나 데이터가 메모리에 적재되어 연산되는 순간에는 평문(Plaintext)으로 노출된다. 클라우드 환경에서 호스트 OS, 하이퍼바이저, 관리 콘솔에 접근 권한이 있는 내부자(Insider)나 공격자는 이 틈을 노린다. Spectre·Meltdown 같은 사이드 채널 공격은 메모리 상의 평문 데이터를 직접 탈취할 수 있다.

컨피덴셜 컴퓨팅은 CPU 하드웨어가 제공하는 격리 영역(Enclave)에서 데이터를 처리하고, 해당 영역 외부의 모든 소프트웨어(OS 포함)를 신뢰하지 않는 모델이다. 이는 Zero Trust의 논리적 신뢰 검증을 물리적 하드웨어 증명으로 확장한다.

- 📢 섹션 요약 비유: 은행 금고(저장 보호)와 현금 수송차(전송 보호)는 있었지만, 창구 직원이 돈을 세는 순간 누구나 볼 수 있었다. TEE는 창구에 방탄 유리 부스를 설치해 세는 동안에도 보호하는 것이다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
+-----------------------------------------------------+
|           컨피덴셜 컴퓨팅 아키텍처                   |
+-----------------------------------------------------+
|  [애플리케이션 코드 + 민감 데이터]                    |
|         v                                            |
|  +---------------------------------+                 |
|  |  TEE Enclave (하드웨어 격리)     |                 |
|  |  - 암호화된 메모리 영역           |                 |
|  |  - CPU만 복호화 가능              |                 |
|  |  - Remote Attestation 제공       |                 |
|  +---------------------------------+                 |
|         v                                            |
|  [Host OS / Hypervisor] <- 접근 불가                  |
|         v                                            |
|  [암호화된 결과만 반환]                               |
+-----------------------------------------------------+
```

| 구분 | Intel SGX | AMD SEV | ARM TrustZone |
| :--- | :--- | :--- | :--- |
| 격리 단위 | 프로세스(Enclave) | VM 전체 | Secure World |
| 메모리 암호화 | MEE(128MB->256MB) | SME/SEV-ES/SNP | TZASC |
| 원격 증명 | EPID/DCAP | SEV-SNP Attestation | OP-TEE |
| 주요 대상 | 클라우드 워크로드 | VM 기반 기밀 VM | IoT·모바일 |
| 성능 영향 | 5-15% 오버헤드 | 2-5% 오버헤드 | 1-3% 오버헤드 |

- 📢 섹션 요약 비유: SGX는 작은 개인 금고(프로세스 단위), SEV는 큰 보안 창고(VM 단위), TrustZone은 스마트폰 안의 비밀 방(Secure World)이다.

## Ⅲ. 비교 및 연결

| 비교 항목 | 기존 암호화 | 컨피덴셜 컴퓨팅(TEE) | 동형 암호 |
| :--- | :--- | :--- | :--- |
| 보호 범위 | At-Rest/In-Transit | At-Rest/In-Transit/In-Use | In-Use |
| 성능 오버헤드 | 낮음(1-3%) | 중간(2-15%) | 극도로 높음(100x+) |
| 신뢰 기반 | 소프트웨어 키 | 하드웨어 증명 | 수학적 보증 |
| 상용화 수준 | 완전 상용 | 상용화 진행 중 | 연구/초기 단계 |
| 검증 방법 | 인증서 검증 | Remote Attestation | 암호학적 증명 |

- 📢 섹션 요약 비유: 기존 암호화는 편지를 봉투에 넣는 것, TEE는 방탄 유리 안에서 편지를 읽는 것, 동형 암호는 봉투를 열지 않고 내용을 수정하는 마법이다.

## Ⅳ. 실무 적용 및 실무자 판단

**체크리스트 (5가지)**
- [ ] Confidential VM(Azure DCsv3, GCP C2D)으로 민감 워크로드 격리 확인
- [ ] Remote Attestation을 통한 엔클레이브 무결성 검증 파이프라인 구축
- [ ] Key Management Service(KMS)와 TEE 키 래핑(Wrapping) 연동
- [ ] 성능 벤치마크(TEE ON/OFF 비교) 수행 및 SLA 영향 분석
- [ ] 데이터 주권 규제(GDPR, 개인정보보호법) 요구사항과 TEE 매핑

**안티패턴**
- ❌ TEE를 도입하면서 Attestation 검증을 생략 -> 위조 엔클레이브 위험
- ❌ 모든 워크로드에 무차별 적용 -> 성능 저하와 비용 증가
- ❌ 사이드 채널 공격(전력 분석, 캐시 타이밍)에 대한 추가 방어 무시
- ❌ TEE 도입으로 소프트웨어 레벨 보안(패치, 접근 제어)을 소홀히 함

- 📢 섹션 요약 비유: 방탄 유리를 설치했다고 경비원(소프트웨어 보안)을 해고하면 안 된다.

## Ⅴ. 기대효과 및 결론

컨피덴셜 컴퓨팅은 데이터의 전 생애주기를 하드웨어 수준에서 보호하여 클라우드 신뢰 모델의 근본적 한계를 극복한다. Zero Trust의 "Never Trust, Always Verify"를 하드웨어 증명(Attestation)으로 완성하며, 멀티 테넌트 환경에서 데이터 주권과 규제 준수를 동시에 보증한다. 향후 동형 암호, 안전한 다자 계산(MPC)과 결합되어 Privacy-Preserving Computation의 핵심 인프라로 발전할 것이다.

- 📢 섹션 요약 비유: 은행이 금고·수송차·창구 부스를 모두 갖추면, 고객은 어느 순간에도 돈이 안전하다고 확신할 수 있다.

| 개념 | 연결 관계 | 참조 영역 |

| Remote Attestation | 엔클레이브 무결성 증명 | 보안/하드웨어 |
| GDPR/데이터 주권 | 규제 요구사항 매핑 | 컴플라이언스 |

### 📈 관련 키워드 및 발전 흐름도

```text
소프트웨어 암호화(AES/TLS)
  -> TPM/HSM 하드웨어 키 보관
    -> Intel SGX 프로세스 엔클레이브
      -> AMD SEV VM 기밀 컴퓨팅
        -> Confidential Containers (K8s)
          -> Privacy-Preserving Computation (FHE+MPC+TEE)
```

### 👶 어린이를 위한 3줄 비유 설명

1. 컨피덴셜 컴퓨팅은 시험을 볼 때 칸막이 부스 안에서 보는 것처럼, 컴퓨터가 계산할 때 아무도 못 보게 벽을 치는 거예요.
2. SGX는 책상 위 작은 금고, SEV는 방 전체를 잠그는 것, TrustZone은 스마트폰 안의 비밀 방이에요.
3. Remote Attestation은 "이 부스가 진짜 안전한 부스인지" 확인하는 보안 검사 도장이에요.
