## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSPM (Cloud Security Posture Management, 클라우드 보안 형상 관리)은 클라우드 계정의 설정 오류(Misconfiguration)를 지속적으로 탐지하고 수정하는 보안 솔루션이다. 클라우드 침해 사고의 99%가 설정 오류에서 기인한다는 Gartner 분석이 CSPM의 중요성을 뒷받침한다.
> 2. **CIS Benchmark와 Drift**: CIS (Center for Internet Security) Benchmark는 클라우드 서비스별 보안 모범 사례 기준선이다. Drift Detection은 승인된 기준선에서 벗어난 변경을 실시간 탐지한다. 2019년 Capital One 사례(S3 버킷 퍼블릭 노출 -> 1억 명 데이터 유출)가 대표적 CSPM 미적용 사례다.
> 3. **판단 포인트**: CSPM은 탐지만이 아니라 Auto-Remediation(자동 수정)으로 연결되어야 운영 효율이 극대화된다. 단, 프로덕션에서 자동 수정 시 서비스 중단 위험이 있으므로 알림+수동 승인 -> 자동 수정 단계적 도입이 필요하다.

---

## Ⅰ. 개요 및 필요성

AWS, Azure, GCP의 클라우드 설정 오류는 사람이 수동으로 확인하기 불가능한 수준으로 복잡하다. S3 버킷 공개 설정 하나, IAM 역할 과도한 권한 하나가 대형 데이터 유출로 이어진다.

CSPM은 이런 설정 오류를 코드 수준에서 지속적으로 검사한다. CIS Benchmark 수천 개 항목을 자동으로 평가하고, 위반 항목을 우선순위화해 보안 팀이 중요한 것부터 처리하도록 안내한다.

> 📢 **섹션 요약 비유**: CSPM은 건물 안전 점검관이다. 매일 소화기 위치, 비상구 잠금 여부, 전기 배선을 점검하고 문제를 보고한다. 사람이 매일 수천 개를 확인할 수 없으니 자동화된 점검관이 필요하다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
+----------------------------------------------------------+
|                    CSPM 동작 흐름                          |
+----------------------------------------------------------+
|                                                          |
|  클라우드 API (AWS/Azure/GCP)                             |
|       | 설정 수집                                        |
|       v                                                  |
|  +--------------------------------------------------+    |
|  |  CSPM 엔진                                       |    |
|  |  - CIS Benchmark 비교 평가                       |    |
|  |  - 드리프트 감지 (기준선 대비 변경 탐지)          |    |
|  |  - 위험 우선순위화 (심각/높음/중간/낮음)           |    |
|  +--------------------------------------------------+    |
|       |                                                  |
|       v                                                  |
|  +--------------------------------------------------+    |
|  |  Auto-Remediation                                |    |
|  |  알림(Alert) -> 승인 -> 자동 수정 (Terraform/CLI) |    |
|  +--------------------------------------------------+    |
+----------------------------------------------------------+
```

주요 탐지 항목:
- S3 버킷 퍼블릭 접근 허용
- 루트 계정 MFA 미적용
- 보안 그룹 0.0.0.0/0 인바운드 허용
- 미암호화 EBS 볼륨
- CloudTrail 로깅 미활성화

> 📢 **섹션 요약 비유**: Capital One 사례는 수백만 개 S3 버킷 중 하나가 퍼블릭으로 설정된 것을 CSPM 없이 방치한 결과다. CSPM이 있었다면 설정 즉시 탐지되었을 것이다.

## Ⅲ. 비교 및 연결

| 항목 | CSPM | CWPP |
|:---|:---|:---|
| 대상 | 클라우드 설정/구성 | 런타임 워크로드 |
| 시점 | 정적 (설정 스캔) | 동적 (런타임 탐지) |
| 탐지 대상 | 잘못된 설정 | 이상 행동, 취약점 |
| 대표 도구 | Wiz, Prisma Cloud | Falco, Aqua Security |

| 도구 | 특징 |
|:---|:---|
| Wiz | Agentless, Risk Graph, 멀티클라우드 |
| Prisma Cloud | 상세 정책, 엔터프라이즈급 |
| AWS Security Hub | AWS 네이티브 CSPM |
| Checkov | IaC 코드 레벨 CSPM |

> 📢 **섹션 요약 비유**: CSPM은 집 설계도가 건축 법규에 맞는지 확인하는 것이고, CWPP는 집에 실제 살면서 이상한 소리가 나면 알려주는 것이다. 둘 다 필요하다.

## Ⅳ. 실무 적용 및 실무자 판단

### CSPM 구현 단계

1. **연결 및 스캔**: CSPM을 클라우드 계정에 연결해 현재 상태 전수 스캔
2. <strong>기준선 설정</strong>: CIS Benchmark Level 1/2 기준으로 허용할 예외 항목 정의
3. **드리프트 감지 활성화**: 기준선 대비 변경 발생 시 즉시 알림
4. **Auto-Remediation 시범 적용**: 저위험 항목부터 자동 수정 시범 운영

### 체크리스트

1. CIS Benchmark Level 1 기준으로 스코어가 85% 이상인가?
2. S3 버킷 퍼블릭 접근 허용 항목이 0건인가?
3. 드리프트 탐지 시 SIEM (Security Information and Event Management) 연동이 되는가?

> 📢 **섹션 요약 비유**: CIS Benchmark 스코어는 학교 안전 점검 성적표다. 100점 만점에 85점 이상을 유지하는 것이 목표이며, 낮은 점수 항목은 우선 수정한다.

## Ⅴ. 기대효과 및 결론

CSPM 도입으로 클라우드 설정 오류로 인한 데이터 유출 위험이 감소한다. 멀티클라우드 환경에서도 단일 콘솔로 전체 보안 상태를 파악하고, 컴플라이언스 보고서를 자동 생성할 수 있다.

CSPM의 핵심 가치는 <strong>"알고 있는 것(Known)을 자동으로 검사하는 것"</strong>이다. 설정 오류는 예측 가능한 위험이기 때문에, 자동화된 검사로 사람의 실수를 보완한다.

> 📢 **섹션 요약 비유**: CSPM 없이 수천 개 클라우드 설정을 수동 점검하는 것은 도서관의 모든 책이 제자리에 있는지 매일 수작업으로 확인하는 것과 같다. 자동화 없이는 불가능하다.

### 👶 어린이를 위한 3줄 비유 설명

1. CSPM은 클라우드 집(AWS/Azure)의 모든 문과 창문이 잠겨 있는지 자동으로 확인하는 로봇 점검관이에요.
2. CIS Benchmark는 이렇게 해야 안전하다는 공식 안전 체크리스트예요. 점검관이 이 리스트를 기준으로 확인해요.
3. Drift Detection은 어제는 잠겼던 창문이 오늘 열려 있으면 바로 알려주는 기능이에요. 누가 몰래 바꿨는지 즉시 알 수 있어요.
