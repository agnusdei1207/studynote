## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 쿠버네티스 (Kubernetes) 오브젝트 아키텍처 (Pod, Service, Deployment, Ingress)은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

## Ⅱ. 아키텍처 및 핵심 원리

Pod는 실행 단위, Service는 안정적 접근점, Deployment는 복제/롤아웃, Ingress는 외부 노출을 담당한다.

```text
Ingress -> Service -> Pod x N
            ^
        Deployment
```

| 오브젝트 | 역할 |
|:---|:---|
| Pod | 실행 |
| Service | 접근점 |
| Deployment | 배포 제어 |
| Ingress | 외부 진입 |

- **📢 섹션 요약 비유**: 교실이 바뀌어도 반 번호로 찾는 것과 같다.

## Ⅲ. 비교 및 연결

오브젝트들은 서로 연결되어 원하는 상태를 유지한다. Deployment가 Pod를 만들고, Service가 그 앞에 붙는다.

| 구분 | Pod | Service | Deployment |
|:---|:---|:---|:---|
| 역할 | 실행 | 연결 | 선언/관리 |
| 안정성 | 낮음 | 높음 | 높음 |
| 접근성 | 직접 | 간접 | 간접 |

- **📢 섹션 요약 비유**: 교실, 복도, 관리자 역할이 서로 다르다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 오브젝트 간 책임을 분명히 하고, 라벨/셀렉터를 정확히 맞춘다.

점검 포인트는 다음과 같다.
1. 선언한 상태와 실제 상태를 계속 맞추는가?
2. 서비스 접근점이 안정적인가?
3. 롤아웃/롤백이 자동화되는가?

- **📢 섹션 요약 비유**: 학생 명단과 자리표가 맞아야 출석이 정확하다.
