## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Injection (인젝션)은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

---

## Ⅰ. 개요 및 필요성

인젝션 (Injection)은 가장 오래됐지만 여전히 강력한 취약점이다. 입력값이 코드나 질의의 일부가 되면 공격자가 동작을 바꿀 수 있다.

SQL Injection (SQLi), OS Command Injection, NoSQL Injection이 대표적이다.

- **📢 섹션 요약 비유**: 레시피에 재료 대신 주문서를 넣어 요리법 자체를 바꾸는 것이다.

---

다음은 Injection (인젝션)의 핵심 구조와 흐름을 보여주는 다이어그램이다.

```text
+-------------------------------------------------------------+
|                  Injection (인젝션)                             |
+-------------------------------------------------------------+
|                                                             |
|  [입력/요구사항] ---> [핵심 처리 과정] ---> [출력/결과물]  |
|       |                    |                    |          |
|       v                    v                    v          |
|   요구 분석           설계·적용           품질 검증        |
|                                                             |
+-------------------------------------------------------------+
```

이 다이어그램은 Injection (인젝션)가 입력 요구사항을 받아 핵심 처리 과정을 거쳐 검증된 결과물을 산출하는 흐름을 보여준다.

## Ⅱ. 아키텍처 및 핵심 원리

핵심은 "문자열 연결" 대신 "파라미터 분리"를 쓰는 것이다.

```text
입력값 -> 파서/실행기 -> 명령 해석
        ^ 분리하지 않으면 공격 가능
```

| 방어 | 설명 |
|:---|:---|
| Parameterized Query | 질의와 데이터를 분리 |
| Allowlist Validation | 허용 목록 검증 |
| Escaping | 문맥에 맞는 이스케이프 |

- **📢 섹션 요약 비유**: 봉투 주소와 편지 내용을 따로 써야 우편물이 헷갈리지 않는다.

## Ⅲ. 비교 및 연결

인젝션은 입력 검증 실패의 결과이기도 하다. 하지만 단순한 길이 검사만으로는 막히지 않는다.

| 구분 | 안전한 방식 | 위험한 방식 |
|:---|:---|:---|
| SQL | 바인딩 변수 | 문자열 합성 |
| 명령 실행 | 고정된 인자 | 쉘 문자열 |
| NoSQL | 객체 분리 | 사용자 값 직접 삽입 |

OWASP Top 10에서 반복적으로 강조되는 이유가 바로 범용성과 피해 규모다.

- **📢 섹션 요약 비유**: 문을 잠갔다고 해도, 창문으로 들어가면 소용이 없다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 ORM (Object-Relational Mapping) 사용 여부보다, 그 ORM을 안전하게 쓰는지가 중요하다.

점검 순서는 다음과 같다.
1. 입력이 어디서 들어오는지 확인한다.
2. 질의/명령과 분리되었는지 본다.
3. 예외 메시지에 내부 정보가 노출되지 않는지 확인한다.

- **📢 섹션 요약 비유**: 재료를 칼로 자르기 전에, 먼저 도마 위에 놓인 것이 진짜 재료인지 봐야 한다.

## Ⅴ. 기대효과 및 결론

인젝션을 막으면 시스템의 가장 기본적인 신뢰 경계를 지킬 수 있다. 그래서 입력 처리 설계가 매우 중요하다.

결론적으로 이 항목은 "입력이 명령으로 변질되는 문제"다.

- **📢 섹션 요약 비유**: 손님이 말한 메뉴가 주방 명령으로 바뀌면 안 된다.

### 👶 어린이를 위한 3줄 비유 설명

1. Injection (인젝션)은 레고 블록으로 성을 만들 때처럼, 규칙을 정하고 역할을 나누어 함께 작업하는 방법이에요.
2. 혼자서 막 만들면 나중에 무너지거나 고치기 어렵지만, 약속을 지키면 누구나 쉽게 고치고 더 크게 만들 수 있어요.
3. 그래서 소프트웨어 공학은 프로그래머들이 좋은 프로그램을 빠르고 안전하게 만들 수 있게 도와주는 '규칙 모음집'이에요.
