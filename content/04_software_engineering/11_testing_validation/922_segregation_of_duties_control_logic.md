## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 보안 조직 분리 정책 위반 (SoD, Segregation of Duties)의 SW 통제 로직은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

---

## Ⅰ. 개요 및 필요성

권한이 너무 모이면 사고가 커진다. 그래서 작업 분리가 필요하다.

승인, 실행, 검토를 분리하면 통제가 쉬워진다.

- **📢 섹션 요약 비유**: 한 사람이 주문, 조리, 결제까지 다 하면 실수가 숨겨지기 쉽다.

---

다음은 보안 조직 분리 정책 위반 (SoD,의 핵심 구조와 흐름을 보여주는 다이어그램이다.

```text
+-------------------------------------------------------------+
|                  보안 조직 분리 정책 위반 (SoD,                        |
+-------------------------------------------------------------+
|                                                             |
|  [입력/요구사항] ---> [핵심 처리 과정] ---> [출력/결과물]  |
|       |                    |                    |          |
|       v                    v                    v          |
|   요구 분석           설계·적용           품질 검증        |
|                                                             |
+-------------------------------------------------------------+
```

이 다이어그램은 보안 조직 분리 정책 위반 (SoD,가 입력 요구사항을 받아 핵심 처리 과정을 거쳐 검증된 결과물을 산출하는 흐름을 보여준다.

## Ⅱ. 아키텍처 및 핵심 원리

SoD는 역할 충돌을 정책으로 막는다.

```text
사용자 역할 -> 충돌 검사 -> 허용/거부
```

| 요소 | 의미 |
|:---|:---|
| Role Conflict | 역할 충돌 |
| Approval | 승인 |
| Execution | 실행 |

- **📢 섹션 요약 비유**: 심판과 선수는 같은 사람이 될 수 없다.

## Ⅲ. 비교 및 연결

SoD는 인가의 세부 확장으로 볼 수 있다.

| 구분 | 일반 인가 | SoD |
|:---|:---|:---|
| 기준 | 자원 접근 | 역할 충돌 |
| 목적 | 권한 제어 | 내부 통제 |
| 효과 | 접근 차단 | 부정 방지 |

감사와 규정 준수에서 중요하다.

- **📢 섹션 요약 비유**: 문을 열 수 있는지보다, 그 사람이 열어도 되는지 따로 본다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 결재 시스템, 운영 권한, 금융/회계 업무에 많이 적용한다.

점검 포인트는 다음과 같다.
1. 충돌 역할이 정책으로 정의되는가?
2. 시스템이 자동으로 검사하는가?
3. 예외 승인이 감사 가능한가?

- **📢 섹션 요약 비유**: 한 사람이 혼자 도장을 다 찍으면 안 된다.

## Ⅴ. 기대효과 및 결론

SoD는 내부 부정과 오용을 줄인다.

### 👶 어린이를 위한 3줄 비유 설명

1. 보안 조직 분리 정책 위반 (SoD, Segregation of Duties)의 SW 통제 로직은 레고 블록으로 성을 만들 때처럼, 규칙을 정하고 역할을 나누어 함께 작업하는 방법이에요.
2. 혼자서 막 만들면 나중에 무너지거나 고치기 어렵지만, 약속을 지키면 누구나 쉽게 고치고 더 크게 만들 수 있어요.
3. 그래서 소프트웨어 공학은 프로그래머들이 좋은 프로그램을 빠르고 안전하게 만들 수 있게 도와주는 '규칙 모음집'이에요.
