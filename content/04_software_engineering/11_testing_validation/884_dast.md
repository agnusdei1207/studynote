## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DAST (Dynamic Application Security Testing)은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

---

## Ⅰ. 개요 및 필요성

DAST는 블랙박스 방식으로 웹 애플리케이션을 테스트하는 경우가 많다. 실제 요청과 응답을 보면서 취약점을 찾는다.

운영과 유사한 환경에서 확인할 수 있다는 점이 강점이다.

- **📢 섹션 요약 비유**: 문을 실제로 열고 닫아 보며 잠금 상태를 확인하는 것이다.

## Ⅱ. 아키텍처 및 핵심 원리

DAST는 실행 중인 앱에 입력을 넣고 반응을 분석한다.

```text
공격 입력 -> 실행 중 앱 -> 응답/행위 분석
```

| 특징 | 의미 |
|:---|:---|
| 실행 기반 | 실제 동작 확인 |
| 블랙박스 | 내부 코드 미확인 |
| 공격 재현 | 페이로드 활용 |

- **📢 섹션 요약 비유**: 제품을 포장만 보고 판단하지 않고 실제로 써 보는 것과 같다.

## Ⅲ. 비교 및 연결

DAST는 SAST가 놓칠 수 있는 인증 흐름, 세션 처리, 설정 문제를 잘 드러낸다.

| 구분 | DAST | SAST |
|:---|:---|:---|
| 초점 | 런타임 | 정적 코드 |
| 장점 | 실제 반응 | 빠른 탐지 |
| 한계 | 환경 필요 | 동적 문제 미흡 |

둘을 함께 써야 분석 범위가 넓어진다.

- **📢 섹션 요약 비유**: 지도와 현장 답사는 서로 다른 정보를 준다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 배포 전 스테이징 환경이나 정기 보안 점검에서 활용한다.

검토 포인트는 다음과 같다.

3. 실제 서비스와 비슷한 환경을 준비하는가?

- **📢 섹션 요약 비유**: 새 신발은 집에서만이 아니라 밖에서도 걸어 봐야 편한지 안다.

### 👶 어린이를 위한 3줄 비유 설명

1. DAST (Dynamic Application Security Testing)은 레고 블록으로 성을 만들 때처럼, 규칙을 정하고 역할을 나누어 함께 작업하는 방법이에요.
2. 혼자서 막 만들면 나중에 무너지거나 고치기 어렵지만, 약속을 지키면 누구나 쉽게 고치고 더 크게 만들 수 있어요.
3. 그래서 소프트웨어 공학은 프로그래머들이 좋은 프로그램을 빠르고 안전하게 만들 수 있게 도와주는 '규칙 모음집'이에요.
