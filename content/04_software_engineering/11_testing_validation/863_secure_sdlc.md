## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소프트웨어 개발 보안 (Secure SDLC)은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

---

## Ⅰ. 개요 및 필요성

Secure SDLC는 보안을 별도 작업이 아니라 개발의 일부로 본다. 그래서 취약점이 생기기 전에 예방한다.

운영 후 대응보다 설계 전 대응이 싸고 빠르다.

- **📢 섹션 요약 비유**: 집을 다 지은 뒤에 자물쇠를 다는 것이 아니라 설계부터 문을 튼튼하게 하는 것이다.

## Ⅱ. 아키텍처 및 핵심 원리

기획 단계에서 요구를 정하고, 설계에서 위협을 생각하고, 구현에서 안전 코드를 쓰고, 테스트에서 취약점을 확인한다.

| 단계 | 보안 활동 |
|:---|:---|
| 기획 | 보안 요구 정의 |
| 설계 | 위협 모델링 |
| 구현 | 시큐어 코딩 |
| 테스트 | 취약점 검증 |

```text
기획 -> 설계 -> 구현 -> 테스트 -> 운영
각 단계에 보안 포함
```

뒤늦은 보안보다 일찍 넣는 것이 핵심이다.

- **📢 섹션 요약 비유**: 신발을 만들 때부터 미끄럼 방지 바닥을 넣는 것이다.

## Ⅲ. 비교 및 연결

Secure SDLC는 DevSecOps와 연결되지만 범위가 더 넓다. 개발 과정 전체의 보안 문화를 뜻한다.

| 구분 | 일반 SDLC | Secure SDLC |
|:---|:---|:---|
| 초점 | 기능 구현 | 기능+보안 |
| 시점 | 후반 보강 가능 | 전 단계 포함 |
| 결과 | 취약점 늦게 발견 | 조기 예방 |

OWASP Top 10, 위협 모델링, 정적 분석과 연결된다.

- **📢 섹션 요약 비유**: 약을 다 먹은 뒤에 몸을 챙기는 것보다, 미리 건강식을 먹는 것이다.

## Ⅳ. 실무 적용 및 실무자 판단

실무에서는 보안 요구사항, 코드 리뷰, 취약점 스캔, 배포 검증을 함께 관리한다. 책임을 한 단계에 몰지 말아야 한다.

체크 포인트는 다음과 같다.
1. 보안 요구를 초기에 정한다.
2. 자동화 검사를 넣는다.
3. 운영 모니터링까지 연결한다.

- **📢 섹션 요약 비유**: 문단마다 맞춤 검사를 넣는 공정 관리다.

## Ⅴ. 기대효과 및 결론

Secure SDLC는 보안을 후처리가 아니라 기본 설계로 만든다. 그래서 비용과 위험을 줄인다.

결론적으로 이 개념은 "보안을 처음부터 넣는 개발 방식"이다.

- **📢 섹션 요약 비유**: 튼튼한 성은 처음 돌을 쌓을 때부터 방어를 생각한다.

### 👶 어린이를 위한 3줄 비유 설명

1. 소프트웨어 개발 보안 (Secure SDLC)은 레고 블록으로 성을 만들 때처럼, 규칙을 정하고 역할을 나누어 함께 작업하는 방법이에요.
2. 혼자서 막 만들면 나중에 무너지거나 고치기 어렵지만, 약속을 지키면 누구나 쉽게 고치고 더 크게 만들 수 있어요.
3. 그래서 소프트웨어 공학은 프로그래머들이 좋은 프로그램을 빠르고 안전하게 만들 수 있게 도와주는 '규칙 모음집'이에요.
