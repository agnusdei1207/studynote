## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 스트랭글러 패턴 레거시 분할은(는) 소프트웨어 공학의 핵심 개념으로, 복잡한 시스템을 체계적으로 설계·관리하기 위한 원칙과 기법이다.
> 2. **가치**: 이 개념을 올바르게 적용하면 소프트웨어의 품질·유지보수성·재사용성이 향상되고, 개발 생산성과 팀 협업 효율이 높아진다.
> 3. **판단 포인트**: 도입 시에는 비용·복잡도·조직 성숙도를 함께 고려해야 하며, 맹목적 적용보다 프로젝트 특성에 맞는 선택적 적용이 핵심이다.

---

## Ⅰ. 개요 및 필요성

수십 년간 운영된 거대한 모놀리식(Monolithic) 시스템을 최신 클라우드 MSA 환경으로 옮기는 작업은 기업의 생사가 걸린 프로젝트다. 과거에는 새 시스템을 완벽히 다 지을 때까지 몇 년을 기다린 후, D-Day 자정에 구형 서버의 전원을 끄고 새로운 유형의 서버를 켜는 <strong>빅뱅 방식(Big Bang Rewrite)</strong>을 썼다. 하지만 이 방식은 숨겨진 버그로 인해 오픈 첫날 시스템이 멈추는 대형 사고를 수없이 만들어냈다.

마틴 파울러(Martin Fowler)는 호주 여행 중, 숙주 나무를 감싸고 자라면서 서서히 숙주를 죽이고(Strangle) 자신이 그 자리를 대체하는 '스트랭글러 무화과나무(Strangler Fig Tree)'를 보고 영감을 얻었다. 시스템 개편 역시 <strong>새로운 덩굴(마이크로서비스)을 하나씩 자라게 하여, 낡은 나무(레거시)를 천천히, 그러나 확실하게 덮어버리자</strong>는 것이 스트랭글러 패턴의 핵심이다.

- **📢 섹션 요약 비유**: 낡은 다리를 부수고 옆에 새 다리를 짓는 동안 차가 못 다니게 하는 것(빅뱅)이 아니라, 낡은 다리의 기둥을 하나씩 몰래 새 기둥으로 교체하여 운전자들은 공사 중인지도 모르게 새 다리를 완성하는 마법이다.

## Ⅱ. 아키텍처 및 핵심 원리

스트랭글러 패턴은 <strong>파사드(Facade) 프록시</strong>를 통한 점진적 라우팅 전환이 핵심 원리다.

- **📢 섹션 요약 비유**: 스트랭글러 패턴 레거시 분할은(는) 복잡한 공사 현장에서 설계도와 공정표를 기반으로 팀을 이끄는 현장 감독과 같다. 원칙 없이 무작정 짓기 시작하면 결국 재공사가 필요하듯, 소프트웨어도 올바른 원칙 위에서만 품질과 효율이 보장된다.

| 항목 | 설명 | 비고 |
| :--- | :--- | :--- |
| 핵심 특성 | 스트랭글러 패턴 레거시 분할의 핵심 특성과 동작 방식 | 필수 이해 요소 |
| 적용 범위 | 어떤 프로젝트·상황에서 활용하는지 | 선택 기준 |
| 제약 조건 | 적용 시 주의해야 할 전제·한계 | 트레이드오프 |

## Ⅲ. 비교 및 연결

대규모 마이그레이션 전략을 비교해 보면 스트랭글러 패턴의 위치가 명확해진다.

| 전략 | 설명 | 리스크 | 적용하기 좋은 경우 |
|:---|:---|:---|:---|
| **Big Bang** | D-Day를 정해 한 번에 스위칭 | **매우 높음** | 레거시 코드가 너무 엉망이라 도저히 분리할 수 없을 때 |
| **Strangler** | API 라우팅을 통한 점진적 기능 교체 | **낮음** | URL 기반으로 기능(도메인)이 명확히 쪼개질 수 있을 때 |
| <strong>Branch by Abstraction</strong>| 코드 내부의 추상화 계층(인터페이스)을 통한 점진적 교체 | 낮음 | 레거시 시스템 내부에서 같은 DB와 프로세스를 공유해야 할 때 |

API 게이트웨이를 두고 네트워크(URL) 수준에서 라우팅을 쪼개면 스트랭글러 패턴이고, 거대한 레거시 코드 뭉치 '내부'에서 인터페이스를 만들어 새 코드로 분기시키면 추상화 분기(Branch by Abstraction) 패턴이다.

- **📢 섹션 요약 비유**: 빅뱅이 이삿날 트럭에 짐을 다 싣고 한 번에 이사 가는 거라면, 스트랭글러는 매일 퇴근할 때 짐을 하나씩 새집에 가져다 놓아 이사를 끝내는 것이다.

## Ⅳ. 실무 적용 및 실무자 판단

이 패턴이 교과서처럼 아름답게 작동하려면 <strong>데이터베이스 분리</strong>라는 가장 거대한 장벽을 넘어야 한다.

- **📢 섹션 요약 비유**: 스트랭글러 패턴 레거시 분할은(는) 복잡한 공사 현장에서 설계도와 공정표를 기반으로 팀을 이끄는 현장 감독과 같다. 원칙 없이 무작정 짓기 시작하면 결국 재공사가 필요하듯, 소프트웨어도 올바른 원칙 위에서만 품질과 효율이 보장된다.

## Ⅴ. 기대효과 및 결론

스트랭글러 패턴을 통해 조직은 '몇 년짜리 기약 없는 재개발 프로젝트'의 압박에서 벗어날 수 있다. 다음 달 당장 하나의 마이크로서비스를 오픈하여 클라우드의 혜택을 누리면서, 점진적으로 레거시를 청산하는 진정한 애자일 전환이 가능해진다.

결론적으로 현대의 시스템 현대화(Modernization) 작업에서 스트랭글러 패턴은 선택이 아닌 필수 표준이다. 실무자는 이 패턴을 설계할 때 단순한 API 라우팅 분기뿐만 아니라, 과도기 상태의 트랜잭션과 데이터 정합성 유지 방안까지 완벽하게 제시해야 한다.

- **📢 섹션 요약 비유**: 거대한 얼음덩어리(레거시)를 망치로 깨부수는(빅뱅) 대신, 따뜻한 물(마이크로서비스)을 부어 서서히 녹여내는 것이다. 주변이 다치지 않고 가장 안전하게 얼음을 없애는 방법이다.

### 👶 어린이를 위한 3줄 비유 설명

1. 스트랭글러 패턴 레거시 분할은 레고 블록으로 성을 만들 때처럼, 규칙을 정하고 역할을 나누어 함께 작업하는 방법이에요.
2. 혼자서 막 만들면 나중에 무너지거나 고치기 어렵지만, 약속을 지키면 누구나 쉽게 고치고 더 크게 만들 수 있어요.
3. 그래서 소프트웨어 공학은 프로그래머들이 좋은 프로그램을 빠르고 안전하게 만들 수 있게 도와주는 '규칙 모음집'이에요.
