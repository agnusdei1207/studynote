## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Live Patching은 커널 재부팅 없이 취약점이나 버그를 패치하는 기술이다.
> 2. **가치**: 서비스 중단을 최소화하면서 커널 수준 결함을 신속히 수정할 수 있다.
> 3. **판단**: kpatch, kGraft 같은 구현은 패치 적용 범위와 안정성 관리가 핵심이다.

---

## Ⅰ. 개요 및 필요성

운영 중인 서버를 재부팅하면 서비스가 끊길 수 있다. Live Patching은 이 문제를 줄이기 위해 등장했다.

그래서 고가용성 환경에서 특히 중요하다.

- **📢 섹션 요약 비유**: 달리는 기차 바퀴를 멈추지 않고 갈아 끼우는 것이다.

---

## Ⅱ. 아키텍처 및 핵심 원리

```text
Kernel Bug
  v
Live Patch
  v
Redirect / Replace
  v
Patched Kernel
```

| 구성 요소 | 역할 |
| :-- | :-- |
| Patch Module | 수정 코드 |
| Hot Update | 실시간 적용 |
| Consistency | 일관성 유지 |

Live Patching은 기존 커널 함수 실행을 새 코드로 전환하는 방식으로 동작한다. 커널 상태를 깨지 않도록 설계하는 것이 중요하다.

- **📢 섹션 요약 비유**: 운행 중인 버스 부품을 멈추지 않고 갈아 끼우는 수리다.

---

## Ⅲ. 비교 및 연결

| 방식 | 재부팅 | 장점 | 한계 |
| :-- | :-- | :-- | :-- |
| Reboot Patch | 필요 | 단순 | 다운타임 |
| Live Patching | 불필요 | 가용성 유지 | 적용 범위 제한 |
| LKM | 불필요 | 모듈화 | 기능 추가 중심 |

| 구현 | 특징 |
| :-- | :-- |
| kpatch | 커널 패치 프레임워크 |
| kGraft | 실시간 커널 업데이트 |

Live Patching은 장애 대응보다 예방적 보안 패치에 특히 유용하다.

- **📢 섹션 요약 비유**: 문을 닫지 않고 자물쇠를 바꾸는 일이다.

---

## Ⅳ. 실무 적용 및 실무자 판단

### 체크리스트

1. 재부팅 없이 패치 가능한가?
2. 패치 적용 범위가 명확한가?
3. 커널 상태 안전성을 보장하는가?
4. 롤백 전략이 있는가?
5. 지원 환경과 버전 제약을 아는가?

### 안티패턴

- 모든 패치를 라이브로 해결하려는 설계
- 적용 범위와 호환성을 무시하는 설계
- 롤백 계획 없이 적용하는 설계
- 안정성 검증 없이 운영하는 설계

실무 관점에서는 Live Patching을 "무중단 패치"로 설명하되, 제약과 운영 절차까지 함께 말해야 한다.

- **📢 섹션 요약 비유**: 움직이는 차를 바로 고칠 수 있지만, 아무 부품이나 다 바꿀 수는 없다.

---

## Ⅴ. 기대효과 및 결론

Live Patching은 커널 취약점 대응과 가용성 유지에 도움이 된다. 그래서 운영 환경에서 매우 유용하다.

결론적으로 Live Patching은 재부팅 없이 커널을 수정하는 기술이다.

- **📢 섹션 요약 비유**: 쉬지 않고 고치는 서비스 센터다.
