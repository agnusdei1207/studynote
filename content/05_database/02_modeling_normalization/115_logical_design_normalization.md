## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 논리 설계는 개념 설계(ERD)를 <strong>관계형 릴레이션 스키마(테이블·PK·FK)</strong>로 변환한 후, <strong>함수 종속성(FD) 분석을 통해 정규화(3NF/BCNF)</strong>를 수행하여 갱신 이상을 제거하는 단계다.
> 2. **가치**: ERD의 엔터티·관계·속성을 체계적 규칙(1:N->FK, M:N->교차 테이블)에 따라 릴레이션으로 변환하고, FD 분석으로 부분·이행·결정자 이상 종속성을 식별하여 분해한다.
> 3. **판단 포인트**: 정규화의 각 단계(1NF->2NF->3NF->BCNF)에서 <strong>제거되는 종속성 유형</strong>을 정확히 구분하고, 정규화 완료 후 <strong>무손실 분해·종속성 보존</strong> 조건을 검증해야 한다.

---

## Ⅰ. 개요 및 필요성

```text
+-------------------------------------------------------+
|    논리 설계 흐름                                      |
+-------------------------------------------------------+
|  [ERD]                                                |
|   엔터티(고객, 주문, 상품) + 관계(구매, 포함)         |
|      |                                                |
|      v 변환 규칙 적용                                 |
|  [릴레이션 스키마]                                    |
|   고객(고객ID PK, 이름, 주소)                         |
|   주문(주문ID PK, 고객ID FK, 날짜)                    |
|   주문상세(주문ID PK, 상품ID PK FK, 수량)             |
|      |                                                |
|      v FD 분석 + 정규화                               |
|  [정규화된 스키마]                                    |
|   부분FD 제거(2NF), 이행FD 제거(3NF),                |
|   결정자 조건(BCNF) -> 갱신 이상 없음                 |
+-------------------------------------------------------+
```

- **📢 섹션 요약 비유**: ERD->릴레이션 변환은 한국어->영어 번역이고, 정규화는 번역된 영어 문장의 문법 검사(갱신 이상 제거)이다.

---

## Ⅱ. 아키텍처 및 핵심 원리

### 정규화 단계별 제거 대상

| 정규형 | 제거 대상 | 조건 |
|:---|:---|:---|
| <strong>1NF</strong> | 반복 그룹, 비원자값 | 모든 속성이 원자값 |
| <strong>2NF</strong> | 부분 함수 종속 | 기본키 일부 -> 일반 속성 |
| <strong>3NF</strong> | 이행 함수 종속 | A->B->C에서 A->C 제거 |
| <strong>BCNF</strong> | 결정자 조건 위반 | 모든 결정자가 후보키 |

### ERD->릴레이션 변환 규칙

| ERD 요소 | 릴레이션 변환 |
|:---|:---|
| 강한 엔터티 | 독립 테이블 + PK |
| 약한 엔터티 | 테이블 + 소유자 FK (PK에 포함) |
| 1:N 관계 | N쪽 테이블에 FK 추가 |
| M:N 관계 | **교차 테이블** (양쪽 PK가 복합키) |
| 다치 속성 | 별도 테이블로 분리 |

- **📢 섹션 요약 비유**: 정규화는 "한 서랍에 양말과 속옷을 섞어 넣지 않는 것"이다. 섞으면 양말을 꺼낼 때 속옷이 따라 나오는 이상 현상(갱신 이상)이 발생한다.

---

## Ⅲ. 비교 및 연결

| 비교 | 비정규형 | 3NF | BCNF |
|:---|:---|:---|:---|
| **중복** | 많음 | 최소 | **최소** |
| <strong>갱신 이상</strong> | 빈번 | 대부분 제거 | **완전 제거** |
| <strong>종속성 보존</strong> | - | **보장** | 보장 안 될 수 있음 |
| **실무** | 안 됨 | 대부분 채택 | 이상적 |

---

## Ⅳ. 실무 적용 및 실무자 판단

### 학습 정리 핵심
1. FD 분석: "주문ID -> 고객ID, 날짜" (완전 FD 확인).
2. 정규화: "고객ID -> 이름, 주소"가 이행 FD인 경우 분해.
3. 무손실 분해 검증: 분해 후 자연 조인으로 원본 복원 가능 확인.

---

## Ⅴ. 기대효과 및 결론

논리 설계와 정규화는 DB 설계의 <strong>수학적 토대</strong>이며, 올바른 정규화 없이 물리 설계(역정규화)를 논의하는 것은 무의미하다. Schema-as-Code와 AI 기반 FD 자동 탐지가 결합하여 정규화 프로세스가 자동화되고 있다.

| 개념 | 연결 포인트 |
|:---|:---|

| <strong>BCNF</strong> | 모든 결정자가 후보키인 이상적 정규형 |

### 👶 어린이를 위한 3줄 비유 설명
1. ERD는 "이 방에는 침대, 저 방에는 책상"이라고 <strong>집 구조를 정하는 것</strong>이에요.
2. 정규화는 "양말 서랍에 속옷을 섞지 않기"처럼 <strong>물건을 깔끔하게 정리하는 규칙</strong>이에요.
3. 잘 정리하면 나중에 양말을 찾을 때 <strong>속옷이 따라 나오는 이상한 일(갱신 이상)</strong>이 안 생긴답니다!
