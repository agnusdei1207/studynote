## Ⅰ. 개요 및 필요성

데이터 거버넌스 3요소 (원칙, 조직, 프로세스)은 데이터베이스 설계와 운영에서 중요한 판단 지점을 설명하는 개념이다. 대용량 질의에서는 같은 SQL도 접근 경로와 실행 계획에 따라 비용이 크게 달라진다. 잘못 쓰면 Full Scan, 정렬, 랜덤 I/O가 한꺼번에 늘어난다.

```text
+--------------------------------------------------------------+
| SQL text -> Planner -> Current concept -> Latency            |
+--------------------------------------------------------------+
| Predicate -> path choice -> I/O cost                         |
+--------------------------------------------------------------+
```

이 그림은 데이터 거버넌스 3요소를 독립 기능이 아니라 전체 데이터 흐름에서 특정 통제 지점을 맡는 구조로 이해해야 한다는 점을 압축해 보여 준다.

- **📢 섹션 요약 비유**: 데이터 거버넌스 3요소는 도서관 색인표로 책을 찾는 일에 가깝다. 중요한 것은 순서를 정하고 책임 범위를 분명히 하는 일이다.

## Ⅲ. 비교 및 연결

데이터 거버넌스 3요소는 종종 `동적 SQL 조립 런타임 질의 파서` 또는 `정보 공학 방법론 데이터 주도적 생명 주기`과 같은 묶음으로 설명되지만, 세 개념의 관심사는 다르다. 동적 SQL 조립 런타임 질의 파서가 준비 단계나 전제에 가깝다면, 데이터 거버넌스 3요소는 실제 통제 지점을 잡고, 정보 공학 방법론 데이터 주도적 생명 주기는 그 결과를 더 강하게 만들거나 다른 방향으로 확장한다. 이 차이를 구분해야 시험 답안에서도 경계와 선택 이유를 설득할 수 있다.

| 비교 축 | 데이터 거버넌스 3요소 | 동적 SQL 조립 런타임 질의 파서 | 정보 공학 방법론 데이터 주도적 생명 주기 |
| :--- | :--- | :--- | :--- |
| 초점 | 현재 주제가 직접 통제하는 병목과 제약에 집중한다. | 바로 앞 단계나 전제를 다룬다. | 후속 확장 또는 보완 역할이 강하다. |
| 적용 시점 | 현재 개념이 요구되는 순간에 핵심 제어점으로 작동한다. | 준비·선행 판단에서 먼저 등장한다. | 세부 최적화나 확장에서 더 자주 등장한다. |
| 주된 위험 | 과신하면 비용 대비 효과가 줄어든다. | 부족하면 현재 개념도 안정적으로 성립하지 않는다. | 무작정 적용하면 복잡도와 운영 부담이 커질 수 있다. |

또한 데이터 거버넌스 3요소는 단순 정의 암기로 끝나는 개념이 아니라, 실제로는 성능·정합성·운영성 중 무엇을 우선할지 결정하는 기준점으로 연결된다.

- **📢 섹션 요약 비유**: 데이터 거버넌스 3요소는 같은 길이라도 우회로를 비교하는 내비게이션에 가깝다. 중요한 것은 순서를 정하고 책임 범위를 분명히 하는 일이다.
