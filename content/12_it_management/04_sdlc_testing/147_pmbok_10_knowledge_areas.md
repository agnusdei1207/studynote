## 핵심 인사이트 (3줄 요약)
> 1. **본질**: PMBOK(Project Management Body of Knowledge, 프로젝트 관리 지식 체계)은 PMI(Project Management Institute, 프로젝트 관리 협회)가 제정한 프로젝트 관리의 표준 프레임워크로, <strong>10대 지식 영역(Knowledge Area)과 5개 프로세스 그룹(Process Group)의 교차점에서 49개 프로세스</strong>를 정의한다.
> 2. **가치**: IT·건설·제조·연구개발 등 모든 산업의 프로젝트 관리자가 공통 언어와 프로세스로 프로젝트를 계획·실행·통제할 수 있는 <strong>글로벌 표준 관리 프레임워크</strong>로, PMP(Project Management Professional) 자격증의 이론적 기반이다.
> 3. **판단 포인트**: PMBOK 제7판(2021)은 프로세스 중심에서 <strong>원칙(Principles) + 성과 영역(Performance Domain)</strong> 중심으로 패러다임이 전환되었으며, 6판(프로세스 중심)과 7판(가치·결과 중심)을 구분해서 이해해야 한다.

---

## Ⅰ. 개요 및 필요성

프로젝트 관리는 정해진 기간·예산·품질 목표를 달성하기 위해 자원을 조직하고 통제하는 활동이다. 1960년대 방산·우주 프로젝트에서 태동한 현대적 프로젝트 관리는 PMI가 1996년 PMBOK 초판을 발표하면서 글로벌 표준으로 체계화됐다.

PMBOK 없이는 다음과 같은 문제가 반복된다:
- **삼중 제약(Triple Constraint) 붕괴**: 범위·일정·비용 간 트레이드오프 관리 실패
- <strong>이해관계자 관리 누락</strong>: 숨어있는 이해관계자(Stakeholder) 요구사항 미발견 -> 후반부 대규모 재작업
- **위험 무관리**: 사전 식별 없이 위험이 현실화 -> 일정·비용 초과

- **📢 섹션 요약 비유**: PMBOK은 **'건물을 짓기 위한 공사 표준 매뉴얼'** 과 같습니다. 착공 전 설계(계획), 공사 중 품질 검사(실행·통제), 준공 검사(종료)의 각 단계에서 무엇을 해야 하는지를 체계적으로 정리한 건설 표준서입니다.

### 2. 10대 지식 영역 요약

| 지식 영역 | 핵심 활동 | 핵심 산출물 |
|:---|:---|:---|
| **1. 통합관리** | 프로젝트 헌장 -> 계획 통합 -> 변경 통제 | 프로젝트 헌장, 프로젝트 관리 계획서 |
| **2. 범위관리** | WBS 작성, 범위 검증·통제 | WBS(Work Breakdown Structure) |
| **3. 일정관리** | 활동 정의, CPM 경로 분석, 일정 통제 | 프로젝트 일정, 네트워크 다이어그램 |
| **4. 원가관리** | 예산 산정, 획득가치(EVM) 분석 | 비용 기준선, EVM 보고서 |
| **5. 품질관리** | 품질 계획, 보증, 통제 (SPC, 파레토) | 품질 관리 계획서 |
| **6. 자원관리** | 자원 계획, 팀 개발, 자원 통제 | 자원 달력, RACI 차트 |
| **7. 의사소통관리** | 의사소통 계획, 정보 배포, 성과 보고 | 의사소통 관리 계획서 |
| **8. 위험관리** | 위험 식별, 정성·정량 분석, 대응 계획 | 위험 등록부, 몬테카를로 시뮬레이션 |
| **9. 조달관리** | SOW 작성, 공급업체 선정, 계약 통제 | RFP, 계약서 |
| <strong>10. 이해관계자관리</strong> | 이해관계자 식별, 참여 계획·통제 | 이해관계자 등록부 |

### 3. EVM(Earned Value Management, 획득가치관리) 핵심 지표

```text
EVM 핵심 지표
  +----------------------------------------------------------+
  |  PV (Planned Value)   : 계획된 작업의 계획 비용           |
  |  EV (Earned Value)    : 완료된 작업의 계획 비용           |
  |  AC (Actual Cost)     : 완료된 작업의 실제 비용           |
  |                                                          |
  |  SV (Schedule Variance) = EV - PV  (일정 편차)           |
  |  CV (Cost Variance)     = EV - AC  (원가 편차)           |
  |  SPI (일정 성과지수)    = EV / PV  (1.0 이상: 일정 앞섬) |
  |  CPI (원가 성과지수)    = EV / AC  (1.0 이상: 예산 절약)  |
  +----------------------------------------------------------+
```

- **📢 섹션 요약 비유**: EVM은 **'택배 배송 진행률 트래커'** 와 같습니다. "오늘까지 전체 택배의 60%(PV)를 보내야 했는데, 실제로 50%(EV)만 보냈고, 그 50% 보내는 데 예상보다 돈이 20% 더 들었다(AC)"면, 일정도 늦고 비용도 초과된 상황입니다.

## Ⅲ. 비교 및 연결

### PMBOK 6판 vs. 7판 비교

| 구분 | PMBOK 6판 | PMBOK 7판 (2021) |
|:---|:---|:---|
| 구조 | 49개 프로세스 (프로세스 중심) | 12개 원칙 + 8개 성과 영역 (결과 중심) |
| 접근 방식 | 예측적(Waterfall) 중심 | 예측적 + 적응형(Agile) 통합 |
| 출력물 | 특정 산출물 강조 | 결과·가치 강조 |
| PMP 시험 | 전통 PM 중심 | 하이브리드 (전통 50% + Agile 50%) |

### PMBOK vs. PRINCE2 vs. ISO 21500

| 구분 | PMBOK | PRINCE2 | ISO 21500 |
|:---|:---|:---|:---|
| 출처 | PMI (미국) | Axelos (영국) | ISO (국제 표준) |
| 성격 | 지식 체계 (가이드라인) | 방법론 (절차 명세) | 국제 표준 |
| 프로세스 수 | 49개 (6판) | 7개 테마 + 7개 원칙 | 39개 |
| 적용 분야 | IT·건설·제조 범용 | 정부·공공 프로젝트 | 범용 |

- **📢 섹션 요약 비유**: PMBOK은 **'요리 백과사전'**, PRINCE2는 **'특정 레스토랑의 표준 조리 레시피'**, ISO 21500은 **'국제 식품 위생 기준'** 입니다. 백과사전은 모든 요리법을 담고, 레시피는 특정 방식으로 따르게 하며, 국제 기준은 최소한의 안전을 보장합니다.

## Ⅳ. 실무 적용 및 실무자 판단

### IT 프로젝트 적용 핵심 포인트

<strong>범위관리 - WBS(Work Breakdown Structure)</strong>: 프로젝트 전체 작업을 계층적으로 분해한 트리. WBS 없이는 작업 누락과 중복이 발생한다. "100% 규칙" — WBS는 프로젝트의 모든 작업을 100% 포함해야 한다.

**위험관리 - 몬테카를로 시뮬레이션**: 각 활동의 기간을 확률 분포로 표현하고 수천 회 시뮬레이션해 프로젝트 완료 확률 분포를 산출. 단일 점 추정의 한계를 극복.

<strong>일정관리 - CPM(Critical Path Method)</strong>: 전체 프로젝트 기간에 영향을 주는 최장 경로. 임계 경로상의 활동은 지연 여유(Float)가 0이므로 단 하루의 지연도 전체 일정에 영향.

### 심화 학습 핵심 암기

1. **삼중 제약**: 범위(Scope) · 일정(Time) · 비용(Cost)
2. <strong>EVM 3대 기준선</strong>: PV(계획 비용), EV(획득 가치), AC(실제 비용)
3. **CPI < 1.0**: 예산 초과, SPI < 1.0: 일정 지연
4. **10대 지식 영역 순서**: 통합·범위·일정·원가·품질·자원·의사소통·위험·조달·이해관계자

### 안티패턴

<strong>골드 플레이팅(Gold Plating)</strong>: 고객이 요청하지 않은 추가 기능을 선의로 추가하는 행위. 범위 기준선을 초과하므로 PMBOK에서 엄격히 금지한다. 모든 변경은 공식 변경 요청(Change Request) -> 변경 통제 위원회(CCB) 승인 절차를 거쳐야 한다.

- **📢 섹션 요약 비유**: 골드 플레이팅은 **'피자 배달 주문에 서비스라며 파스타를 추가로 가져가는 것'** 과 같습니다. 고객이 원치 않을 수도 있고, 배달 지연(일정 초과)과 재료 비용 증가(원가 초과)를 유발합니다.

## Ⅴ. 기대효과 및 결론

PMBOK을 따른 프로젝트 관리는 계획·실행·통제의 각 단계에서 근거 기반 의사결정(Evidence-Based Decision Making)을 가능하게 한다. EVM으로 조기에 일정·비용 이탈을 감지하고, 위험 등록부로 잠재 위험을 사전에 통제하며, WBS로 작업 누락을 방지한다.

**한계**: PMBOK의 예측적 접근(Waterfall)은 요구사항이 자주 변하는 소프트웨어 개발에 경직적으로 적용하면 과도한 문서화와 절차 부담을 낳는다. 이것이 7판에서 애자일(Agile)·하이브리드 접근을 통합한 이유다.

**미래 방향**: ① PMBOK 7판의 원칙 기반 접근 확산, ② 애자일·하이브리드 PM의 제도화, ③ AI 기반 프로젝트 일정·위험 예측 자동화.

PMBOK은 "프로젝트를 통제하는 도구"가 아니라, **"프로젝트를 통해 가치를 전달하는 프레임워크"** 라는 7판의 관점으로 이해해야 한다.

- **📢 섹션 요약 비유**: PMBOK 6판과 7판의 차이는 **'요리 방법 매뉴얼(6판: 레시피 중심)'** 에서 **'고객이 맛있게 먹었는가(7판: 결과·가치 중심)'** 로의 관점 전환입니다. 레시피를 완벽히 따랐어도 손님이 맛없다면 실패한 것이라는 발상의 전환입니다.

### 👶 어린이를 위한 3줄 비유 설명

1. PMBOK은 **'큰 건물을 짓기 위한 표준 공사 매뉴얼'** 이에요. 처음에 설계도(계획)를 그리고, 공사(실행)하면서 품질 검사(통제)를 하고, 준공 검사(종료)를 하는 모든 단계를 표준화한 책이에요!
2. 10개의 '관리 영역'(범위·일정·비용·품질 등)이 있어서, 공사의 어떤 부분이 문제인지 빠르게 찾아낼 수 있어요.
3. EVM은 **'택배 배달 진행률 체크'** 같아요 — "오늘까지 60%를 보내야 했는데 50%만 보냈고 돈도 더 썼어요"라고 알려줘서, PM이 <strong>일찍 문제를 발견하고 수정</strong>할 수 있게 해줘요!
